# dataDirLock.test.ts — 置き場所の lock のテスト仕様

## 何を

`lockDataDir` (置き場所 `dataDir` を 1 つのプロセスだけが開けるようにする lock) を検証する。

## なぜ

置き場所 = 端末 (actor) で、正典の SQLite と発番器の状態を持つ。MCP server が動いている間に CLI を
同じ置き場所で開くと、**同じ actor の seq が重なる** (計画 `agent-stage3-mcp.md` F8)。一方で、
落ちたプロセスの lock が残って二度と開けなくなるのも困る。

## どのように

- 取って放すと file が消え、また取れる
- 生きた別のプロセスが持っていれば断る (このテストのプロセスが持ち、別の pid として取りに行く)
- 落ちたプロセスの lock は取り直す (`true` を走らせて終わった pid を使う)
- 壊れた lock (pid として読めない) は取り直す
- 放すのは自分の lock だけ — 落ちたと見なされて奪われた後に元の持ち主が放しても、新しい持ち主の
  lock を消さない
- 🔴 落ちた lock を同時に取り直しに来ても、取れるのは 1 つだけ (#391)。8 つのプロセス (`testing/lockContender.ts`) を
  起動し、**同じ時刻に揃えて**取りに行かせる (起動の遅れで順に並ぶと取り合いにならない)。取れたプロセスは放さずに
  待つ — 放すと、遅れたプロセスが正しく取れてしまう。取り直しの lock (`lock.recover`) が残らないことも見る
  - 取り合いは確率で起きるので、この試験は「必ず捕まえる」ものではない。上書きしていた前の実装では 5 回に 2 回落ち、
    今の実装では 10 回続けて通ることを確かめた。退けてから作り直す案 (rename) も 3 つ以上の取り合いで 2 つ取れることを、
    この試験が見つけた
