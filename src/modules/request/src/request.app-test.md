# request.app-test.tsx — 依頼の操作の App 結合の仕様

## 何を

App を丸ごと描き、「依頼・相談」の種を入れた Sheet で依頼 node を作る (1 台の端末)。そのうえで、
**node のそばの操作と dialog** で、送る・答える・閉じる・開き直す・送り直すを行う
(agent 段 4 R4、計画 node-actions-request-module.md N3)。
あわせて、2 人の間で依頼が届き、答えが返ることも確かめる (R5)。

App は依頼の module を登録して描く (`testing/requestDriver.tsx`。アプリの入口 `main.tsx` と同じ)。

## なぜ

状態は 3 か所に出る。

- node のそばに出る操作 (状態で決まる)
- node の上の印。core の `NodeBadges` が、module の `badge` を React Flow の store から決める
- 正典の op-log

**3 つが同じ操作で揃って動く**ことは、部品ごとのテストでは見えない。

答えると、node と edge をまとめて足す event (`NODES_PASTED`) が、貼り付けと同じく選択を外す。
そうなると続けて操作できない。core が実行の後に対象の node を選び直す (`useNodeActions`) ので、
ここでは答えた後もそのまま「閉じる」を押せることを確かめる。

## どのように

- 依頼の種類で node を作ると、作った時から応答を求める node (印は下書き)。そばの操作は「送る」だけ。
  **property の欄に依頼の区画は無い**
- 送る (dialog で宛先を選ばない = 参加者全員) → 印は送った・未回答で「1 回目」が添えられる。
  操作は「送り直す」「答える」「閉じる」
- 答える (dialog に本文) → node が 2 つになり、回答あり。正典では、依頼から答えへの edge に次の 2 つが載る
  - label「答え」
  - `answers` = 1
- 閉じる → 閉じた (操作は「開き直す」だけ)。開き直す → 回答ありに戻る
- 送り直すと、前の答えでは回答ありにならない (印は送った・未回答で「2 回目」)
- 画面を何度も往復するので、テストの上限を bun の既定 (5 秒) より長くする
- **2 人 (R5)**:
  1. alice が File を作って bob を招き、bob が参加する
  2. alice が依頼を作り、送る dialog で宛先に bob を選んで送る。「送り直す」の dialog を開くと、bob が選ばれている
     (値は property に入っている)。取り消して閉じる
  3. bob が同期すると、右下に「alice.test から依頼が届きました」が出る
  4. bob が「開く」を押すと依頼が選ばれ、通知は既読で消える。bob は node のそばの「答える」で答える
  5. alice が同期すると、node の印が回答あり。alice には通知は出ない (自分が送ったもの)
