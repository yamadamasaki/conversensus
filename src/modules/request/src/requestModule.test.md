# requestModule.test.ts — 依頼の module のテスト仕様

## 何を

依頼の module (`REQUEST_MODULE`、計画 node-actions-request-module.md N3) を検証する。
module が core の node の操作の拡張点に登録する宣言と関数である。

- 状態ごとに出る操作
- dialog の初めの値
- 実行して GraphEvent にすること
- node の上の印

試験は core の判断 (`createNodeActionRegistry`・`runNodeAction`) を通して呼ぶ。画面と同じ道である。

## なぜ

画面は、module が「使える」と言った操作をそのまま node のそばに出す。**使えると言ったのに実行できない**と、
押せるのに効かないボタンになる。依頼の状態は 4 つあり、状態ごとに出す操作が違う。印もこの module が決め、
**すべての node について canvas が変わるたびに**呼ばれる。そのため、依頼でない node で出ていく edge を数えないことも約束にする。

## どのように

- (例) 状態ごとに出る操作。どれも登録の順に出る。
  - 下書き: 「送る」
  - 送った・回答あり: 「送り直す」「答える」「閉じる」
  - 閉じた: 「開き直す」
  - 応答を求める node でなければ何も出ない
- (性質) **出た操作はどれも実行でき、op にできる。**状態は次の組み合わせから引く。
  - 送った回数: 0〜3
  - 閉じたか
  - 最後の送信に答えがあるか
  - 生成器の判断: 回数は小さくてよい。状態を分けるのは 0 か 1 以上かと、答えの回数が最後の送信と合うかである
  - 引数: 「答える」は本文を渡し、他は dialog の初めの値をそのまま渡す。利用者が何も変えずに「実行」した場合に当たる
- (例) **送る**
  - dialog の初めの値は、今の宛先と答えの置き場所。置き場所が無ければ `linkedNode`
  - 宛先・答えの置き場所・送った回数は 1 つの event に書く
  - 答えの置き場所は選択肢にある値だけを受ける。まだ答える側が扱わない `newSheet` は断る
- (例) **答える**
  - 答えの edge の label は、答える人の言語 (`ja` は「答え」、`en` は「answer」)
  - edge の `answers` は今の送った回数
  - 空白だけの答えは断る
- (例) **印**
  - 値は状態。送っていれば何回目かを文言に添える (「回答あり · 2 回目」)
  - 応答を求める node でなければ印は無く、**出ていく edge を引かない**
