# tauriConfig.test.ts — Tauri の設定のテスト仕様

## 何をテストするか

`tauri.conf.json` と `lib.rs` に散らばった **Tauri の設定のうち, 間違えても
静かに壊れるだけのもの**を固定する。今のところ 2 つある。

### 1. デーモンのポートの一致

Tauri アプリが使うデーモンのポート番号が, **2 つの言語のファイルで一致している**こと。

- `src-tauri/src/lib.rs` の `DAEMON_PORT` — アプリがデーモンを起動するときに渡す
- `src/client/.env.tauri` の `VITE_API_BASE` — クライアントが焼き込む宛先

## なぜテストするか

**言語をまたぐので型では守れない。** 片方だけ変えると, アプリは「起動するのに
何も読めない」状態になる。しかも出るエラーは CORS でも 404 でもなく**接続拒否**なので,
アプリの不具合と読み違えやすい。

これは step1 が繰り返し踏んできた**「2 箇所に同じ約束が書かれている」**形である
(ANA-125 では `node.setLayout` の生成口が 2 つあり, 片方の丸め漏れが同期を止めた)。
一本化できないものは**機械的に突き合わせる**。

## どのようにテストするか

- 双方のファイルを読み, 正規表現でポートを取り出して比較する。
  **取り出せなければ例外にする** — 書式が変わったことに気付かず素通しになるのが
  一番困るためである
- **開発用の 3000 でないこと**も見る。開発機では `bun run dev:server` が 3000 を
  掴んでいることが多く, アプリが同じポートを使うと日常的に衝突して起動できない
  (計画 §2.3 / D3)

## 反証で確かめたこと

`.env.tauri` のポートをわざと 1 つずらすと赤くなることを確認した
(`Expected: "39847" / Received: "39848"`)。

### 2. drag & drop を webview に任せる (`dragDropEnabled: false`)

**既定 (`true`) だと Tauri が OS の drop を横取りし, webview に渡さない。**
実機で「画像を落としても何も起きない」という形で出た (Phase 8 S4)。

診断を難しくするのは**非対称**である — 貼り付け (Cmd+V) は横取りされないので動く。
片方だけ動くと「画像の受け入れが壊れている」ではなく「drop だけ効かない」に見え,
アプリのコードを疑ってしまう。

**本物のドラッグは合成できない** (ANA-125 で確認済み) ので, ここで検査できるのは
**設定が意図どおりであること**だけである。それでも, 誰かが既定へ戻したときには気付ける。
