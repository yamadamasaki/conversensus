# corsOrigin.test.ts — CORS の許可 origin のテスト仕様

## 何をテストするか

どの `Origin` からの要求を通すかの判断そのもの。**通す 3 つと, 通さない 5 つ**を固定する。

## なぜテストするか

**判断を `cors()` の中に直書きしたままでは検査できない。** `Origin` は Fetch 仕様の
**禁止ヘッダ**で, スクリプトからは設定できないためである — テスト環境の happy-dom も
仕様どおり落とすので, コールバックには空文字が届く (実際にそれで一度赤くした)。
検査できるようにするために判断を関数へ出した。

内容の重要さは 2 方向にある。

- **通し漏れ**: `tauri://localhost` を通さないと**配布物は全リクエストが落ちる**。
  しかも画面は出て一覧だけが空になるので, 「アプリが壊れている」と誤診しやすい
- **通し過ぎ**: 許可を足すときに前方一致などで緩めると, `tauri://localhost.example.com`
  のような別物まで通る。デーモンは**認証を持たない**ので, 通した相手は全データを
  読み書きできる

## どのようにテストするか

通すもの:

- **`tauri://localhost`** — 同梱アプリ。リモートの出自ではなく同じ端末で動く
  アプリの名前なので, 環境変数に関係なく常に通す
- **`http://localhost:*`** — 開発中のクライアント (:5173) と E2E (:5174)。
  ポートが可変なので前綴りで見る。両方のポートで確かめる
- **`ALLOWED_ORIGIN` に一致するもの** — VPS のクライアント

通さないもの:

- **`ALLOWED_ORIGIN` が無いときの VPS の origin** — 開発機のデーモンが本番
  クライアントからの要求を受けない, ということでもある
- **見知らぬ origin**
- **`tauri://localhost.example.com`** — 完全一致で見ていることの確認。
  前方一致で書いていればここで落ちる
- **`http://localhost.example.com`** — 前綴りが**コロンまで**含むことの確認
- **`Origin` が無い要求** — CORS ヘッダを返す相手が居ない
