# authors.test.ts — node・edge を書いた人のテスト仕様

## 何を

`authorsOf` を検証する。op-log から、node・edge ごとの作者 (DID の列) を導く関数である (#354、設計 agent-actor.md D2a)。

## なぜ

avatar は「誰がこれを書いたか」を人に伝える。数える op を取り違えると、並べ替えただけの人が全 node の作者になったり、
書いた人が抜けたりする。作者は op-log からの導出なので、**どの順で batch が届いても同じ**でなければならない
(受信の順は端末ごとに違う)。どれも全称命題なので性質で書く。

## どのように

- (例) 作った人を先頭に、あとは最後に書いた順 (新しい順)
- (例) 位置と見た目を変えただけの人・消した人は数えない
- (例) edge も同じ。つなぎ替えは書いたに数え、label の位置は数えない
- (例) 同じ人の別の device は同じ人。未ログインの actor (`local`) は数えない
- (例) import した File の中身 (actor が `genesis`) は数えない (#382)。誰でもない書き手で、DID ではない。
  その後に書いた人だけが作者になる
- (例) 作成の op が手元に無い要素 (受信の途中など) は、書いた人を最後に書いた順に並べる
- (性質) 作者は、その要素に数える op を出した人ちょうど (重ならず、未ログインと genesis を含まない)。batch の並びを
  入れ替えても結果は同じ
- (性質) 作られていれば、最初に作った人 (畳み込みの順で最初の作成) が先頭。残りは最後に書いた順
- **生成器**:
  - 要素 3 つ (node 2・edge 1)・人 3 人 + 未ログイン + genesis・clock 0〜6 の小さなプールから引く。同じ要素を何人もが書き、
    clock が重なる組をよく引くためである
  - op は数えるもの (作成・中身・プロパティ・つなぎ替え) と数えないもの (位置・見た目・消す・label の位置) を混ぜる
  - node の op を edge の id に向けることもある。形の正しさは見ず、種類と target だけで数えることを確かめる

性質が見張っていることは、2 つの壊し方で確かめた。

- 畳み込みの順に並べ直すのをやめると、並び替えの性質が落ちる
- 作った人を最初の作成に固定しないと、先頭の性質が落ちる
