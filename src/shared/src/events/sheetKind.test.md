# sheetKind.test.ts — シートの種別の読み出し (step3 Phase 1 D7)

## 何を

`sheetKindOf` がシートのプロパティ `app.conversensus.sheetKind` から種別を読むこと。

## なぜ

特殊なグラフ (metagraph、template graph、将来は拡張が持ち込むもの) は、op の種類を足さずに
**種別プロパティが特別な値を持つ sheet** として表す (architecture step3 §3.3 D3)。op は他人の
repo に永久に残る通信形式なので、拡張が op を足すと、持たない相手が畳めずに同じログから違う
projection が出る。プロパティなら、持たない相手も保存して運び、無視できる。

読み出しで守るべきは**壊れ方**である。相手が新しい種別の書き方をしていても、こちらでは
「ただの sheet」として開ける必要がある — `templatesOf` が知らない id を黙って落とすのと同じ。

## どのように

例で書く。入力の形が 4 通り (値がある / 無い / 文字列でない / 空文字) しかなく、全称命題の形を
していない。

- **値を読む**
- **置かれていなければ undefined**: 別のプロパティだけがあっても種別にはならない
- **文字列でない・空の値は例外にせず undefined**: 上の「壊れ方」
- **プロパティ名は名前空間付き**: D3 が拡張に許すのはこの形のプロパティだけである。名前を
  固定するのは、これがログに載る通信形式の一部だからである (変えると既存のログが読めなくなる)
