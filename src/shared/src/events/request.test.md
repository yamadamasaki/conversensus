# request.test.ts — 応答を求める node のテスト仕様

## 何を

`request.ts` (応答を求める node のシステム・プロパティ 4 つの読みと、状態の導出) を検証する
(agent 段 4 R1、設計 agent-actor.md D6・D8)。

## なぜ

状態 (下書き / 送った・未回答 / 回答あり / 閉じた) は**保存せず導出する**。画面の印、通知、agent の
「自分宛ての未回答」の一覧が、すべてこの導出に乗る。食い違えば、答えたのに未回答に見える・閉じたのに
agent が答える、が起こる。値は op-log から来るので、形の違う値で落ちてもいけない。

## どのように

- **値の読み** (例): `addressee` を持つ node だけが応答を求める node (空の配列 = 不特定も含む、配列で
  なければ違う)。宛先の配列の文字列でない要素は落とす。送った回数・答えの回数は 1 以上の整数だけを読み、
  他 (0・負・小数・文字列・null・boolean) は無いのと同じ
- **状態** (例): 下書き / 送った・未回答 / 回答あり / 送り直すと前の答えでは回答ありにならない /
  他の node から出た答えの edge は数えない / 閉じたは他より優先 (`true` のときだけ)
- **状態** (性質。どれも全称命題):
  - 閉じた node は、どんな送信・答えでも「閉じた」
  - 「回答あり」⇔ 閉じておらず、この node から**最後の送信への**答えの edge がある
  - 送り直すと、送り直した回数への答えが無い限り「回答あり」ではなくなる
  - 生成器: 回数は小さなプール (無し・1〜3・0・負・小数・文字列) から引く。広いと「答えの回数 =
    送った回数」に当たらず、回答ありの場合が試されない。edge の始点は依頼 node と別の node の 2 つ
- **宛先**: 宛先に入っていれば宛てたもの、空 (不特定) なら誰にでも、応答を求める node でなければ誰にも
- **名前空間**: 4 つのシステム・プロパティは依頼の module の名前空間 (`app.conversensus.request.`) にあり、
  system として扱われる (property の欄・検索・`set_property` からは見えず変えられない)。module へ
  切り出す計画 (node-actions-request-module.md N0) で core の名前から移した
- **`requestsInFile`**: 状態つきで並べ、**template graph の sheet は除く** (依頼の種類の node は既定値として
  `addressee` を持つが、それは型の定義であって依頼ではない — 計画 F3)
