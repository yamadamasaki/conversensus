# dtr.test.ts

## 何を

判断ログから DtR の状態 (記録された呼び出し対象・積み上がった承認) を導く `foldDtr` と、
「全員が承認したか」を言う `allApproved` を検証する。

## なぜ

**この畳み込みは「端末によって結論が変わらない」ことを担保する装置である。**

仕様 (`dialogueToResolveGraph.md`「承認の判定」) はこう言う — 名簿は共同作業者の間で
食い違ってよいと決めたので、「全員が承認したか」を**名簿への生きた問い合わせ**として
書くと、a の手元では「全員承認済 → 再 merge 可能」、b の手元では「1 人足りない → 保留」が
**同時に、どちらも正常な状態として成立してしまう**。再 merge は trunk を書き換えるので、
これは表示の食い違いでは済まない。

したがって検証の軸は 2 つになる。

1. **記録された集合に対して判定しているか** (名簿を見に行っていないか)
2. **誰の手元でも同じ結論になるか** (順序に依らず、承認が消えない)

## どのように

### pre 条件で捨てるもの

名簿の畳み込みと同じ「検証して捨てる」意味論である。捨てるのは 3 つ。

- **`duplicateOpen`**: 2 度目の起動。通すと、後から来た起動が呼び出し対象を書き換え
  られることになり、「**呼び出し対象は起動時に確定する**」が崩れる
- **`dtrNotOpen`**: 起動されていない DtR への承認・対象の変更。起動が届いていない手元で
  承認だけが先に効くと、集合を知らないまま判定が始まる
- **`issuerNotCallee`**: 呼ばれていない actor の承認・対象の変更。「外して先に進む」は
  当事者の判断であって、外部から変えられてはならない

捨てた op は**位置 (`opIndex`) つきで返す**。名簿側と同じ理由で、同じ内容の op が 1 つの
batch に 2 つ並び、その一方だけが捨てられることがあるためである (例のテストで固定した)。

### 承認は DID 単位である

`actor` は端末単位、承認は人単位。端末ごとに数えると、2 台持ちの人が 1 人で「全員の承認」を
作れてしまう。名簿が `didFromActor` で DID に落としているのと同じ扱いにする。

### 呼び出し対象を変えても承認は消さない

`dtr.setCallees` は集合を**置き換える**が、それまでの承認は残す。仕様の
「承認は積み上がる一方なので、集合を固定すれば判定は単調になる」を、**集合が変わりうる
場合にも**保つための選択である。外された人の承認が残っても、判定は「今の呼び出し対象が
すべて承認に含まれるか」なので結論には影響しない。再び呼べば、その承認は活きる。

`dtr.setCallees` を語彙に入れた理由は**保留の出口**である。仕様は「承認しない actor がいたら
普通はそのまま (保留) だが、呼び出し対象から外して先に進むこともできる」と書いており、
これが無いと全員が承認するまで DtR に出口が無い。

### 名簿の op は読み飛ばす

判断ログは 1 つの collection を 2 つの畳み込みが別々に読む。ここの `switch` は名簿の op を
`default` で読み飛ばし、逆向きは `foldParticipation` の `switch` に `default` が無いことで
成り立っている (DtR の op は名簿の「捨てた op」に入らないので、「名簿に反映できなかった
判断がある」の警告が誤って出ない)。**混ぜて渡しても結果が変わらない**ことで示す。

### 性質として書いたもの

どちらも「**あらゆる** op 列で成り立つ」形なので、例ではなく性質で書く。

- **順序に依らない**: 実機の判断ログは受信順に並ぶ。畳み込みが自分で全順序
  (`compareByClockActorId`) に整列していることの確認であり、崩れると端末によって結論が
  変わる。並べ替えは**任意の置換**を作る (各 batch に乱数の鍵を付けて並べ替える) —
  反転のような特定の置換だけだと、整列の一部が壊れていても通ってしまう
- **承認は消えない**: 後ろに何を足しても、一度採択された承認は残る。仕様の単調性
  そのものであり、`setCallees` が承認を消さないという上の判断を支えている

**生成器は小さなプールにしてある** (DID 2 人 / DtR 1 つ / clock 1–4 / 1 batch に op 2 つまで)。
広い生成器では同じ DID も同じ clock も引かないので、「2 度目の起動」「同じ clock の同着」
「呼ばれていない人の承認」といった**境界に当たらない** — ここで見たいものが全部
境界にある。名簿の op も生成器に混ぜ、読み飛ばしが性質の側でも保たれることを見る。

## テストしていないこと

- **再 merge の可否**。pre 条件は「全員の承認が**その操作より前に**記録されていること」で
  clock の比較を伴い、判定はグラフの畳み込みの**手前**で行われる (`admissible`)。
  ここが出すのは材料までである
- **承認しないまま参加を取りやめた actor が自動的に外れること** (仕様)。名簿の状態が
  要るので、`foldParticipation` と組み合わせる段で見る
- **起動の引き金** (content 競合からの強制起動 / fork からの起動)。語彙と畳み込みの
  検証であって、どこから呼ばれるかはここでは見ない
