# cascade.test.ts — 削除のカスケード規則

## 何をテストするか

`node.remove` / `edge.remove` が**実際に消す要素の集合**を求める規則
(`cascadeOfNodeRemoval` / `cascadeOfRemoval`)。

## なぜここを固定するか

この規則は「op に何が書かれているか」ではなく「**そのとき状態に何があるか**」に依存する。
`node.remove` の op には対象の id が 1 つ書かれているだけだが、実際に消えるのは
その子孫ノードと、端点を失うエッジでもある。

そのため、**状態を持たずに op の `target` だけを読む側からは、消える要素が見えない**。
競合検出 (`merge.ts` の `collectRemoveDependencies`) は現状そうなっており、
グループを 1 つ消したときに子ノードを前提にした相手側の op を削除依存として拾えない
(`deepse/plans/step2-phase3-conflict.md` の事実 C)。

規則を 1 箇所に置くのは、**片方だけが更新される形を構造的に潰す**ためである。
実際にそれは起きていた — `applicability.ts` の `removeNode` は
「`applyOp` の node.remove 分岐と同じ」と書かれていながら、子孫の削除が抜けていた
(端点を失うエッジしか消していなかった)。この乖離を落とすテストは無かった。

グループの削除は「中身をまとめて消す」操作なので、共同作業では単独ノードの削除より
起こりやすい。取り逃しの影響は小さくない。

## 何を確かめるか

### 例で固定する振舞い

| 例 | 何を守るか |
|---|---|
| 子を持たないノード | カスケードが無い場合に余計なものを巻き込まない |
| 入れ子のグループ (g > child > grandchild) | **1 段しか辿らない実装を落とす。**孫が残る |
| 端点を失うエッジ (消える子に繋がるものを含む) | **T0 の主眼。**「op に書かれた id」だけ見ると `child` にも `e2` にも届かない |
| グラフに無いノード | 削除は冪等。呼び出し側に「存在を確かめてから呼べ」を強いない |
| 親子が循環している | 壊れたデータで無限ループにしない。**止まることが要件**で、結果の中身は副次的 |
| `edge.remove` | エッジ 1 本だけ。ノードへはカスケードしない (非対称なのは意図である) |

### 性質として書いたもの

主張が「**あらゆる**グラフと削除対象について成り立つ」形なので、例ではなく性質にした。

1. **`cascadeOfNodeRemoval` が返す集合 = projection の前後で消えた要素**

   `project.ts` はこの規則を呼んでから削除するので、一見トートロジーに見えるが
   そうではない。落とすのは「集合は正しく求めるが、消し方がそれと違う」ずれである —
   ノードだけ消してエッジを消し忘れる、layout を消し忘れる、といった形。
   T1 の検出器はこの一致を前提に「消える集合」で削除依存を判定するので、
   ここが崩れると検出と projection が食い違う。

2. **削除後のグラフに孤児が残らない**

   こちらは**実装を一切参照しない**。残ったノードの親は消えていない、残ったエッジの
   端点はどちらも消えていない。カスケードが存在する理由そのものを述べている。

### 生成器の設計

**ノードは 5 個の固定プールから引く。**広い生成器 (毎回新しい UUID) では親子関係も
エッジも繋がらず、カスケードが起きる形をほとんど引かない。同じプールから親も引くことで、
入れ子・循環・端点の共有が普通に出る。`properties.test.md` と同じ判断である —
**値の広さより値の衝突の方が効く**。

親は `fc.option` で undefined も引く (根が混ざらないと「親を持たないノードは巻き込まれない」
側が確かめられない)。自己参照 (`parentId === 自分`) は projection 側では起きえないので
生成の段階で落とす。

エッジは最大 6 本。プールが 5 個なので端点は頻繁に共有され、「1 つのノードを消すと
複数のエッジが消える」形が普通に出る。

### 変異検査

3 つの変異でこのテストの有効性を確かめた (2026-09-07)。

| 変異 | 落ちたテスト |
|---|---|
| 子孫を集めない | 4 件 (入れ子・エッジ・循環・孤児の性質) |
| 端点を失うエッジを集めない | 2 件 (エッジの例・孤児の性質) |
| projection がエッジを消さない | 1 件 (性質 1 = projection との一致) |

3 つ目は性質 1 だけが落とす。**例のテストは 1 件も落ちない** — 規則の側は正しいままで、
使う側だけがずれる変異だからである。性質 1 を置いた理由がこれにあたる。
