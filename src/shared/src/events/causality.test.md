# causality.test.ts — 因果の文脈

step3 Phase 1 S1-2 ([設計](../../../../deepse/plans/step3-phase1-oplog-v2.md) D1)。

## 何を

batch の点 `(actor, seq)` と依存 `deps` から、2 つの操作が「前・後・並行」のどれかを答える判定
(`happenedBefore` / `concurrent`)。歯抜けの先の batch の扱い (D2 の決定)。

## なぜ

この判定は、競合の検出 (T5)・上書きの報告 (T8)・参加期間・分岐点の 4 つの判断の土台になる。
間違えても**静かに違う答えを出す**側で (step3-entry §2.1)、壊れるとどの判断も一斉にずれる。
「ある例で合う」では足りず、**あらゆる履歴で実際の因果と一致する**ことを言いたいので、
性質として書く。

## どのように

### 生成器: 複数の actor が書いて、互いの batch の一部を受け取る履歴

3 人の actor が「書く」と「相手の batch の一部を受け取る」をランダムに繰り返す。
受け取りは**任意の部分集合**なので、歯抜けも順序の入れ替わりも起きる。書くたびに
**実際の因果の過去** (その人が直接・間接に見ていた batch の id) を記録しておき、判定と突き合わせる。

生成器の判断:

- **受け取りは直近の batch に偏らせる** (新しい方から 0〜2 番目)。推移律が効くのは
  「A が書き、B がそれを見て書き、C が B の分だけを受け取って書く」連鎖があるときで、
  古い batch を満遍なく拾う生成器ではこの連鎖がめったに起きない。**実際、最初の生成器は
  「受け取った batch の deps を知識に取り込まない」変異を見逃した** (例のテストだけが落とした)
- 因果の一致の性質は 500 回回す (他は既定の 100 回)
- actor は 3 人。2 人では「間接に見た」が作れない

### 性質

| 性質 | 言っていること |
| --- | --- |
| a → b ⇔ b を書いた人が a を直接または間接に見ていた | 判定が**実際の因果そのもの**である |
| → は半順序 (非反射・反対称・推移) | |
| 異なる 2 つは「前」「後」「並行」のちょうど 1 つ | 並行の判定が漏れも重複も無い |
| a → b なら全順序 (`compareByClockActorId`) でも a が先 | vector は畳み込みの順序と矛盾しない。**順序を置き換えない**という設計の前提 |

### 例

| テスト | 固定すること |
| --- | --- |
| 推移: C が B だけを受け取っても A は C より前 | `deps` は**因果の知識** (持っているものではない) |
| 自分の分は deps に載せない | |
| joinVectors は各項目の最大 | |
| 歯抜けの先の batch も知識に入る (D2 の決定) | 手前の batch を持たなくても「見た」と言い、その知識で書いた点は持っていない手前の batch より後と判定される。**受け入れた穴をそのまま固定する** — 変えるなら、この例を書き換える判断から始める |

### 変異で確認したこと

| 変異 | 落ちるテスト |
| --- | --- |
| `covers` を `>=` から `>` に | 因果の一致、推移の例 |
| 受け取った batch の `deps` を知識に取り込まない | 因果の一致 (生成器を直した後)、推移の例 |

## heldMaxima (step3 Phase 1 S1-5)

actor ごとに持っている最大の seq。歯抜けで止まらない。分岐点の vector
に使う (`branchLog.test.md` の「分岐点は vector で切る」)。例で固定する。

## 歯抜けで止まる到達点を外した (D2, 2026-10-13)

以前は「手元の到達点」(`contiguousFrontier`: 歯抜けの手前で止まる) とその性質を置いていたが、どこからも使われて
いなかった (deps は `knowledgeOf` で、歯抜けの先も数える)。歯抜けは恒久的に生じるので、歯抜けで止まる判断は採らない
と決め (`causality.ts` の冒頭)、関数とテストを外した。
