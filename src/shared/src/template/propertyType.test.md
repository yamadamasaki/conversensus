# propertyType のテスト仕様

## 何を

template の property の型 (template-update K10、計画 T4): 型の文字列の読み (`parsePropertyType`)・書き
(`formatPropertyType`)・型で値を検証する関数 (`matchesPropertyType`・`checkPropertyValue`)。

## なぜ

型は template graph の種類の node/edge に文字列で書く (K9)。読み書きが互いの逆でないと、宣言を編集の欄に
出して書き戻しただけで型が変わる。検証は読み取り側で使う — 他の参加者の op は書き込みの検証を通らずに
届くので、合わない値を落とさず印を付ける (K2)。その判定がずれると、正しい値に印が付き、誤った値を見逃す。

「書いて読むと戻る」「配列は要素がすべて合うときちょうど」は**あらゆる**型・値で成り立つ主張なので、性質として書く。

## どのように

### 生成器

- 型の構文木: 基本の型 5 つ・リテラルの列挙 (1〜3 個)・配列 (再帰、浅く) から引く
- リテラルは**小さなプール**から引く: 空文字・空白・日本語・文法の記号 (`|`・括弧・`[]`) を含むもの・単引用符を
  含むもの (二重引用符で書かれる)。記号を含むリテラルで、書き出しの引用が足りないことや、読みが引用符の
  中の記号に反応することを捕まえる。**両方の引用符を含むものは引かない** — 文法にエスケープが無く書けない
- 値: どの基本の型にも合うものと合わないものが入るプール (数・数字の文字列・NaN・真偽・null・日付・存在しない
  日・日時・範囲外の時刻・object) と、その 1〜2 段の配列

### 性質

| 性質 | 固定すること |
| --- | --- |
| 書いて読むと同じ宣言に戻る | 読み書きが互いの逆。列挙の配列は括弧で書かれ、記号を含むリテラルも戻る |
| 値が無ければ、optional なら合格、そうでなければ欠けている | `?` の意味 (K10・review-2 R3) |
| 配列の型に合うのは、配列で要素がすべて要素の型に合うときちょうど | 空の配列は合う / 入れ子も同じ規則 |
| 列挙に合うのは、列挙のどれかと等しい文字列ちょうど | 部分一致や数への寄せをしない |

### 例

- 基本の型・配列・列挙 (単引用符と二重引用符の混在)・列挙の配列・optional を読む
- 空白は語の間のどこにでも置ける
- 誤りは例外ではなく位置と理由で返す (他の参加者が書いた文字列を読むため): 知らない型・空・`|` の後が無い・
  引用符が閉じていない・余計な文字・**型のユニオン** (`string | number`、K10 で扱わない)
- 括弧の無い列挙の後ろの `[]` は誤り (どこに掛かるか読めない)
- 数は有限の number だけ。**数字の文字列は合わない** (値から型を推論しない、2026-09-20 の判断)
- 日付は存在する日だけ。日時は ISO 8601 で、秒・小数・時差は省略できる。24 時は誤り

## valueFromInput (T7)

### 何を・なぜ

入力欄の文字列を、**宣言された型に従って**値にする。値から型を推論するのではない (2026-09-20 の判断) —
型を決めているのは template の宣言である。number を宣言した property に `3` と打てば数の 3 を保存する。
宣言が無ければ文字列のまま (文字列の `"3"` を入れる手段を奪わない)。

### どのように

- 性質: number の宣言では、有限の数を書いた文字列は元の数に戻る (`String(n)` → `n`)
- 性質: number・boolean 以外の宣言と宣言の無いときは、どんな文字列も文字列のまま
- 例: 前後の空白は数として読む。空文字・読めない文字列は文字列のまま (型に合わない印が付く)。真偽は
  `true`/`false` だけを真偽値にする
