# template/kind のテスト仕様

## 何を

要素が template の**どの種別か**を `properties` から読み書きする規約 (`KIND_PROPERTY` /
`kindIdOf` / `nodeKindById`) と、両端の種別から edge の**候補**を引く `edgeKindsBetween` /
`isTemplateEdge` を見る。

## なぜ

**種別を `nodeType` ではなく property に載せた** (設計 D3, 2026-09-12)。toulmin の「主張」は
見た目としては markdown node であり、`nodeType` (markdown / グループ / 画像) とは
**直交する軸**である。property に載せると `node.setProperty` と、プロパティ名ごとに割れた
競合単位 (P1 の `fieldKeyOf` を入れたときに確認した) がそのまま使える — **新しい op も
新しい競合規則も要らない**。

edge 側の主題は **「繋げない」と「制約の対象外」を取り違えないこと**である。どちらも
候補は空になるが、前者は toulmin node どうしで許されない組、後者は片端が普通の node で
自由に繋いでよい場合である。混同すると**普通のノードに繋げなくなる**。

## どのように

### 種別の読み書き

- **システム接頭辞を持つ**: `.` を含むことが「編集者のものではない」の判定規則そのもの
  (`spec/propertyEditor.md`「名前」)。値ではなく**規則**を見ている。
- **property が無い / `kind` が無いなら `undefined`**: 種別を持たない = template の要素では
  ない、が既定である。
- **空文字は種別なし**: 「外した」形が来ても種別として読まない。
- **文字列でない値は種別なし**: op-log は他の参加者が書く。**他人の書いたログを信用しない** —
  数値や `null` が入っていても落ちずに「種別なし」として読む。

### 種別 id から種別を引く

- **同じ id を持つ template が 2 つあれば先勝ち**: 種別一覧の `unionById` と同じ規則に
  揃える。`NodeKindId` は template の中でだけ一意なので、これは既知の穴である (設計 §7)。
  **規則を揃えておくことで、穴が 2 種類にならない**。

### edge の候補

- **許される組は候補 1 / 許されない組は候補 0**: toulmin の 5 つの規則そのもの。
- **toulmin では候補が 2 以上にならない**: 5×5 の全組合せを数えて、候補 1 がちょうど 5 つ、
  候補 2 以上が 0 であることを固定する。**これが「step2 では選択メニューが要らない」の
  根拠そのもの**なので、例ではなく全数で見る。
- **候補が複数になる template では複数返す**: step2 では到達しないが、判定は一般の形で
  ある (設計 D5)。合成 template で通しておくと、step3 で UI を足すときに判定側を
  書き直さずに済むことが確かめられる。
- **解決は template ごと**: 和の上で引くと、T1 の edge 規則を T2 の node 種別で満たす
  混線が起こる (id は template をまたいで一意ではない)。`fold` の
  「label → 種別の解決は template ごと」と同じ判断である。
- **候補 0 と「制約の対象外」は別物**: `edgeKindsBetween` はどちらも空を返すので、
  **`isTemplateEdge` が両者を分ける唯一の手段**である。ここを 1 本のテストで
  並べて示してある。
