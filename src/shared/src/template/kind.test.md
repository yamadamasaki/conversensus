# template/kind のテスト仕様

## 何を

要素が template の**どの種別か**を `properties` から読み書きする規約 (`KIND_PROPERTY` /
`kindIdOf` / `nodeKindById`) と、両端の種別から edge の**候補**を引く `edgeKindsBetween` /
`isTemplateEdge` を見る。

## なぜ

**種別を `nodeType` ではなく property に載せた** (設計 D3, 2026-09-12)。toulmin の「主張」は
見た目としては markdown node であり、`nodeType` (markdown / グループ / 画像) とは
**直交する軸**である。property に載せると `node.setProperty` と、プロパティ名ごとに割れた
競合単位 (P1 の `fieldKeyOf` を入れたときに確認した) がそのまま使える — **新しい op も
新しい競合規則も要らない**。

そのプロパティ名は **template ごとに分かれる**。`spec/propertyEditor.md`「名前」は
system / extension / custom の 3 つを定めており、**template は拡張 (extension)** なので
「提供者のドメイン (逆順)」を前置する。`TemplateId` を逆順ドメインにして名前空間を
兼ねさせているので、名前は id から導ける。

edge 側の主題は **「繋げない」と「制約の対象外」を取り違えないこと**である。どちらも
候補は空になるが、前者は toulmin node どうしで許されない組、後者は片端が普通の node で
自由に繋いでよい場合である。混同すると**普通のノードに繋げなくなる**。

## どのように

### 種別の読み書き

- **template の id から名前空間ごと導く**: 名前を別に持たず id から導けること。
- **system (`app.conversensus.*`) ではない**: template は本体のものではない。
  ここを間違えると、仕様が拡張のために用意した枠を使わずに本体の枠を侵すことになる。
- **custom にも見えない**: `.` を含むことが「編集者のものではない」の判定規則そのもの。
- **template が違えば別のプロパティになる**: だから **1 つの node が複数の template の
  種別を同時に持てる**。これは一般化として正しい — 制約が働くのは 1 つの template の中
  だからである。
- **property が無い / `kind` が無いなら `undefined`**: 種別を持たない = template の要素では
  ない、が既定である。
- **空文字は種別なし**: 「外した」形が来ても種別として読まない。
- **文字列でない値は種別なし**: op-log は他の参加者が書く。**他人の書いたログを信用しない** —
  数値や `null` が入っていても落ちずに「種別なし」として読む。

### 種別 id から種別を引く

- **別の template のプロパティは読まない**: `kindIdIn` は渡された template の名前空間
  しか見ない。ここが漏れると、名前空間を分けた意味が無くなる。
- **その template に無い id は種別なし**: 種別名を変えても id は切れないが、
  **id ごと消えた場合**は種別なしとして読む。

### edge の候補

- **許される組は候補 1 / 許されない組は候補 0**: toulmin の 5 つの規則そのもの。
- **toulmin では候補が 2 以上にならない**: 5×5 の全組合せを数えて、候補 1 がちょうど 5 つ、
  候補 2 以上が 0 であることを固定する。**これが「step2 では選択メニューが要らない」の
  根拠そのもの**なので、例ではなく全数で見る。
- **候補が複数になる template では複数返す**: step2 では到達しないが、判定は一般の形で
  ある (設計 D5)。合成 template で通しておくと、step3 で UI を足すときに判定側を
  書き直さずに済むことが確かめられる。
- **判定は template ごとに閉じる**: 両端が**同じ** template の種別を持つときだけ、その
  template の規則が効く。同じ `NodeKindId` でも template が違えば別物である。
- **返すのは `EdgeKindRef` (種類 + template)**: 種類を書き込むプロパティ名が template
  ごとに分かれるので、どの template の種類かを失ってはいけない。

### 種別プロパティの見分け (`isKindProperty` / `hasTemplateKind`)

**どの template のものかを問わない判定**である。「ラベルを編集させてよいか」のように
template を特定する必要が無い問いに使う — 描画側 (`EditableLabelEdge`) に template を
配るより、規約をここに 1 つ置く方が漏れない。

- **種別プロパティを名前だけで見分ける / custom は当たらない**: `.` を含まない名前は
  編集者のものなので、誤って当たることは無い (`spec/propertyEditor.md`)。
- **種別以外の拡張プロパティも当たらない**: 語尾が `.kind` であることが判定である。
- **候補 0 と「制約の対象外」は別物**: `edgeKindsBetween` はどちらも空を返すので、
  **`isTemplateEdge` が両者を分ける唯一の手段**である。ここを 1 本のテストで
  並べて示してある。
