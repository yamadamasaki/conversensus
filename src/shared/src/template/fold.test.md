# template/fold のテスト仕様

## 何を

適用された template から **選べる種別の一覧** (`nodeKindsOf` / `edgeKindsOf`) を出す
畳み込みを見る。

## なぜ

`templateIds` は複数を許す。**当面は toulmin 1 つしか当てないが、畳み方を後から決めると
「1 つのときだけ通る実装」が固定される** (設計 §4)。したがってこのテストの主題は
toulmin が正しく引けることではなく、**複数のときの畳み方**である。

> **2026-09-12 の仕様変更で、接続の判定はここから出た。**当初は label の照合で
> 「警告してよいか」を 3 値で畳んでいたが、仕様が toulmin node とその他を分けたので、
> 判定は**種別 id**で行うようになった (`kind.test.md`)。ここに残るのは一覧だけである。

## どのように

### 種別の一覧

`nodeKindsOf` / `edgeKindsOf` は**メニューに何を並べるか**だけを持つ。接続の可否は
種別 id で判定するので `kind.ts` にある (設計 D5, 2026-09-12)。

- **toulmin の内容**: spec の表 (5 種別 / 5 接続) をそのまま固定する。**順序込みで見る**のは、
  これがメニューの並びになるからである。
- **template が無ければ空**: 種別メニューを出さない根拠になる。
- **複数 template は和になる — 狭めない**: template は語彙を**足す**ものである。
- **同じ id は先に来た方を残す**: 一覧は和だが、並びが安定していないとメニューが揺れる。

## 対象外

- **プロパティの定義** (`EdgeKind.properties`) は宣言だけで、食う画面が無い (設計 事実 D)。
  Phase 4 の property editor が入るまで検証しようがない。
- **接続の可否**は `kind.test.md` にある。ここは一覧だけを持つ。
- **2 つの template が同じ `NodeKindId` を使ったとき**。一覧も種別の解決も「先勝ち」で
  揃えてあるが、曖昧であること自体は解消していない → step3 (設計 §7)。
