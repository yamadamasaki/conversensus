# 後から当てた template のテスト

## 何を

`applied.ts` — 既にある sheet に後から当てた template (#355、計画 apply-template-355.md)。後から当てたものは
op の種類を足さず、template graph ごとに 1 つの sheet のプロパティ
(`app.conversensus.appliedTemplate.<template graph の sheet の id>` = `{ at: 切断面 }`) で表す。
`appliedTemplateRefs` は、作るときのもの (`sheet.templateIds`) と後から当てたものを合わせて、sheet に当たっている
template をすべて求める。template を読む所はどこもこれを使う。

## なぜ

- **並びが手元によって変わると、同じログから違う画面が出る。**プロパティの並びは畳み込みの順に依るので、
  id で並べて決めている。これが崩れると、種類のメニューの並びや、同じ名前の種類が 2 つあるときにどれが引けるかが
  人によって変わる
- **同じ template graph が二重に当たると、種類が 2 回並ぶ。**後から当てる入口は当たっているものを出さないが、
  2 人が同時に当てれば重なりうる。そのときは作るときの切断面を採る
- **キーを template graph ごとに分けたのは、同時に当てたときに片方が消えないため**である。1 つのキーに配列を
  置く形では `sheet.setProperty` の後勝ちで片方が消える。これを op-log からの畳み込みで確かめる

## どのように

- 性質 (fast-check):
  - 作るときのものが先にその順で並び、後から当てたもののうち重ならない分が id の順で続く
  - プロパティを入れる順を入れ替えても、答えは同じ
- 例:
  - 両方にある template graph は、作るときの切断面を採る
  - 後から当てたものが無ければ、作るときの配列そのものを返す (`useResolvedTemplates` が中身で比べるので同一性は
    要らないが、余計な配列を作らない)
  - 読めないもの (形の違う切断面・`null`・数・id でないキー・ほかのプロパティ) は黙って落とす。相手の新しい書き方でも
    sheet を開けるべきだから (`sheetKindOf` と同じ)
  - `appliedTemplateSheetIds` は、作り込みの id を含めずに template graph の id を返す (候補から除くため)
  - 2 人が互いを知らずに別の template を当てた歴史を、2 通りの順で畳んでも、どちらの template も残る

**生成器**: template graph の sheet は 4 つの小さなプールから、作るときのもの (0〜3 個) と後から当てたもの (0〜4 個) を
別々に、重複なく引く。プールを小さくするのは「両方にある」場合に当てるためである。切断面の中身は並びと重なりに
関わらないので 1 つに固定する。

**変異で確かめた**: 並べる所を外すと性質 2 つが、重なりを除く所を外すと性質 1 つと例 1 つが落ちる。
