# templateGraphOf のテスト

## 何を

`templateGraphOf` — template の表 (種, `SEED_TEMPLATES`) を template graph の中身 (node・edge・置き場所) に
する (step3 Phase 4 S4-1c)。「Toulmin model を追加」が File に複製するのに使う。

## なぜ

Q1 で Toulmin は「作り込みの template」から「File に複製する template graph」になった。当てたシートが
参照するのは複製の方なので、**複製を読み替えた種類が元の表と食い違うと、Toulmin が静かに別物になる**
(端の向きが逆、説明が落ちる、既定値が消える)。`templateFromSheet` の逆向きなので、**往復で同じ種類に戻る**
ことを性質として書く。

## どのように

### 生成器

- node の種類は 1〜4 つ、名前は**重ならない**ように小さなプールから引く。往復は id ではなく名前で比べる
  (複製すると id は変わる) ので、同じ名前の種類が 2 つあると区別できない
- edge の種類は 0〜5 つ。端の番号が種類の数以上なら「任意」にして、任意の端を引く。両端とも任意の edge は
  種類にならない (template graph の説明書きと同じ) ので引かない。label の有無・既定値の有無も引く

### 性質

| 性質 | 固定すること |
| --- | --- |
| 種 → template graph → 読み替え で同じ種類に戻る (名前・説明・端の種類の名前・既定値) | 複製と読み替えが互いの逆になっている |

### 例

- Toulmin model は往復して同じ種類に戻る
- 「任意」の端を持つ種類があると、label の無い node を **1 つだけ**置く (任意の端ごとに増やさない)
- すべての種で、置き場所が重ならない

## 並べ方 (#256)

### 何を・なぜ

種は自分の並べ方 (`KindPlacement`) を持てる。Toulmin model は 3 列の格子に並べると、上の段で
「正当化する」がデータの node を横切り、label が重なって読めなかった (FPR の確認 §3)。

- 並べ方を渡すと、その種類の node はそこに置かれる
- Toulmin の並べ方では、**edge の label どうしが 120px 以上離れ、どの label も node の中に
  入らない**

### どのように

label は edge のおよそ中点に出るので、両端の node の中心を結ぶ線分の中点で近似する。
node は既定の大きさ (160 × 80) とする。曲線の形や接続点の辺 (`graph/facingSides.ts`) は
描く側の話なので、ここでは置き場所が満たすべき条件だけを見る。
