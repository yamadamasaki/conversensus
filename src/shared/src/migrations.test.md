# migrations テスト仕様

## 何を

`.conversensus` ファイルを**最新形式として解釈する** `parseConversensusFile` をテストする。
v5 の素通し、v4 / v3 / v1 からの移行、どの版でもないものの拒否を見る。

## なぜ

同じ解釈が **client (`Sidebar` の読み込み) と server (`POST /files/import`) の両方で必要**
である。以前は同じ if の連なりが両側に写してあり、版を 1 つ足すたびに 2 箇所直す形だった
(v5 = ANA-116 D1 の同梱 blob でそれに気付いた)。1 箇所に集めた以上、**階段が途中で
切れていないこと**をここで固定する — 切れると「昔のファイルが開けない」という形で、
使う人にしか分からない壊れ方をする。

## どのように

版に依らない最小のグラフ (どの版のスキーマにも合う形) を土台に、版ごとの差分だけを
足した payload を渡す。移行が本当に働いたかは、**その版の要点**で見る。

- **最新版 (v5) はそのまま通し、同梱 blob を保つ**: `blobs` が落ちないこと。
  ここが落ちると export/import で画像が失われる (D1 の再発)
- **v4 を v5 に上げる (`blobs` は付けない)**: v4 のファイルには実体が無い。
  空配列を付けると「同梱したが空」と区別できなくなる
- **v3 を辿って v5 にする**: v3→v4 の要点である「`nodeType` がレイアウトからノードへ
  移る」ことと、レイアウト側から消えることを見る
- **v1 を最後まで辿って v5 にする**: v1→v2 の要点である「`style` がレイアウトへ分離
  される」ことを見る。**階段の全長が繋がっている**ことの確認でもある
- **どの版でもないものは失敗させる**: 返すのは**最新スキーマのエラー**である。
  旧版として読めなかった理由を並べても助けにならない (ほとんどは単に壊れている)

各段の移行関数そのもの (`migrateV1toV2` など) の詳細な変換は、この階段を通した
結果として観測している。段を足すときは、ここに「その段の要点」を 1 件足すこと。
