# pasteTarget のテスト仕様

## 何をテストするか

画像を貼り付けたときの**行き先の選び方** (`pickImagePasteTarget`)。
設計 D6 の「画像ノードが選択されているならそのノードへ, いなければ新規ノード」を
規則として固定する (`deepse/plans/step1-refinement-ana116-image.md` §4 D6)。

## なぜテストするか

貼り付けは**利用者が結果を予測できること**が要件である。「どこへ入るか」が
選択状態で変わる以上, その分岐は仕様であって実装の都合ではない。
`GraphEditor` の中に埋めたままだと, 大きなコンポーネントを描画しないと
確かめられず, 境界条件 (複数選択・別種の選択) が誰にも見えなくなる。

## どのようにテストするか

React Flow の `Node` は多くのフィールドを持つが, 判断に要るのは
`id` / `type` / `selected` の 3 つだけである。テストもその最小の形で書き,
React Flow を描画しない。

- **画像ノードが 1 つ選択されていればそれを返す** — 基本形
- **選択が無ければ `undefined`** — 呼び出し側が新規ノードを作る合図
- **画像ノードが複数選択されていれば `undefined`** — そのうちの 1 つが差し替わると
  どれが変わったか予測できない。**新規ノードを作る方に倒す**
- **選択されているのが画像ノードでなければ `undefined`** — テキストノードを
  選んだまま画像を貼っても, そのノードを画像で潰さない
- **画像ノードと別種を同時に選んでいる場合も画像ノードを選ぶ** — 条件は
  「画像ノードがちょうど 1 つ」であって, 選択総数ではない

## ここでテストしないこと

- **貼り付けた画像の保存と op の組み立て**: `imageBlob.test.ts` の領分
  (`saveImageBlob` / `imagePropertiesChange`)
- **キーボード経路とクリップボード API**: ブラウザ差の吸収は `GraphEditor` 側の配線で,
  単体では観測できない
