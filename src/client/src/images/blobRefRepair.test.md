# blobRefRepair のテスト

## 何をテストするか

壊れて保存された画像の参照を、受け直さずに手元で直せること (#264)。壊れた形は、v1.0.0 の直前まで
実際に起きていた経路で作る — `@atproto/api` の `jsonToLex` (blob を `BlobRef` のインスタンスに
変える) → Worker への `structuredClone` → JSON として保存。

- 壊れた形では画像の場所が読めない (画面では「画像 URL を入力」のまま)
- `repairBrokenBlobRefs` で元の参照に戻り、画像の場所が読める

## なぜテストするか

PR #244 で受信の入口は直したが、それより前に受け取って保存したものは直らなかった。受信は手元に
無い batch だけを引くので、壊れた行は引き直されない。保存を消さずに直すには手元で戻すしかない。

壊れた形を手で書くと、`@atproto/api` の形が変わったときに気付けない。ここでは実物の経路で作る。
修復の関数そのものの性質 (壊れていない値は同じ値を返す、など) は shared の `blob.test.ts`、
保存の書き直しは `eventStore.test.ts` が見る。
