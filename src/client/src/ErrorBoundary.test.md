# ErrorBoundary.test.tsx

## 何を

描画中の例外を、境界の内側だけの知らせに留める部品 `ErrorBoundary` (#290)。App ではグラフ・左右のサイドバー・
アプリ全体に置いている。

## なぜ

React は描画中の例外を受け止める境界が無いと木全体を外し、画面が真っ白になる。描くものには他人が書いた値
(受信した op) が混ざるので、1 つの壊れた値で全部が消え、何が起きたかも分からなくなる。

## どのように

外から壊す・直すを切り替えられる子 (`Fragile`) を境界の中に描く。

- **場所と理由を知らせる**: 知らせ (`role="alert"`) に「グラフを表示できませんでした」と例外の文が出る
- **隣は描かれたまま**: 境界を 2 つ並べ、壊れていない方の中身が残る。境界を置く目的そのもの
- **「もう一度表示する」で描き直す**: 一時的な例外 (読み込みの途中など) なら、直った後に押せば中身に戻る
- **コンソールに残す**: 場所の名前つきで 1 回。知らせの文だけでは調べられないので、部品の stack も出している

React と境界がコンソールへ出すエラーは `console.error` を黙らせて見る (テストの出力を汚さない)。
「再読み込み」(`location.reload`) は押していない — 押した先はブラウザの仕事である。
