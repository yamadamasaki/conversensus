# NodeTypeMenu のテスト仕様

## 何を

ノード生成メニューが**見た目を選んでから、その見た目の種類を選ぶ**形 (#412) になっていること、
種類を選ぶとその種類の見た目の node になること (#406)、および
**template が当たっていないシートでは種類が並ばない**ことを見る。

## なぜ

いまの「ノードの種類」は **markdown / グループ / 画像** — *見た目*の種類である。
template が言う「種類」は*意味*の種類 (主張 / データ / …) で、**直交する 2 つの軸**である
(設計 事実 C)。同じ語が 2 つの意味を持っていたので、画面の文言ごと分けた。

2 つの軸は直交するが、種類は見た目を 1 つ持つ (template-update K11: 見た目も種類の一部)。
以前は種類の段が見た目の段と別にあり、どの種類を選んでも markdown になったので、group の種類が
group node にならなかった (#406)。今は各見た目のすぐ下に、その見た目の種類を字下げして並べる。

種類を出す / 出さないは**普通のグラフを侵さないための境界**である (設計 D1・D3)。
共同作業では相手の画面にも出るので、意味的に誤ったメニューは自分だけの問題にならない。

## どのように

- **template が無ければ見た目だけが並ぶ**: 種類の名前が出ないこと。
- **template があれば、各見た目のすぐ下にその見た目の種類が並ぶ**: 見た目の違う種類を持つ template
  (markdown 2 つ・group 1 つ・image 1 つ) で、ボタンの並びが「見た目、その見た目の種類、次の見た目、…」で
  あることを順序まで固定する。順序が崩れると、どの見た目の種類か位置で読めなくなる。
- **種類を選ぶと、その種類の見た目と `NodeKindRef` を渡す**: group の種類なら `'group'` (#406 の回帰を防ぐ)。
- **見た目を選ぶと種別を伴わない**: `onSelect('group')` であって
  `onSelect('group', undefined)` ではない (引数の数まで固定する — 呼び出し側が
  `label` の有無で分岐するため)。
- **見た目を持たない種類を選ぶと見た目は markdown に決まり、`NodeKind` ごと渡す**: 見た目と種類を
  別々に 2 回選ばせることはしない。種類が見た目を決めるので 1 回で済む。
  渡すのが label ではなく `NodeKind` なのは、**id が実体で label は表示**だからである
  (設計 D3)。label だけ渡すと呼び出し側が id を引き直すことになる。

  **ここが種別を決める唯一の場所である** (2026-09-12 の仕様変更)。toulmin node の種別と
  ラベルは作成時に決まり、その後変更できない (OnMutation)。当初あった「右クリックで
  後から変える口」は撤回された。
- **種別の説明を `title` に出す**: 「主張」「論拠」「裏付け」の 5 語だけでは、
  toulmin を知らない人に区別がつかない。説明は `NodeKind.description` にあるので、
  持っている情報を捨てない。
- **種類の名前と説明は見る人の言語で出す** (#356): 日本語で複製した Toulmin (`multilingualSeed`) を en で開くと
  「Claim」と英語の説明が出て「主張」は出ない。ja では「主張」。訳は template graph の property から来るので、
  メニューが `kindLabelIn`・`kindDescriptionIn` を通らないと、言語の違う参加者が読めない名前を見る
