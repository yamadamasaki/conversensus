# NodeTypeMenu のテスト仕様

## 何を

ノード生成メニューが **2 段** (見た目 / 種別) になっていること、および
**template が当たっていないシートでは種別の段が無い**ことを見る。

## なぜ

いまの「ノードの種類」は **markdown / グループ / 画像** — *見た目*の種類である。
template が言う「種類」は*意味*の種類 (主張 / データ / …) で、**直交する 2 つの軸**である
(設計 事実 C)。同じ語が 2 つの意味を持っていたので、画面の文言ごと分けた。

段を出す / 出さないは**普通のグラフを侵さないための境界**である (設計 D1・D3)。
共同作業では相手の画面にも出るので、意味的に誤ったメニューは自分だけの問題にならない。

## どのように

- **template が無ければ「種別」の段そのものが無い**: 2 段目が空になるのではなく、
  見出しごと無い。空の段があると「この sheet には種別が定義されていない」ではなく
  「種別を選び忘れている」に見える。
- **template があれば 2 段になる**: toulmin の 5 種別が並ぶこと。
- **見た目を選ぶと種別を伴わない**: `onSelect('group')` であって
  `onSelect('group', undefined)` ではない (引数の数まで固定する — 呼び出し側が
  `label` の有無で分岐するため)。
- **種別を選ぶと見た目は markdown に決まり、`NodeKind` ごと渡す**: 2 軸なのだから理屈では
  両方訊けるが、**種別を持つのは意味のあるノードだけ**なので訊かない。ここを 2 段階の
  選択にすると、ノード 1 つ作るのに 2 回選ぶことになる。
  渡すのが label ではなく `NodeKind` なのは、**id が実体で label は表示**だからである
  (設計 D3)。label だけ渡すと呼び出し側が id を引き直すことになる。

  **ここが種別を決める唯一の場所である** (2026-09-12 の仕様変更)。toulmin node の種別と
  ラベルは作成時に決まり、その後変更できない (OnMutation)。当初あった「右クリックで
  後から変える口」は撤回された。
- **種別の説明を `title` に出す**: 「主張」「論拠」「裏付け」の 5 語だけでは、
  toulmin を知らない人に区別がつかない。説明は `NodeKind.description` にあるので、
  持っている情報を捨てない。
