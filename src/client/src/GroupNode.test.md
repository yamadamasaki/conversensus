# GroupNode.test.tsx — テスト仕様

## 何をテストするか

`GroupNode` — グループ・ノードの見た目と、ダブルクリックの振り分け。
タイトルバーはラベル編集、本体はノード生成。

## なぜテストするか

ANA-107 S4 (設計 D5) で、本体のダブルクリックの意味を変えた。
以前はここで直接 markdown ノードの `NODE_ADDED` を dispatch していたため、
グループ内では markdown しか作れなかった (ANA-110)。今は pane と同じ
`NodeTypeMenu` を開き、種類が選ばれてから生成する。

「直接作らなくなった」ことは画面を見ても分かりにくい (メニューが一瞬で
閉じれば同じに見える) ので、**dispatch していないこと**を明示的に張る。

## どのようにテストするか

`@xyflow/react` と 2 つの context をモジュール単位でモックし、React Flow の
実体なしにコンポーネント単体をレンダリングする (`EditableNode.test.tsx` と
同じ方式)。生成先コンテナがメニューに正しく渡るかを、モックした
`openNodeTypeMenu` の引数で見る。

### 観点ごとの意図

- **本体のダブルクリック**: `openNodeTypeMenu` が「クリックした画面座標」と
  「このグループの id」で呼ばれる。id を渡さない実装だと、選んだノードが
  グループの子にならずトップレベルに出てしまう。あわせて
  **その場では dispatch しない**ことを見る。
- **タイトルバーのダブルクリック**: メニューではなくラベル編集が始まる。
  同じ要素の中で意味が分かれるので、取り違えを固定する。
- **ghost 表示**: 差分表示の抜け殻ではノードを作らせない。

座標をコンテナ相対に直す処理は `hooks/useNodeTypeMenu.test.ts` が担当する。
