# viewLink のテスト

## 何をテストするか

`viewLink.ts` は、グラフ view のアドレスを URL の fragment にし、また読み戻す (#251 Deep Link)。

- `viewHash`: trunk は `#/v/<fileId>/<sheetId>`、branch は `#/v/<fileId>/<sheetId>/<branchId>`。
  過去の切断面は query の `at=<actor>@<seq>` (actor の順)、強調は `n=` / `e=` に載せる (#73 の「その時点のタブ」)。
  空の切断面は値の無い `at=`、空の強調は何も載せない
- `parseViewHash`: アドレスを戻す。知らない query は読み飛ばす。view のリンクでなければ、また切断面・強調が
  読めなければ null
- `viewUrl`: 元の URL の path と query は残し、fragment だけを替える

## なぜテストするか

リンクは**他の人・他の端末・後の版**が読む値である。

- 往復が崩れると、渡したリンクが別の view (branch ではなく trunk など) を開き、しかも開いた側には
  間違いだと分からない
- ログインの戻り (OAuth) も fragment を使う (`#state=…&code=…`)。これを view のリンクと取り違えると
  ログインの途中で画面が動く。`#/` で始まるかどうかで見分けることを固定する
- 外から来た値なので、壊れた値 (id の形が違う・段の数が違う・壊れた `%`) を開かず、投げもしない
- #251 では切断面と強調を載せていなかった。#73 で載せたので、その前の版が書いたリンク (query 無し) も
  今の版で開ける (最新として読む)。逆に、後で項目を足しても今の版が読み飛ばして開けることを固定する
- actor は DID と端末の id で、`:`・`#` を含み、did:web では `@` も含みうる。最後の `@` で分けるので、
  そのような actor でも戻ることを性質で見る

## どのようにテストするか

- 往復は**性質**で書く: あらゆる UUID の file・sheet・強調の要素と、有無を問わない branch、最新か
  vector の切断面で `parseViewHash(viewHash(a))` が a に戻る (空の強調は「強調なし」として)。
  id は UUID の生成器から引く — 形の検査 (zod) を通る値の全体が対象だから。actor は小さなプール
  (`:`・`#`・`@` を含むものと含まないもの) から引く
- 性質が見つけた反例: **空の切断面が最新に化けた** (`at` が 1 つも無いと最新と読むため)。値の無い `at=` で
  表すようにし、例として残した
- 「投げない」も性質で書く: 任意の文字列と、頭に `#/v/` を付けた任意の文字列
- view のリンクでないものは例で並べる (空・OAuth の戻り・頭が違う・段の過不足・id の形・壊れた `%`・
  読めない `at`・形の違う強調)
