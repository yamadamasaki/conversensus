# registry.test.ts — node の操作の拡張点のテスト仕様

## 何を

node の操作の拡張点 (`nodeAction.ts` の型、`registry.ts`。計画 node-actions-request-module.md N1) を検証する。

- `createNodeActionRegistry`: module の登録
- `actionsFor`: この node に今使える操作
- `badgesFor`: この node に描く印
- `validateArgs`: 引数を宣言どおりに確かめる
- `runNodeAction`: 直前に確かめ直してから実行する

## なぜ

core は「node に操作がある」ことだけを知り、どんな操作があるかは module (依頼が最初) が登録する。
画面 (node のそば・右クリックのメニュー・dialog) と MCP の道具は、どちらもここの判断を使う。
**ここが崩れると、押せるのに効かないボタンや、見るだけの所で書ける操作が出る。**どの module が
登録されても成り立つべき約束なので、全称命題は性質として書く。

## どのように

### 使える操作 (性質)

- **見るだけの所では、どの node にも何も出ない** (`readOnly`)
- **出るのは使える操作ちょうど**で、順は登録の順。使えない操作は出ず、使える操作は落ちない
- **実行は、使える操作のときだけ `run` に届く。**見るだけ・知らない鍵・今は使えない、のどれでも
  `NodeActionError` を投げ、`run` を呼ばない (dialog を開いている間に使えなくなった場合に当たる)

**生成器**: module を 1〜3 個、それぞれに 0〜3 個の操作を持たせる。操作が使えるかどうかは
「node の本文が、その操作の token を含むか」で決め、token は 4 つの小さなプールから引く。

- 小さなプールにするのは、同じ token を持つ操作 (同じ node で一緒に使える・使えない) と、どれも使えない
  node (本文が空) をよく引くためである
- id は位置から振るので、重ならない。重なりは登録の誤りなので、例で確かめる
- 実行の鍵は、登録された鍵から引くか、操作が 1 つも無ければ知らない鍵になる

性質が見張っていることは、2 つの壊し方で確かめた。

- 実行の直前の確かめ直しを外すと、3 つ目の性質が落ちる
- `readOnly` のときに全部を返すようにすると、1 つ目の性質が落ちる

### 登録 (例)

- module の id・同じ module の中の操作の id が重なるもの、区切り文字 `/` を含む id、空の id は断る
  (起動のときに 1 度だけ登録するので、ここで止めてよい)
- 別の module なら同じ操作の id でもよい。鍵は `<module>/<action>`
- `available` が投げる操作は出さず、警告を残す。module の誤りで画面を落とさないため

### 印 (例)

- 印は module の登録の順に並び、どの module の印かを添える (画面は `data-node-badge` に出す)。印を決める関数には
  node と、出ていく edge を引く関数だけを渡す (すべての node について呼ばれるので、Sheet 全体は渡さない)。
  次の 3 つは飛ばす。
  - 印を返さない module
  - 印を持たない module
  - 印の関数が投げる module

### 種 (例)

- module の種 (`NodeModule.seeds`、計画 B2) を登録の順に並べる。種を持たない module は何も足さない
  (core の種は画面が前に置く — `CORE_SEEDS`)

### 知らせ (例)

- 知らせ (`NodeModule.notices`、計画 B1) は、知らせを持つ module の登録の順に集め、module の id を添える。
  見つける関数が投げる module は飛ばす (受信を止めない)
- 既読の鍵 (`noticeKeyOf`) は module の id を前に付けるので、module の間で重ならない
- 知らせの欄の宣言は module の id で引ける (`noticeSource`)

### 引数の確かめ

- (例) 宣言どおりの値はそのまま通る。足りない値は次のように扱う。
  - `actors`: 空の配列
  - 任意の `text`: 空文字
  - `choice`: 既定が無いので誤り
- (例) 次の値は断る。
  - 宣言に無い名前。MCP から来た引数の綴り違いを黙って捨てないため
  - 選択肢に無い値
  - 空白だけの必須の本文
  - 配列でない `actors`
- (性質) 確かめは冪等で、`actors` は同じ人を 1 度だけ持つ。宛先を 2 度選んでも 1 人になる

### 初めの値を宣言に合わせる (#393)

- (例) 選択肢に無い値は先頭の選択肢に、形の違う値 (配列でない actors・文字列でない text) は空に、知らない名前は落とす。
  直した値は `validateArgs` を通る (dialog の「実行」が詰まらない)
- (性質) 直した後は、選択肢の値は選択肢の中・名前は宣言の中にあり、直し直しても変わらない。生成器は正しい値と
  形の違う値を混ぜた小さなプール
