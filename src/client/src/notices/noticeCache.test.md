# noticeCache.test.ts — 閉じていない通知の端末の控えのテスト仕様

## 何を

`saveNotices` / `loadNotices` (localStorage への控え) を検証する (step3 Phase 6 S6-1b, 設計 Q2)。

## なぜ

競合と上書きの通知は「受信前の手元」を分岐点に検出するので、受信が済んだ後には求め直せない (設計 F4)。
閉じる前に再読み込みすると消えるので端末に控える。内容は PDS に置かない (Q4)。

## どのように

- **往復**: 控えて読むと元に戻る。`MergeConflict` は op を含むただの JSON で、`Map` (名前の対応表) は
  組の配列にして持つ
- **actor ごとに分かれる**: 同じブラウザで別の人がログインしても、前の人の通知は出ない。未ログインも別の鍵
- **空になったら消す**: 閉じた後に古い控えが残って、再読み込みで出直さない
- **壊れた控え**: JSON でない・形が違うものは `null`。通知が出ないだけで、画面は壊れない
- **localStorage が使えない環境** (`safeLocalStorage` が null): 何もしない

## 前に出ていない File の通知の控え (#260)

前に出ていない File の競合の通知 (`pending`、File ごとに 1 つ) も控える。再読み込みしてもタブの印と中身が残る。

- 控えて読むと元に戻る。**`pending` だけがあるときも控えを消さない** (空の判定に入れ忘れると、前の File に
  通知が無いだけで背後の分まで消える)
- `pending` の形が壊れていたら控えごと null (通知が出ないだけ)。古い控え (`pending` が無い) はそのまま読める
