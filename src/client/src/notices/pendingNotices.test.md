# pendingNotices.test.ts — 前に出ていない File の競合の通知の控えのテスト仕様

## 何を

`addPending` (競合の通知をその File の控えに足す) と `takePending` (その File の控えを取り出す) を検証する (#260)。

## なぜ

右下の競合の通知は前に出ている File の分だけを出す。背後のタブの File で検出した競合と、前から外れた File の
出ていた通知は、File ごとにここへ溜まり、タブの印になる (利用者判断 2026-10-11)。

- **同じ競合を 2 度溜めない。**前から外した通知と背後で検出した通知は重なりうる。重ねると、前に出したときに
  同じ競合が 2 行並ぶ
- 名前は合わせるが、**先に溜めた方を残す** (検出したときの分岐点の名前)
- 保留した件数 (fork の数) は足すが、競合の数を超えない
- 溜めるのは File の分かる通知だけ (既読を File ごとに書くため)

## どのように

- 例: File ごとに溜め、取り出すと残りから消える。元の控えは変えない (React の state に置く)
- 例: 同じ File に重ねたときの競合・名前・保留の件数
- 例: File の無い通知と競合の無い通知は溜めない / 控えに無い File を取り出すと同じ控えを返す (state を替えない)
- 性質: **あらゆる溜める順で**、File の控えの競合の鍵は、その File に溜めた通知の鍵の和集合と一致し、重複しない
  - 生成器は 2 つの File と 3 つの対象から引く。小さなプールにして、同じ競合が重なる場面を頻繁に起こす
