# fakePds.test.ts — App 結合テスト用の PDS

## 何を

`fakePds.ts` が、conversensus が頼っている PDS の振る舞いを本物どおりに再現していること。

## なぜ

App 結合テスト (`App.app-test.tsx`) は、この偽物を通して「同期が画面まで届く」を検証する。
**偽物が本物とずれていると、App 結合テストは偽物の側が正しいことを確かめるだけになる。**
特に `listRecords` の範囲の意味は、step1 Phase 7 の範囲取得 (`rangeFetch.ts`) がそのまま
依存しているので、ずれると範囲取得の不具合を見逃す。

## どのように

### `listRecords` の範囲の意味 (性質)

**あらゆる rkey の集合・ページの大きさ・向きで、cursor を辿ると全件が 1 回ずつ rkey 順に出る。**

これは「ある例で成り立つ」ではなく全称命題なので、性質として書く (CLAUDE.md)。

生成器の判断:

- rkey は `[a-z0-9~]{1,6}` の**小さなプール**から引く。`~` を含めるのは本物の rkey
  (`v1~<fileId>~<clock>~<batchId>`) の区切りが辞書順に効くためで、短くするのは
  前方一致・同値に近い rkey どうしが当たるようにするため
- ページの大きさは 1〜5、件数は 0〜12。**ページ境界にちょうど揃う場合**が頻繁に出る
  (境界で cursor を返す・返さないの取り違えがここで出る)
- 向きは両方 (`reverse`)

例として残すもの: 「ページがちょうど埋まったときは cursor を返す」。本物は埋まったときだけ
cursor を返し、次のページが空になる。性質は全件を辿れることしか見ないので、
**cursor を返す条件そのもの**は例で固定する。
