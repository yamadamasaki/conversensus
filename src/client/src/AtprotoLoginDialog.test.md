# AtprotoLoginDialog.test.tsx — ログインのダイアログ (step3 Phase 2 D7)

## 何を

ログインのダイアログが、認証の口 (`atproto/auth.ts`) の種類に応じて 2 つの形を取ること。

- **OAuth** (本番と開発): handle だけを入れる。パスワード欄は出さず、PDS のページへ移ることを案内する
- **パスワード** (App 結合テストの偽の PDS だけ): handle とパスワードを入れる

## なぜ

認証を ATProto OAuth へ移した (計画 Q3)。**公開するアプリで利用者に app password を入れさせない**
ことが目的なので、OAuth のときにパスワード欄が出ていたら、移した意味が無い。

一方、App 結合テストは OAuth の同意画面を通れない (PDS の画面を人が操作する) ので、偽の PDS に
パスワードでログインする。ダイアログはその両方を受ける。

## どのように

| テスト | 固定すること |
| --- | --- |
| 🔴 OAuth ではパスワード欄を出さない | handle だけで `onLogin(handle, undefined)` が呼ばれる。案内が出る |
| パスワードの認証ではパスワードが無いと押せない | 既存の振る舞い (App 結合が通る道) |
| OAuth を始められなかったら handle を確かめるよう出す | handle が解決できないなど。パスワードの話をしない |

## テストしていないこと

- **OAuth のやりとりそのもの** (`oauthAuth.ts`) — PDS の同意画面を人が通るので自動化できない。
  開発用 PDS で実機で確かめた (設計の S2-6 の記録)
