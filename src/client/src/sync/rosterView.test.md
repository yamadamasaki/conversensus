# rosterView.test.ts — 名簿を一覧に整形するテスト仕様

## 何を

`rosterRows` (名簿 + 見る人 → UI の表の行) を検証する。

## なぜ

仕様の UI 例が求めるのは「invite されているアクタと invite しているアクタ, 参加コード,
**状態**, **action** の表」である。**状態と action は名簿そのものではない** — 同じ行でも、
自分の行なら承認でき、他人の行なら取り消せる。**見る人の立場で変わる**。

この導出をコンポーネントに置くと、表を描く関心と「誰が何をできるか」の判断が混ざる。
後者は pre 条件と対応していなければならない (押せてしまって畳み込みで捨てられるより、
押せない方がよい) ので、単体で確かめられる形に切り出してある。

## どのように

### 状態

- **招待済は `sent`、承認済は `accepted`**
- **取り消しは `revoked`、自分から降りたのは `resigned`。**外から見て両者は区別がつかない
  ので、畳み込みの `departed` が覚えている
- **招待されていない actor の承認は `invalid`。**これは名簿の**外**から来る唯一の行である
  — 畳み込みで捨てられるので `participating` にも `invited` にも現れない。
  **`rejected` (捨てた op と理由) を返す設計にしたのは、この 1 行を出すためである**
- **`invalid` は後から正規に招待されたら上書きしない。**「承認しようとして弾かれた人」が
  その後ちゃんと招待されたなら、出すべきは `sent` である
- **他 PDS への招待は一覧に載せない。**名簿に関わったことが一度も無いからである。
  承認だけを `invalid` として拾うのは、「その人が参加しようとした」という事実が
  本人にも招待者にも見えるべきだからで、招待の失敗は招待した側が既に知っている
- **招待者を出す。**作成者 (genesis) には招待者が無い

### action は立場で決まる

| 行 | viewer | できること |
| --- | --- | --- |
| 自分・`sent` | — | `preview` / `accept` |
| 自分・`accepted` | — | `resign` のみ |
| 他人・`sent` or `accepted` | 参加者 | `revoke` |
| 他人 | 参加していない | 何もできない |
| 外れた行 (`revoked` / `resigned`) | — | 何もできない |

- **自分を `revoke` する action は出さない。**`resign` と同じことなので二重に出さない
- **参加していない viewer は他人に何もできない。**取り消しの pre 条件
  (`issuer ∈ participating`) と同じ条件でグレイアウトする

### 並び

**DID 順に並べる。**`Set` / `Map` の反復順に任せると、読み直すたびに表の行が入れ替わりうる。

## 表示名 (step2, 2026-09-04 追加)

**記録は DID、画面はハンドル名**である (`deepse/requirements/spec/participation.md` の図)。
名前を引くのはネットワークを伴うので、`rosterView` 自身は引かない — 引いた結果の
同期の関数 (`labelOf`) を受け取るだけである。これは `foldParticipation` が
`isLocalDid` を受け取るのと同じ形で、理由も同じ (**非同期を持ち込むと決定論が壊れる**)。

- **`rosterDids` は名簿からではなく行から集める。**名簿から集め直すと、行を組む条件と
  食い違ったときに「表には出ているのに名前が引かれていない」DID が生まれる。
  行に出る DID と引く DID が同じものであることを、両方向 (集める / 集めない) で見る
- **`sortRowsByLabel` は DID 順とは違う順序を作る。**テストでは A の DID を最小に、
  ハンドル名を `zoe.test` (最大) にしてあるので、**並べ替えが名前で行われていなければ
  この 2 つは区別できない**
- **名前が引けなかった行は DID の文字列として並ぶ。**順序が乱れることより、
  「引けるまで順序が決まらない」状態を作らないことを採る。`rosterRows` が DID 順で
  返すのはそのためである
