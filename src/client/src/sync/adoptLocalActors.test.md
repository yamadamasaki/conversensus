# adoptLocalActors.test.ts — 未ログインの編集を出し直す手順のテスト仕様

## 何を

`adoptLocalActors` (ログインしたときに、未ログインの batch を訊いてから自分の batch に付け替え、送る) の
手順を、保存と送信を偽物にして検証する (FPR 前 L-1)。付け替えそのものの正しさ (projection が変わらない・
連番が崩れない) は `eventStore.test.ts` で見ている。

## なぜ

未ログイン (オフラインで起動してログアウト扱いになった間も含む) の編集は、そのままでは誰にも届かない。
ログインしたら自分の編集として出し直す。ただし**同じブラウザを別の人が使っていたかもしれない**ので、
出し直す前に訊く (設計 Q1)。

## どのように

- 未ログインの batch が無ければ、**訊かない** (ログインのたびに空の問いを出さない)
- 件数と File と**最後の編集の時刻** (File をまたいだ最後, #288) を見せて訊き、**断られたら何も書き換えず送らない** (手元に残り、次のログインでまた訊く)
- 承けたら、**`local` の actor ごとに新しい自分の actor** (`<did>#<新しい id>`) へ付け替える。同じ端末の
  `<did>#<deviceId>` は連番がぶつかるので使わない (設計 F5)。関わった File ごとに catch-up で送る
- **送れなくても例外にしない** — 付け替えは済んでいて、次の同期 (起動時・online・今すぐ同期) が送る

## この端末だけの File (#253)

「送らない」と答えたら、その File を**丸ごとこの端末に留める**。以前は編集だけを留め、File の起源
(名前・最初の Sheet) はログインで送られ、ログインした後の編集も送られた。

- 断ったら、訊いた File に `declined` の印を付ける (branch も)
- 前に「この端末に残す」と答えた File は訊き直さない (後から File の詳細で保存できる)
- 未ログインで作っただけの File (編集が無い) も訊く。作っただけでも名前と最初の Sheet がある
- branch の編集は元の File として訊き、承けたら branch も送る

印は本物の `localOnlyFiles` を、`Map` で作った保存領域の上で使う。
