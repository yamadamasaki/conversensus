# liveChannel.test.ts — 参加者の PDS の流れのテスト仕様

## 何を

`LiveChannel` (PDS の firehose に繋ぎ、File への書き込みの合図を配る) を検証する (#252)。
WebSocket と「繋いでよいか」(画面を見ていて回線がある) は差し替え、知らせはテストが手で出す。

## なぜ

- 合図は**グラフの op-log と判断ログ (名簿)** の書き込みだけ。ほかの collection (Bluesky の投稿・Folder など)
  で取りに行けば、無駄な往復になる。同じ File への書き込みが 1 つの commit に並んでも、合図は 1 つでよい
- **繋がった・切れたときは「取りこぼしたかもしれない」(`fileId: null`) を出す。**繋がるまでの間の書き込みは
  流れに載らない。切れたときは、受信の側がポーリングの間隔を元に戻すきっかけになる
- 細いネットワークで無駄に受けない: **背後・オフラインでは切り**、戻ったら繋ぎ直す。繋ぎ直しは間隔を延ばし
  ながら試す (繋がらない PDS を叩き続けない)
- 止めた後に届いた「閉じた」知らせで繋ぎ直すと、閉じたタブが繋ぎ続ける

## どのように

- 繋ぐ URL が `wss://<PDS>/xrpc/com.atproto.sync.subscribeRepos` で、開いたら繋がった状態になり null の合図
- batch と judgment の path は File への合図 (1 つにまとまる)。`app.bsky.*` と Folder は合図にしない
- 繋がった後に切れたら null の合図。最初の間隔 (5ms) の後に繋ぎ直し、また切れたら倍の間隔で
- 繋がらないまま切れたら合図は出さない
- 背後に回ると切って null の合図、戻ると繋ぎ直す / 見ていない間に始めたら繋がず、見たときに繋ぐ
- 止めたら切り、その後の閉じた知らせでは繋ぎ直さない
