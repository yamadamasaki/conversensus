# FileSessionPool のテスト

## 何を

`FileSessionPool` — 開いている File のセッションの置き場 (step3 Phase 3 S3-3c)。持ち手
(前に出ている view・背後のタブ) が参照する File の集合を宣言し、置き場はそれに合わせて
セッションを作り・止める。File の発番器はセッションより長く持つ。

## なぜ

壊れ方が 2 つあり、どちらも画面からは見えない。

- **同じ File のセッションが 2 つ走る。**同期が 2 本になり、outbox が割れ、同じ点を 2 回発番する。
  あるいは**閉じたタブの File が同期を続ける** (止め忘れ)。足し引きの参照数だと、React の
  StrictMode が effect を 2 度走らせるだけで数がずれる。だから置き場は「持ち手ごとの集合の宣言」で
  数える。その規則が本当に効いているかを見る
- **発番器がセッションと一緒に作り直される。**ログインで remote キューが付くとセッションは
  作り直されるが、発番器まで新しくすると同じ点を 2 回振る

「あらゆる宣言の列で成り立つ」主張なので性質として書く。

## どのように

セッションは start / stop の回数を数える偽物にする。置き場が見るのは `start` (契機を張り、
止める関数を返す) だけなので、本物の `FileSession` は要らない。

### 生成器

- File は 3 つ、持ち手は 2 人 (前・背後)。**小さなプール**にするのは、2 人が同じ File を持つ
  (セッションを共有すべき) 場面と、片方だけが離す場面に当たるため
- 1 手は「持ち手がこの集合を持つ」か「持ち手が離す」

### 性質

| 性質 | 固定すること |
| --- | --- |
| 止まった後に生きているのは、誰かが持っている File のセッションちょうど 1 つずつ | 止め忘れ・作りすぎ・同じ File の重複が無い |
| 同じ File の発番器は、セッションを作り直しても常に同じもの | 毎手の後に止めを走らせ、作り直しを起こしながら見る |

### 例

- 前と背後が同じ File を持つとセッションは 1 つ
- **離してすぐ持ち直すと作り直さない** (StrictMode・タブの切り替え)。止めを 1 拍遅らせる理由そのもの
- 前と背後で File が入れ替わっても作り直さない (タブの切り替えで起きる)
- 誰も持たなくなった File は 1 拍遅れて止まる
- 作り方を差し替える (ログイン) と生きているセッションを作り直し、発番器は引き継ぐ
- 作り方がまだ無いうちは作らず、渡された後の宣言で作る
