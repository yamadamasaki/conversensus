# ownJudgmentPoint のテスト

## 何をテストするか

この端末が最後に書いた判断の点を File ごとに手元に覚え、読み戻すこと (#261 の窓 1)。

- 覚えた点を File ごとに読み戻す
- 別の actor の点は下限にしない (seq は actor ごとの連番で、actor はログインで変わる)
- 前に覚えた点より小さければ覚え直さない
- 壊れた値・保存領域が無いときは無いものとし、書けなくても例外にしない
- 読み戻した点を下限にした発番器は、その点の後から振る

## なぜテストするか

判断ログは PDS にだけあり、ローカル正典に載らない。File を開くと発番器はローカルの op-log から
復元されるが、判断ログを知るのは**開いてから最初の受信サイクル**である。その間に編集すると、
自分が前に書いた判断と同じ点 `(actor, seq)` を振る。相手はその判断を知っただけで「その編集を
見た」ことになり、並行の書き換えが競合ではなく上書きに分類される (step3 Phase 5 S5-3 で残った窓)。

最後の例が要点である — 覚えた点を読み戻した発番器が、その点を飛び越えて振ること。

## どのようにテストするか

保存領域は `Map` で作った `Storage` を渡す (localStorage を汚さない)。発番器は本物の
`CausalClock` を使う。
