# rosterSource テスト仕様 (step2 Phase 2 S1)

対象: `rosterSource.ts` — File 単位の名簿の供給元。
設計: [step2 Phase 2](../../../../deepse/plans/step2-phase2-sync.md) §2。

## 何をテストするか

**名簿の「読み方」がここ 1 つに閉じていること**である。中身 (誰が参加しているか) は
`readRoster` と `foldParticipation` の担当で、ここは扱わない。したがって名簿の値は
「読めたことが分かる」最小の形にしてあり、代わりに**何回・どの引数で読んだか**と
**同時に来た読みをどう畳んだか**を見る。

## なぜこの形なのか

### 読み方が 2 箇所に分かれてはならない

Phase 1 では名簿を読むのはダイアログだけだったので、読み方 (起点は自分・起点が無ければ
置いて読み直す) は `useParticipation` の中にあった。**Phase 2 は同期サイクルごとに名簿を
要る** — 「読む順序は名簿 → グラフに固定される」(アーキテクチャ §2) ため、グラフを
取りに行く前に必ず名簿を通る。

分かれたままにすると、**片方だけが起点を修復する**状態が生まれる。起点の無い File では
依頼が 1 件残らず `issuerNotParticipating` で捨てられ、しかも捨てられた依頼は行を持たない
ので画面にも出ない (Phase 1 で実機発覚)。同期サイクルしか触らない File — ダイアログを
一度も開いていない File — でも修復が要る。

そこで「起点を自分にする」「起点を置いたら読み直す」「置く判断にはいま読んだ判断ログを
渡す」の 3 つを、この層の契約として固定する。

### TTL を持たないので、代わりに畳み方を固定する

「N 秒は読み直さない」形にしなかったのは、TTL が**「相手の参加が見えるまでの遅れ」を
根拠の無い定数で決めてしまう**からである。その遅れを決めるのは同期の間隔 (S4) であって、
その内側にもう 1 つ時定数を置かない。

代わりに**同時に走った読みだけを畳む**。同期サイクルの最中にダイアログが開く場面は普通に
起きるが、そこで名簿を 2 回読む理由は無い (1 回の読みが参加者数分のリクエストである)。

### ⚠️ 書き込みの直後は畳んではならない

畳み込みには 1 つだけ穴がある。**判断ログを書いた直後に、書く前から走っていた読みへ
相乗りすると、書く前の名簿が返る。**ダイアログは「依頼したのに表に出ない」を見ることに
なる。`readFresh` はそのための口で、進行中の読みを無視して新しく読む。

これは `read` / `readFresh` の呼び分けという形で**呼び出し側に判断を残す**設計である。
供給元の側で「書き込みがあったか」を知る術は無い。

## テストケース

### 読み方

| ケース | 何を固定するか |
|---|---|
| 起点を自分にして読む | 不動点計算の起点。既に参加している File を見る場合の既定 (まだ参加していない File は参加コードが指す依頼者を起点にするが、それはこの層ではなく `previewCode` の担当) |
| 起点を置いたら読み直す | 置く前の名簿は依頼を全部捨てている。**置いた後の読みが本番**である |
| 置く判断にはいま読んだ判断ログを渡す | ここで読み直すと、その間に増えた分とずれる |
| 起点を置かなければ 1 回しか読まない | 修復が不要なときに往復を倍にしない |
| 読めなければ投げる | **名簿が読めないことと名簿が空であることは違う**。握り潰すと「相手が参加者にならない」が理由不明のまま残る |

### 同時に走った読みを畳む

| ケース | 何を固定するか |
|---|---|
| 進行中の読みがあれば相乗りする | 同期サイクルとダイアログが重なる場面。**同じ結果オブジェクトを共有する**ことまで見る |
| File が違えば畳まない | 畳む単位は File である |
| 前の読みが終わっていれば新しく読む | TTL を持たない = 毎回読む、を固定する |
| 失敗した読みを残さない | 残すと次の呼び出しが同じ失敗を受け取り続け、再試行できないキャッシュになる |

### `readFresh` (書き込みの直後)

| ケース | 何を固定するか |
|---|---|
| 進行中の読みに相乗りしない | 本命。相乗りすると書く前の名簿が返る |
| `readFresh` の後の `read` は新しい方に相乗りする | 新しい読みが登録されること (古い方に戻らない) |
| 古い読みが後から終わっても新しい読みを取り下げない | `finally` が無条件に登録を消すと、遅れて終わった古い読みが新しい読みの登録を消し、以後の `read` が毎回新規になる |

## テストしていないこと

- **名簿の中身** — `readRoster.test.ts` / `participation.test.ts` の担当である。
- **実 PDS の応答** — この層は `loadRoster` を注入で受けるので、PDS を知らない。
