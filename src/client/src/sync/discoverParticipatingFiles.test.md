# discoverParticipatingFiles テスト仕様 (step2 Phase 2 S3)

対象: `discoverParticipatingFiles.ts` — 参加を承認した File を手元に立ち上げる。
設計: [step2 Phase 2](../../../../deepse/plans/step2-phase2-sync.md) §1 事実 B /
スパイク: [u6-p1-report](../../../../deepse/spikes/u6-p1-report.md)。

## 何をテストするか

**列挙の入口が自分の repo であること**と、**書く前に 2 つの検査を通ること**である。

承認しただけでは手元に File は無い。判断ログには承認が載るが、グラフの batch は 1 件も
自分の repo に無いからである。`discoverRemoteFiles` (自分の repo のグラフ op-log から
未知 File を拾う) はこの File を見つけられない。

## なぜこの形なのか

### ⚠️ 他 actor の repo を列挙してはならない (U6-P1)

素朴な実装は「参加者の repo に `listFileHeads` を回す」だが、これは**その actor の File が
全部見える** (スパイクで実測 23 個)。`discoverRemoteFiles` は未知の fileId を新しい File
として materialize するので、そのまま繋ぐと**相手の無関係な File が自分のサイドバーに並ぶ**。

計画はこれを「発見の対象を名簿で絞る」と書いていたが、**絞る前にそもそも他人の repo を
列挙する必要が無い**。自分が関わる File には自分の repo に必ず判断ログがある
(`genesis` / `accept` / `invite` のどれか)。判断ログの rkey は `batches` と同じスキーム
なので、自分の repo の `listJudgmentFileIds()` が候補の集合を返す。

テストが `listJudgmentFileIds` を唯一の入口として組んでいるのはこの構造を固定するためで
ある。**他 actor の repo を列挙する口をこのモジュールが持たない**ことが、宿題の答えである。

### 名簿は絞り込みであると同時に「読む順序」である

判断ログには「依頼されたが承認していない」File も「離脱した」File も載る。いま自分が
参加者である File だけを立ち上げる。

「参加者でないなら**グラフを読みに行かない**」ことまで見ているのは、これが節約ではなく
意味論だからである — 参加期間が 1 つも開いていないので、読んでも `participationFilter` が
全部落とす。読みに行くのは無駄な往復であると同時に、「読む順序は名簿 → グラフ」の
順序が壊れている印になる。

### ⚠️ 削除は書く前に見る

`discoverRemoteFiles` は削除を 2 段で弾く — 列挙の着地レコードが tombstone なら本体を
引かず、引いた op-log に `file.remove` があれば書かない。**ここには前者の安い枝が無い**
(列挙が判断ログなので、グラフの着地レコードを持たない)。したがって「引いてから、書く前に
見る」の 1 段だけになる。

**書いてから消す形は取れない。**ローカル正典から File を取り除く口は無く、削除は
tombstone でしか表せないので、「削除済みの File を作ってから削除し直す」ことになる。
これが `collectParticipantBatches` (集めるだけで書かない) を切り出した理由である。

### 1 件も集まらなければ File を作らない

名簿には載っているが相手の repo が読めない・空だった場合である。空の File を作ると、
サイドバーに中身の無い File が並び、次のサイクルで中身が入るのか壊れているのかを
利用者が区別できない。

## テストケース

### 列挙の入口

| ケース | 何を固定するか |
|---|---|
| 自分の判断ログにあって手元に無い File を立ち上げる | 本体。集めた batch がそのまま受信追記に渡る |
| 既知の File は触らない | **名簿すら読まない** — 既知の File に発見の仕事は無い |
| 2 回目は何もしない | べき等。1 回目で materialize されたので既知集合に入る |

### 名簿で確かめてからグラフを読む

| ケース | 何を固定するか |
|---|---|
| いま参加者でない File は立ち上げない | 依頼されただけ / 離脱済。**グラフを読みに行かない** |
| 名簿が読めなければ理由とともに返し、他の File は続ける | 相手の PDS が応答しないことは正常に起こる。1 件の失敗で残りの発見を止めない |

### 書く前の検査

| ケース | 何を固定するか |
|---|---|
| 相手が消した File は materialize しない | remove-wins。**1 件も書かない** |
| 1 件も集まらなければ File を作らない | 中身の無い File をサイドバーに並べない |
