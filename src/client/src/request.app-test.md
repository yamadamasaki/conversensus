# request.app-test.tsx — 依頼の区画の App 結合の仕様

## 何を

App を丸ごと描き、「依頼・相談」の種を入れた Sheet で依頼 node を作り、右の欄の「依頼」の区画で
送る・答える・閉じる・開き直す・送り直すを行う (agent 段 4 R4、1 台の端末)。あわせて、2 人の間で
依頼が届き、答えが返る (R5)。

## なぜ

状態は 3 か所に出る — 区画の状態の行、node の上の印 (`RequestBadge`、React Flow の edge の store から
答えの有無を読む)、正典の op-log。**3 つが同じ操作で揃って動く**ことは、部品ごとのテストでは見えない。
実際に、答えると node と edge をまとめて足す event (`NODES_PASTED`) が貼り付けと同じく選択を外し、
区画が消える食い違いがここで見つかった (依頼を選んだままにして直した)。

## どのように

- 依頼の種類で node を作ると、作った時から応答を求める node (下書き、宛先は指定なし)
- 送る → 送った・未回答 (1 回目)。node の印も `sent`
- 答えを書いて答える → node が 2 つになり、回答あり。正典では依頼から答えへの edge に label「答え」と
  `answers` = 1 が載る
- 閉じる → 閉じた (答えるのボタンが消える)。開き直す → 回答ありに戻る
- 送り直すと、前の答えでは回答ありにならない (2 回目、node の印も `sent`)
- 右サイドバーは既定で畳まれているので広げてから操作する。画面を何度も往復するので、テストの上限を
  bun の既定 (5 秒) より長くする
- **2 人 (R5)**: alice が File を作って bob を招き、bob が参加する → alice が依頼を作り、宛先に bob を名簿から
  選んで送る → bob が同期すると右下に「alice.test から依頼が届きました」が出る → 「開く」で依頼が選ばれ
  (区画に未回答が出る)、通知は既読で消える → bob が答えて送る → alice が同期すると node の印が回答あり。
  alice には通知は出ない (自分が送ったもの)
