# SettingsPopup.test.tsx — テスト仕様

## 何をテストするか

`SettingsPopup.tsx` コンポーネント。
ファイル/シートの名前・概要編集、削除、閉じる操作を提供するポップアップ UI。

## なぜテストするか

- ファイル/シート管理の基本 UI であり、名前の空入力防止・IME 対応など細かい UX 要件がある
- onSave/onDelete/onClose のコールバック呼び出し条件が複数ある
- キーボード操作（Enter/Escape）の挙動が仕様通りであることを保証する必要がある

## どのようにテストするか

| カテゴリ | テスト内容 |
|---------|-----------|
| 初期表示 | name/description の props が input に反映される |
| 保存操作 | 保存ボタンで onSave + onClose 呼ばれる。名前変更反映。空文字フォールバック |
| キーボード | Enter で保存。IME 変換中は抑制。IME 確定後は保存。Escape で保存せずに onClose |
| 削除 | 削除ボタンで onDelete |
| 外部クリック | ポップアップ外クリックで**保存せずに** onClose。内部クリックでは何も起きない |

## 確定と破棄を 2 対 2 にする (ANA-126)

以前は**保存する経路が 3 つ** (保存ボタン・名前欄の Enter・ポップアップ外クリック)、
**破棄する経路が 1 つ** (Escape) だった。この非対称が「保存ボタンは何のためにあるのか」を
分からなくしていた原因である — ボタンは「保存する唯一の手段」ではなく、単に明示的な
確定の口でしかなかった (設計 `step1-refinement-ana118-file-deletion.md` D4)。

外クリックを**破棄**に変え、確定 = ボタン / Enter、破棄 = 外クリック / Escape の
2 対 2 に整理した。ボタンは残す — 消すとポップアップが未完成に見えるし、明示的な
確定の口は必要である。

`deepse/requirements/operation-manual-for-dev.md` のファイル管理の節は**元から
「ダイアログ外をクリックすると保存せずに閉じる」と書かれていた**。つまりこれは仕様変更
ではなく、実装が仕様からずれていたのを直したものである。テストは旧挙動 (外クリックで
onSave) を固定していたので、それも書き換えた。

内部クリックのテストを足したのは、外クリックが破棄になったことで**閉じてはいけない
場面で閉じる回帰の代償が大きくなった**ため (以前は最悪でも保存されていた)。
