# alignToPane のテスト

## 何を

`alignToPane(result, pane, ids)` — merger の「取り込む」(step3 Phase 5 S5-1c, Q9)。merge 元・先の pane で選んだ
要素ごとに、merge 後の姿をその pane の姿に揃える event の列を作る。merge 後の canvas の dispatch を通すので
undo できる。

## なぜ

取り込みは「この pane の姿を採る」という利用者の判断をそのまま形にする操作である。**揃えたつもりが揃って
いない** (本文だけ揃って名前が古い、端の node が無くて edge が入らない) と、利用者は merge 後をもう一度見比べる
まで気づかない。逆に**選んでいない要素まで動かす**と、それまでの解決の編集を壊す。

どちらも「あらゆる姿と選び方で成り立つ」主張なので性質として書く。

## どのように

### 生成器

- node 3 つ・edge 2 本 (端は固定: e1 = n1→n2、e2 = n2→n3) の**小さなプール**。merge 後と pane のそれぞれで、
  node は在るか無いか・本文 (a / b)・名前 (無し / 主張)・プロパティの有無・位置 (x = 0 / 100) を引く。edge は在るか
  無いか・名前を引き、端の node が在るときだけ置く
- 姿は op-log で組んで projection する (画面と同じ形のシートにするため)。揃えた後も、event を batch にして後ろに
  積み、projection し直して比べる (畳み込みを通した結果で見る)

### 性質

| 性質 | 固定すること |
| --- | --- |
| 揃えた後、選んだ要素は pane の姿と同じ (在否・本文・名前・プロパティ・位置)。pane に在る edge は端の node ごと取り込まれて在る | 取り込みが揃え漏れない (Q9)。端の node を連れてくる |
| 選ばなかった node は変わらない | 取り込みは選んだ要素だけ (node を消すときに繋がる edge は消えるが、他の node は動かない) |

### 例

- 同じなら何も出さない (余計な undo の段を積まない)

## 変異で確かめたこと

- 本文を揃えない → 1 つ目の性質が落ちる
- edge を取り込むときに端の node を連れてこない → 1 つ目の性質が落ちる
