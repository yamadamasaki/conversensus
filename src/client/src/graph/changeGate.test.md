# changeGate.test.ts — canvas の変化の門

## 何を

`createChangeGate` / `contentOf` が、canvas の変化のうち**グラフの中身 (op に落ちる値) が変わったもの
だけ**を通すこと。

## なぜ

`GraphEditor` は nodes/edges が変わるたびに親 (`onChange`) へ知らせる。ところが React Flow の
nodes/edges は、中身の編集以外 (寸法の計測・選択・差分の色) でも変わる。以前はそれを
**時刻 (再 seed 後 150ms) と回数 (色を塗った次の 1 回)** で捨てていたので、利用者の編集が
その窓に入ると一緒に捨てられた。step2 T7-7 の未修正の不具合 (branch で置いたノードが
「(N 変更)」に数えられず、コミットできない) の原因である。

門は**中身で**見分ける。見分けを誤る向きは 2 つある。

| 誤り | 起きること |
| --- | --- |
| 中身が変わったのに通さない | 編集が親に届かない (T7-7 の型)。**致命的** |
| 中身が同じなのに通す | 親が同じ中身で更新される。無害だが、再描画が増える |

## どのように

### 性質

1. **あらゆる nodes について、計測・選択・差分の色だけが変わった canvas は通さない。**
   React Flow が実際に書き換える値 (`measured` / `selected` / `data.diffType`) を任意に変える
2. **あらゆる 2 つの nodes について、通すのは中身が違うときだけで、同じ変化は 2 度通さない。**
   「違う」の判定には `contentOf` の射影そのものを使う — この性質が固定するのは
   「門が射影の同一性に忠実であること」と「通した中身が次の基準になること」である

生成器の判断:

- id は 3 つ、座標は 3 値、content は 3 値の**小さなプール**から引く。広い生成器だと
  2 つの nodes がほぼ必ず違い、性質 2 の「同じなら通さない」側に当たらない
- `uniqueArray` で id の重複を除く。canvas に同じ id のノードは並ばない
- 計測の値は広くてよい (どの値でも通さないことを言いたいので)

**性質 1 が言えるのは `fromFlowNodes` が見た目の値を読まないからである。**将来 `fromFlowNodes` が
`measured` を読むように変わると、この性質が落ちて知らせてくれる。

### 例

| テスト | 固定すること |
| --- | --- |
| seed 直後に置いたノードは通す | **時間で見分けない**こと。T7-7 の回帰 |
| ゴーストの出入りは通さない | ゴーストは保存対象ではない (削除予定の表示) |
| edge の色は通さず、端点の変更は通す | edge 側も同じ規則であること |
| seed し直すと新しい基準になる | 受信による再 seed の後、置き直した中身を変化として通さない |

## App 結合での対応

`App.app-test.tsx` の「branch を開いた直後に置いたノードも、変更として数えられる」が同じ不具合を
画面の側から見ている (再 seed 後 150ms の窓を戻す変異で落ちることを確認)。
