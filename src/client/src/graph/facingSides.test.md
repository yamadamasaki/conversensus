# facingSides のテスト

## 何をテストするか

端の接続点を持たない edge の端を決める `facingAnchors`・`withFacingHandles` (#256・#410)。

- 例: 真横の node へは右辺の真ん中から左辺の真ん中へ、真上の node へは上辺から下辺へ。
  横に並んだ 2 つの node の edge が上辺を回らないこと (Toulmin の上の段で起きた形)。
  斜めの node へは、中心線の交点 = 辺の真ん中からずれた所 (#410)
- 性質: どんな 2 つの矩形でも、端はそれぞれの node の枠の上にあり、かつ **2 つの中心を結ぶ線の上**にある (#410)
- 性質: 辺の上の位置は 0〜1 で、いちばん近い接続点の番号は 1〜`SLOTS`
- 並べた接続点の id: 真ん中は今までの id (`source-top` など。保存済みの端は変わらない)、両側は番号付き

- `withFacingHandles` (例): 両端とも接続点を持たない edge に、交点にいちばん近い接続点を当てる。
  **同じ辺を向く edge でも、相手の方向が違えば別の接続点に散らばる** (#410。以前は辺の真ん中に集まって重なり、
  一番上しか選べなかった)。並べた接続点を持たない node は辺の真ん中を使う。人が選んだ端 (片方だけでも)・
  まだ測られていない node・辺に接続点を持たない node (group) は、同じオブジェクトのまま返す

## なぜテストするか

node の接続点は 4 辺にあるが、接続点を持たない edge は React Flow が最初の接続点 (上辺) を
両端に使う。template graph の種から作った edge は接続点を持たないので、横に並んだ node の
edge が上辺の外を回り、label が重なって読めなかった (#256)。

**端は接続点として React Flow に渡す** (`withFacingHandles`)。以前は edge の部品の中で線の端だけを
ずらしていたが、付け替えのつかみ所は React Flow が最初の接続点 (上辺) に描くので、線の端とつかみ所が
ずれ、種から作った Toulmin の edge を付け替えられなかった (template-update 段 2 の実機の確認 W7)。
接続点として渡せば、線もつかみ所も同じ所に描かれる。渡すのは表示だけで、保存はしない。
人が選んだ端を変えない・group のように辺に接続点の無い node には当てない、を例で固定する。

**#410 で、端を「向かい合う辺の中点」から「中心線と枠の交点にいちばん近い接続点」に変えた**。各辺に接続点を
`SLOTS` (5) か所並べ (`SlotHandles`、見えず押せない)、交点にいちばん近いものを使う。交点そのものに線の端を置くと、
付け替えのつかみ所 (React Flow が接続点の位置に描く) とずれて W7 に戻るためである。両端の辺は向かい合うとは
限らない (横長と縦長の node が斜めに並ぶときなど) ので、「向かい合う」の性質は「中心線の上」に置き換えた。

「枠の上にある」「中心線の上にある」は、**あらゆる配置で**成り立ってほしい命題なので性質で書く。
例だけでは、node の大きさが違うときや斜めに離れているときを引けない。

## どのようにテストするか

- 生成器: 位置は ±2000、大きさは 20〜400 の整数の矩形。node の大きさが揃わない場合と、
  重なっている場合 (中心が近い) も引けるように、位置と大きさを独立に引く
- 中心が重なる配置は除く (線が決まらない)
- 交点は小数で求まるので、枠の上・線の上は小さな誤差を許して比べる
