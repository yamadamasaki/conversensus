# coords.test.ts — テスト仕様

## 何をテストするか

`src/client/src/graph/coords.ts` の座標変換関数群。

| 関数 | 責務 |
|---|---|
| `absolutePositionOf` | 祖先チェーンを畳んで絶対座標を求める |
| `toParentRelative` | 絶対座標を指定した親から見た相対座標へ変換する |
| `depthOf` | 入れ子の深さ (トップレベル = 0) |
| `isAncestorOf` | 祖先関係の判定 |
| `groupBoundsOf` | グループの絶対座標での境界 |
| `pointInGroup` | 絶対座標の点がグループ内にあるか |
| `nodeSizeOf` | ノードの表示サイズ (measured → style → 既定値) |
| `absoluteCenterOf` | ノードの絶対座標での中心点 |
| `absoluteBoundingBoxOf` | ノード群を絶対座標で囲む外接矩形 |

## なぜテストするか

このモジュールは ANA-107 (グループ化の問題点) の修正設計
`deepse/plans/step1-refinement-ana107-grouping.md` §4 D4 に基づいて新設された。
それまで絶対座標⇄相対座標の変換は `GraphEditor` / `useGroupNodes` /
`graphTransform` に**別実装で散在**しており、1 箇所を直しても他が同じ前提を
共有していないため別の症状として再発していた。集約した以上、ここが唯一の
正しさの基準になるので厚くテストする。

特に重要なのは次の 3 点である。

- **`positionAbsolute` に依存しないこと。** React Flow の `positionAbsolute` は
  非同期に更新されるためドラッグ中は stale でありうる。旧実装
  (`GraphEditor.getAbsPos`) はこれを使ったうえで「親を 1 段だけ」補正しており、
  2 段以上の入れ子で絶対座標が誤っていた (ANA-108)。stale な
  `positionAbsolute` を持つノードで結果が変わらないことを固定する。
- **3 段以上の入れ子で正しいこと。** 旧実装が壊れていたのがまさにこの条件である。
- **停止すること。** 親子関係が循環したデータ (破損時に起こりうる) で
  無限ループしないことを保証する。`MAX_ANCESTOR_HOPS` による打ち切りの回帰テスト。

## どのようにテストするか

### 隔離

外部依存なし。`bun:test` のみ使用。React Flow の `Node` は型としてのみ使い、
ランタイムには持ち込まない。

### 共通の題材

`outer(100,100) > middle(50,50) > inner(10,10)` の 3 段の入れ子を共有の題材にする。
段ごとの絶対座標は `outer`=(100,100)、`middle`=(150,150)、`inner`=(160,160) となり、
「どの段で計算を打ち切っても値が違う」ため一段補正のような誤りを確実に検出できる。

### ヘルパ

`node(id, position, parentId?, extra?)` で React Flow の `Node` を組み立てる。
`data` は空オブジェクト固定。`measured` / `style` / `positionAbsolute` は
`extra` で個別に与える。

### 観点ごとの意図

- **`ancestorsOf`**: 祖先チェーンを辿る唯一の場所。`absolutePositionOf` /
  `depthOf` / `isAncestorOf` はいずれもこの関数の上に載っている (S3 で 4 つあった
  同型のループを 1 つに寄せた)。打ち切り条件 — 親が見つからない / 循環 — も
  ここだけで守ればよくなるので、その 2 件をここで固定する。
- **`absolutePositionOf`**: トップレベル / 1 段 / 3 段 / stale な `positionAbsolute` /
  孤児 (親が存在しない) / 循環。孤児のケースは「相対座標をそのまま返す」ことを
  仕様として固定している — React Flow が親不在の子をそう扱うため、それに合わせる。
  なお孤児が生まれること自体は ANA-111 / ANA-112 の原因であり、S3 で
  「孤児を作らない」不変条件として `applyEvent` 側で塞ぐ。
- **`toParentRelative`**: 親なし / 入れ子の親 / 存在しない親に加えて、
  **`absolutePositionOf` の逆変換になっている**ことを往復で確認する。
  この 2 つがずれると、グループへの出し入れでノードが飛ぶ。
- **`groupBoundsOf`**: `measured` と `style` の大きい方を採る挙動は、
  `recalculateParentBounds` が `style` を更新した直後に DOM の再測定が
  追いつかないケースへの対処であり、旧実装から引き継いだ仕様。
  フォールバック値 (300×200) も旧実装と同じ値を保つ。
- **`pointInGroup`**: 境界上を `true` に含めること (旧実装と同じ `>=` / `<=`)、
  `buffer` が外側に広がること、そして**入れ子のグループを絶対座標で判定すること**。
  最後の 1 件は、相対座標のまま判定していたら通らないよう題材を選んである。
- **`nodeSizeOf`**: `measured` → `style` → `DEFAULT_NODE_STYLE` の優先順位。
- **`absoluteCenterOf`**: 絶対座標とサイズの合成。ドロップ先の判定はノードの
  中心点で行うため、ここがずれると入れ先が変わる。
- **`absoluteBoundingBoxOf`**: グループ化するときに新しいグループの矩形を決める
  計算である。**親が異なるノード同士を選択したケース**を必ず含める — 旧実装
  (`useGroupNodes`) は `node.position` (親からの相対座標) をそのまま比較しており、
  選択ノードの親が揃っていないと異なる座標系を混ぜて矩形が破綻していた。
  題材の `child` は group の子 (相対 40,40 / 絶対 140,140)、`outside` は
  トップレベル (10,10)。相対座標のまま比較すると `maxX` / `maxY` が
  200 ではなく 100 になるため、混在の再発を確実に検出できる。
  空配列で `undefined` を返すのは、呼び出し側 (`groupSelectedNodes`) が
  選択ゼロ件で早期 return できるようにするため。
- **`descendantIdsOf`**: `isAncestorOf` を全ノードに当てただけの薄い関数なので、
  「自身を含めない」ことと「孫まで辿る」ことだけを固定する。
  これは `resolveDropTarget` の循環防止に使う集合である。
- **`innermostGroupAt`**: ANA-109 の中核。**外側のグループが配列上で内側より
  先に来る** 題材 (`nestedGroups`) を使う — React Flow は「親は配列上で子より前」を
  要求するので、旧実装の `.find()` (配列順の最初の一致) では入れ子で必ず外側が
  勝っていた。同じ題材を `reverse()` した配列でも結果が変わらないことを併せて
  確認し、**配列順に依存しない**ことを仕様として固定する。
  同深度の重なりでは面積が小さい方を選ぶ (こちらも順序を入れ替えた 2 通りで確認)。
  グループ以外のノードが候補にならないこと、`excludeIds` が効くことも押さえる。
- **`resolveDropTarget`**: `onNodeDrag` (ハイライト) と `onNodeDragStop` (確定) が
  共用する関数なので、**両者のずれ**を防ぐことが目的である。観点は 5 つ。
  - 入れ子のグループ上にドロップしたら内側を返す (ANA-109 の受入基準)
  - `nodes` 内の自分自身が stale でも、**引数で渡された `node` の位置**で判定する。
    ドラッグ中は `getNodes()` の同じノードが古い位置を持ちうるため、この性質が
    崩れるとハイライトが 1 フレーム遅れる / ドロップ先がずれる。
  - 親を少しはみ出しただけなら親に留まる (ノード幅・高さの半分をバッファに使う
    ヒステリシス。旧 `onNodeDragStop` から引き継いだ仕様)
  - 親をほぼ完全に出たら離脱する
  - 自分自身と自分の子孫は候補にならない。子が親をほぼ覆う配置を題材にして、
    親の中心が子の内側に入る状況を作っている。ここを塞がないとグループを
    自分の子グループへドロップでき、親子関係が循環する。

  なお「どのグループにも入っていないときだけ親のバッファを見る」順序が重要である。
  逆順 (旧実装) だと、外側グループの中で内側グループへドラッグしても
  外側のバッファ判定が先に成立してしまい、内側に入れない。
