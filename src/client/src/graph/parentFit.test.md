# parentFit のテスト

## 何をテストするか

`withParentFit` は、node を動かす・親を変える・大きさを変える操作の event に、親 group を中身に
合わせて広げた分 (`fitted`) を載せる (#250 無限キャンバス)。

- 枠の中で動かしただけなら何も載せない (同じ event を返す)
- 右下へはみ出したら group の大きさだけを広げる
- 左・上へはみ出したら group が左上へ動き、兄弟と動かした node 自身の相対座標がずれる。動かした node の
  `from` は**操作の前**の位置にする。ずれるだけの node には大きさを付けない
- 入れ子: 内側の group が広がって外側からはみ出せば、外側も広げる
- 親を変えて入れたとき (`NODE_REPARENTED`) と、大きさを変えたとき (`NODE_RESIZED`) も載せる
- 広げた分は、元の操作と同じ batch の `node.setLayout` になる (`toUnified`)
- 既に載っている event (undo / redo) には重ねて載せない

## なぜテストするか

以前は親を広げる処理 (`recalculateParentBounds`) が**画面の上でだけ**効いていた。op-log に残らないので、
再読み込みや他の端末では元の枠に戻り、中身がはみ出したままになった。group の中で動かしただけ
(`NODE_MOVED`) のときは、画面でも広がらなかった。

- `from` を「操作の前」にしないと、undo で操作そのもの (元の位置へ戻す) と食い違い、動かした node が
  ずれた位置に残る
- ずれるだけの node に大きさを書くと、中身に合わせて伸びる node の大きさが固定されてしまう

## どのようにテストするか

- 例: 上に挙げた振舞いを 1 つずつ。React Flow の node を手で組み、`applyEvent` で画面の姿を求める
- **性質**: group の 2 つの子のどちらを、どこへ動かしても次が成り立つ
  - 広げた後は、子がすべて枠 (余白と題名の帯を含む) に収まる
  - **op-log の姿は画面と同じ** — 元の姿に event の `node.setLayout` を当てたものが、画面の姿と一致する。
    これが以前の不具合そのもので、広げた分を載せない変異でこの性質が落ちることを確かめてある
  - undo (`invertEvent` を当てる) で元の姿に戻る
- 生成器: 座標は小さなプール (`-200, -30, 0, 40, 120, 250, 600`) から引く。枠の中・左/上へはみ出す・
  右/下へはみ出す、のすべてと、その組 (左へも下へも) に当てるため。広い生成器では組を引きにくい
