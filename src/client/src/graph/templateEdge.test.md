# templateEdge のテスト仕様

## 何を

edge を繋ぐときの 2 つの判断を見る。

- `edgeKindFor` — 両端の種別から **edge の種類を決める** (設計 D5)
- `canConnectByTemplate` — その接続を **許してよいか**

## なぜ

**種類はユーザが選ぶものではない。**仕様 (`spec/template semantics`) は「edge の種類は、
両端の nodes が決まれば自動的に決まり、ラベルはそれに対応するものになり、その後
変更することはできない」と定める。したがって UI に選択肢は出ず、**繋いだ瞬間に決まる**。

この 2 つを `GraphEditor` から出したのは、**判断が純関数だから**である。React Flow の
`onConnect` / `isValidConnection` の中に埋めると、ドラッグを合成しないと確かめられない —
そして合成ドラッグは実機の挙動を保証しない (過去の教訓)。

## どのように

### 種類を決める (`edgeKindFor`)

- **候補 1 なら種類を返す**: 返すのが `EdgeKindRef` (種類 + template) であること。
  種類を書き込むプロパティ名は template ごとに分かれるので、template を失えない。
- **向きが逆なら候補 0 — 何も返さない**: `from`/`to` が非対称であること。
- **片端が普通のノード / template が当たっていない**: 制約の対象外なので何もしない。
- **候補が複数なら何も返さない**: 選ばせる UI は step2 では作らない (設計 D5)。
  **`>= 1` と書くとここで落ちる** — 複数のときに先頭を勝手に当ててはいけない。
- **居ないノードを指しても落ちない**: 受信で消えた直後などに起こる。

### 許してよいか (`canConnectByTemplate`)

**この関数の主題は「候補 0」と「制約の対象外」を取り違えないことである。**どちらも
`edgeKindCandidates` は空を返すが、前者は許されない組で、後者は普通のノードが絡む
自由な接続である。

- **規則どおりの接続は許す / 許されない組は拒否する**: 警告ではなく繋がせない。
  旧設計 (D5) は「拒否しない」だったが、その理由 (端点の種別が空のとき判定できない) は
  仕様が toulmin node とその他を分けたことで消えた。
- **片端が普通のノードなら許す**: **取り違えの本命**。`isTemplateEdge` の判定を落とすと
  ここが落ちる (変異で確認済み)。ここを間違えると**普通のノードに繋げなくなる**。
- **template が当たっていなければ何でも許す / 居ないノードは許す**: 止める根拠が無い。

### 付け替えてよいか (`canReconnectByTemplate`)

仕様 (`template.md` の OnMutation) は template の edge について
**「edge の種類が変わらない範囲でのみ接続を変更できる」**と定める。

**禁じているのは付け替えではなく、種類が変わることである。**「支える先の主張を
付け替える」は普通に起こる編集なので、付け替え自体を塞ぐと使える操作まで失う。一方
種類が変わる付け替えを許すと、label は変更できないのに種類だけ変わり、
**ラベルが古いまま残る**。

`canConnectByTemplate` との違いは**元の edge を見る**ことである。React Flow の
`isValidConnection` は `Connection` しか渡さず、新規の接続か付け替えかを区別できないので、
`GraphEditor` が `onReconnectStart` で対象の edge を控えて渡す。

- **種類が変わらない付け替えは許す** (データA → 主張A を データA → 主張B に):
  主張が 2 つある node 集合 (`NODES2`) が要るのはこのためである。
- **種類が変わる付け替えは拒否する** (データ → 主張 を 論拠 → 主張 に): **種類の一致を
  見ずに「候補があれば許す」と書くとここで落ちる** (変異で確認)。
- **toulmin node 以外への付け替え / 許されない組への付け替えは拒否する**: 種類が
  無くなる、あるいは決まらない。
- **種類を持たない edge は今までどおり自由 / template が当たっていなければ何でも許す**:
  **当たっている template で種類を解決できなければ制約の対象外**とする。名前だけで
  見分ける `hasTemplateKind` で判定すると、相手の template を持たないせいで付け替えが
  塞がる (P3 の「知らない id は黙って落とす」と同じ判断)。解決できない種類も対象に
  すると、この 2 件が落ちる (変異で確認)。

## 対象外

- **ドラッグそのもの**は React Flow の仕事なので見ない。ここで見るのは、React Flow が
  訊いてきたときに返す答えである。繋がる / 繋がらない、付け替えられる / られないは
  実機で確認した (付け替えは Chromium で、op-log の `edge.reconnect` の増減で判定)。
