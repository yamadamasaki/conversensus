# deletion.test.ts — テスト仕様

## 何をテストするか

`deletionTargets(nodes, edges)` — delete キーで消えるノードとエッジの集合を決める
純関数。

## なぜテストするか

グループの delete は ANA-107 S3b で **「グループと中身をまとめて削除」** に仕様を
変更した (それ以前はグループ・ノードだけが消え、中身は親を失って画面上を飛んでいた
= ANA-111)。何が消えるかはユーザーから見て取り返しのつかない操作なので、
境界 (どこまで巻き込むか) をテストで固定する。

判断の根拠は 2 つ。

- copy (`collectCopyData`) が既にグループの子孫を再帰的に含んでいる。
  copy は子孫込み・delete は置き去り、という非対称は説明できない
- 「中身を残したい」はグループ解除してから削除で表現できる (S3a で解除が
  一級の操作になった)

## どのようにテストするか

題材は `group > child > grandchild` の 2 段の入れ子と、外側の `outsider`。
2 段にしてあるのは、直接の子だけを消す実装 (1 段しか辿らないバグ) を落とすため。

### 観点ごとの意図

- **選択なし**: 何も消えない。delete キーが常に何かを消してしまわないこと。
- **グループを選ぶと子孫もまとめて対象**: S3b の仕様変更そのもの。
- **子だけを選んだときは親を巻き込まない**: 巻き込みは下向き (子孫) だけで、
  上向き (祖先) には伝わらない。
- **消えるノードに繋がるエッジ**: 選択されていなくても消す。端点を失ったエッジを
  残さないため。`unrelated` (両端が生き残る) は消えないことも同時に見る。
- **選択されたエッジ**: 端点が生き残っていても消える (エッジ単体の削除)。
- **返す順序**: 引数の順序を保つ = 親が子より前。React Flow は配列上で親が子より
  前にあることを要求するので、undo (`NODES_RESTORED`) で復元したときに
  この並びが崩れないことが要る。

削除イベントの適用と undo は `events/applyEvent.test.ts` の
`NODES_DELETED / NODES_RESTORED` が、op-log 側 (`node.remove` の子孫カスケード) は
`shared/events/project.test.ts` が担当する。
