# TabBar のテスト

## 何をテストするか

タブ帯の溢れ方と、アクティブなタブの見分け (#277)。

- アクティブなタブだけが `aria-selected` を持ち、見た目の印 (`data-active`) を持つ。
  印の見た目 (白い地・上の選択の色の帯・濃い文字) は `index.css` の `.cs-tab` が持つ
- 名前の全体を tooltip (`title`) に持つ。縮んで省略されても読めるように
- タブは並ぶ数に応じて縮み (`flex: 0 1 200px`)、下限 (96px) を持つ
- 縦のホイールを横の送りに読み替える (横のスクロールバーを出さないので、マウスで送る口が要る)
- アクティブなタブが変わると、帯の外に送られていても見える所まで寄せる

## なぜテストするか

UI/UX review §2.3 で、タブが溢れると横のスクロールバーが出て名前が省略される、アクティブな
タブの見分けが弱い、と指摘された。スクロールバーをやめたので、**代わりの送り方と、
アクティブなタブを見える所に置くこと**が要る。どちらかが欠けると、開いているタブに戻れない。

## どのようにテストするか

- happy-dom は配置を計算しないので、縮み方は `flex`・`min-width` の指定で見る
- ホイールは `scrollLeft` が増えることで見る
- 寄せる動きは `scrollIntoView` を差し替えて、呼ばれた回数で見る

## 通知の印 (#260)

前に出ていない File に判断の要る通知 (競合・届いた fork) があるタブに、印を付ける。中身はそのタブを前に出したときに
右下に出る。

- 印は求められたタブにだけ付く
- **タブの名前 (押す口の名前) を変えない。**印は押す口の外に置く。中に入れると、タブの名前で引く検査や読み上げに
  印の名前が混ざる
- 求めなければ (既定) 印は付かない
