# ShareStatusIcon.test.tsx — 共有の印のテスト仕様

## 何を

`ShareStatusIcon` (共有している / 共有が切れている、を 1 つの絵で出す) を検証する。

## なぜ

**取り消されても File は手元に残る。**ローカル正典は自分の写しなので、共有が切れたから
といって消す筋合いは無い。しかし止まるのは取り込みであって表示ではないので、**何も出さないと
「もう同期されない File」が普通の File に見える** (2026-09-05 実機で混乱した)。

最初はこれを「同期していません」という札で出したが、**File 名の隣で幅を食い、サイドバーの
主目的である File 名の識別を潰した** (同日、実機で判明)。状態は 2 値なので絵で足りる。
文字は `title` に移した — 絵は「切れている」ことしか言えず、**何が届かないのかは絵では
言えない**からである。

## どのように

- **共有しているときは ✕ を描かない。**下地 (`👥`) だけが出る
- **共有が切れているときだけ ✕ を重ねる。**`role="img"` + `aria-label` で読み上げにも出す
- **✕ は絵文字ではなく図形として描かれている。**ここが判断の中身である。絵文字の合成
  (`👥` に `❌` を重ねる、異体字セレクタ、合字) は**エンジンごとに位置も大きさも変わる**。
  WebKit を本命に据えている以上 (ANA-125)、決定論的に描けるものを使う。
  「✕ が出ている」ことを文字の有無で見ると、この判断ごと素通しになるので、
  **`<line>` 2 本と `<circle>` 2 つ (白い縁 + 赤い本体) があること**で見る
- **下地の共有の絵は塗り潰されない。**最初は ✕ を絵の全面に渡したが、15px では下地を
  塗り潰してしまい**「✕」としか読めなくなった** (描いて確かめた)。共有の絵が残らなければ
  「何が切れたのか」を言えないので、✕ は隅に小さく置き、下地は薄くもしない
- **✕ は当たり判定を持たない。**箱ごと参加者ボタンの一部なので、`pointer-events: none` で
  クリックを下へ通す。ここが抜けると「切れている File だけボタンが押せない」が起きる

## 何を見ていないか

**色と大きさは見ない。**見た目の調整はサイドバー全体の refinement で動く予定で、
そこで必ず落ちるテストを先に置く意味が無い。ここで固定するのは
「切れているときだけ ✕ が出る」「✕ は線である」「押下を妨げない」の 3 つである。
