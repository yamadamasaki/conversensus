# ParticipationHistoryDialog のテスト仕様

## 何を

参加履歴ダイアログが、渡されたラウンドを表として描くことを検証する。

## なぜ

**判断はこの部品に無い。**どの列に何が入るかは `participationRounds` が決めており、
ここは日付に直して並べるだけである。したがって検証したいのは「導出が正しいか」では
なく、**導出の結果が漏れなく画面に出ているか**である。

とくに 2 つ。

- **実行者も DID ではなくハンドル名で出す。**参加者の列だけ名前にして実行者の欄に
  DID が出る、という状態を作らない。`labelOf` を通し忘れても「何か出ている」ので
  目視では気づけない
- **記録が無いときに空の表を出さない。**列だけの表は「読み込み中」と区別がつかない

## どのように

- **日付と実行者を両方見る。**片方だけだと `labelOf` の通し忘れが通ってしまう
- **DID が出ないことを明示的に見る** (`queryByText` が null)。「ハンドル名が出ている」
  だけでは、DID と併記されていても通る
- **`at: 0` が `—` になる。**作成者の参加日時は記録されていない (genesis の timestamp は
  べき等のために 0 固定)
- **4 列はいつも出す。**巡によって列が消えると、行ごとに列がずれる
- 記録が無いときは文言を出し、**表の見出しを出さない**

## 引かなかったもの

- スクロールの挙動。仕様も「スクローラはなくてもいいかもしれない」としている
- 日付の書式そのものは `formatDay` のテスト (`participationHistoryView.test.md`) が持つ。
  ここで二重に固定すると、書式を変えるときに 2 箇所直すことになる
