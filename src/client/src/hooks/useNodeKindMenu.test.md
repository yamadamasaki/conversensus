# useNodeKindMenu のテスト仕様

## 何を

既にあるノードを右クリックして**種別を変える**口の状態遷移と、そこから出る
`NODE_LABEL_CHANGED` を見る。

## なぜ

この口は「あれば良い」ではなく**要る** (設計 D3)。仕様が「既存のノードのラベルは空でよい」と
言う以上、**空のまま存在するノードに種別を与える道が無ければ、template を当てた sheet に
既存のノードを持ち込めない**。Phase 6 が dialogue graph を作るときにも通る道である。

エッジの `useEdgeContextMenu` と同じ形にしてあるので、固定したいのは**同じ形になっている
こと**と、**種別に固有の判断**である。

## どのように

### メニューを開く

- **右クリックしたノードを対象にし、現在の種別を持つ**: 現在値が分かるとメニューで
  ハイライトできる。
- **種別を持たないノードの現在値は空文字**: `undefined` にしない。空文字は「種別なし」の
  現在値そのものであり、メニューの末尾にある「種別なし」が現在値として光る。
  `undefined` と空文字を分けると、`op` に載る値 (空文字) と画面の状態が食い違う。
- **選択中が複数ならまとめて対象にする / 混在なら現在値は null**: エッジの経路種別と
  同じ規則。混在時に片方を現在値として光らせると、押していない方の値が正だと誤解させる。
- **template が当たっていなければ開かず、`preventDefault` もしない**: 種別の段を出さないのと
  同じ理由 (D3) に加えて、**ブラウザの既定の右クリックを奪ってはいけない**。
  種別が無いシートでコンテキストメニューが死ぬのは、機能が無いことより悪い。

### 種別を変える

- **`NODE_LABEL_CHANGED` を from/to つきで出す**: undo が要るので双方向の値を持つ。
- **与えるときの from は空文字 / 外すのは to が空文字**: 「無い」を空文字で表す規則が
  両方向で一貫していること。`node.setLabel` に空文字を載せるのであって、op が消えるのではない。
- **変わらないものは op-log に積まない**: 複数選択でまとめて変えるとき、既にその種別の
  ノードまで op を出すと、**op-log が伸びるだけでなく他の参加者に無意味な LWW 上書きが飛ぶ**
  (Phase 3 T8 の「上書きの報告」に偽の報告が出る)。
- **選び終えたらメニューを閉じる**: 開いたままだと、次の右クリックで位置が更新されずに
  古い対象へ操作してしまう。
