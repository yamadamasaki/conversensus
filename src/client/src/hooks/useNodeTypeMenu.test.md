# useNodeTypeMenu.test.ts — テスト仕様

## 何をテストするか

`useNodeTypeMenu` — ノード生成の入り口。ダブルクリックを受けて
「どこに何を作るか」を決める `NodeTypeMenu` の状態を組み立てるフック。

## なぜテストするか

ANA-107 S4 (設計 D5) で、ノードの生成経路を pane とグループ本体の 2 本から
**このフック 1 本**に集約した。それ以前はグループ本体のダブルクリックが
直接 `NODE_ADDED` を dispatch していたため、グループ内では markdown ノードしか
作れなかった (ANA-110)。

集約したことで、座標をコンテナ相対に直す処理もここ 1 箇所になった。
座標系の取り違えは画面上「ノードが別の場所に飛ぶ」形でしか現れず、
実機でしか気づけない類のバグなので、変換の結果をテストで固定する。

## どのようにテストするか

`screenToFlowPosition` は本物 (ReactFlow の viewport 変換) を使わず、
`+1000` の単純なずらしに差し替える。これで「画面座標をそのまま使っている」
実装と「変換を通している」実装がテスト上で区別できる。

題材は `outer(100,100) > inner(50,50)` の 2 段の入れ子。`inner` の絶対座標は
(150,150) になるので、親の `position` だけを引く実装 (1 段しか辿らないバグ) は
`inner` を指定したケースで落ちる。

### 観点ごとの意図

- **コンテナ未指定**: 位置は canvas 座標そのもの。`containerId` を持たない。
- **コンテナ指定**: そのコンテナの絶対座標を引いた相対座標になる。
  React Flow の子ノードの `position` は親からの相対座標だから。
- **入れ子のコンテナ**: 祖先まで辿った絶対座標が基準であること。
- **ダブルクリック判定**: pane では ReactFlow がイベントを握るため React の
  `onDoubleClick` が使えず、クリックの間隔と距離から自前で判定している。
  1 回では出ない / 同じ場所の連続で出る / 離れた場所では出ない、を固定する。
- **閉じる経路**: `clearNodeTypeMenu` と ESC。

グループ本体のダブルクリックがこのフックを呼ぶこと自体は
`GroupNode.test.tsx` が担当する。選ばれた種類のノードを実際に作るのは
`GraphEditor` の `addNode` で、生成イベントの適用は
`events/applyEvent.test.ts` の `NODE_ADDED` が見る。
