# useFileParticipants のテスト

## 何を

依頼の宛先の候補 (開いている File の参加者) が、同期サイクルの読んだ名簿に追随すること。

## なぜ

以前は File を開いたときに 1 度だけ名簿を読んでいたので、開いた後で参加した人は開き直すまで
宛先の候補に出なかった (#381)。今は名簿を自分で読まず、同期サイクルが毎回読む名簿 (`participating`)
を受け取る。その受け渡しが崩れると、同じ不具合が戻る。

## どのように

`renderHook` で描き、名簿 (`participating`) を差し替えて候補を見る。ハンドル名を引く口は
引数で差し替える (本物は PDS に問い合わせる)。

| テスト | 確かめること |
| --- | --- |
| ハンドル名の順に並べる | 候補はハンドル名で引かれ、その順に並ぶ |
| 開いた後で参加した人 (#381) | 新しい名簿を渡すと、増えた人が候補に出る |
| 名簿が届く前 | 候補は空 (宛先は選べないが、不特定で送れる) |
| 別の File の名簿 | File を替えた直後、前の File の参加者を候補に出さない |
