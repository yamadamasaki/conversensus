# useAtprotoSession.test.ts — セッションの復元のやり直しのテスト仕様

## 何を

`useAtprotoSession` が、オンラインに戻ったときにセッションの復元をやり直すことを、セッションの口
(`resumeSession` / `login` / `logout`) を偽物にして検証する (FPR 前 L-2)。

## なぜ

起動時の復元はネットワークを要るので、オフラインで起動するとログアウトした扱いになり、その間の編集は
未ログインの actor で書かれる。以前は起動時に 1 度しか復元しなかったので、オンラインに戻ってもログアウトの
ままだった。戻ったときに復元できれば、ログインし直さずにログイン済みに戻り、未ログインの編集の出し直し (L-1) へ
進める。

## どのように

- **オフラインで起動 → オンラインに戻る**: 起動時の復元は失敗してログアウトの扱い。`online` を送ると復元が
  通り、ログイン済みになる
- **ログイン中はやり直さない**: `online` を送っても復元を呼ばない (無駄な往復をしない)
- **自分でログアウトした後**: やり直しても、保存されたセッションが無いので null が返り、ログアウトのまま。
  勝手にログインし直さない

`oauthAuth` が失敗した復元を覚えない (client ごと作り直す) ことは、OAuth のライブラリを要るのでここでは見ない。
App 結合はパスワードの認証で動くので、そちらも別の経路である。
