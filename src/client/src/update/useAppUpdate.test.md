# useAppUpdate.test.ts — 新しい版を見張るフックのテスト仕様

## 何を

`useAppUpdate` (配られている build の印を見に行き、このタブの印と違えば知らせる) を検証する (#262)。
取得口 (`fetchLatest`) を差し替え、配られている印をテストの中で変える。

## なぜ

知らせを出すのは、**このタブが古い版のまま動いている**ときだけでなければならない。
同じ版で出せば知らせが信用されなくなり、出し損ねれば op の種類を足した版 (MINOR) の op が効かないまま
使い続けることになる。見に行く時機 (前に戻ったとき・一定の間隔) と、見に行かない時機
(背後にある間・見つけた後・開発サーバ) も固定する — 見つけた後に見に行き続けるのは無駄な通信である。

## どのように

- 同じ版なら知らせない / 開いた時点で新しければ知らせる
- 背後にある間に配られた版: **背後に回ったときは見に行かず**、前に戻った `visibilitychange` で気付く。
  間隔は鳴らないほど長くして、タイマーでなく `visibilitychange` で見に行ったことを確かめる
- 開きっぱなし: 間隔 10ms で、途中で配られた版に気付く
- 見つけた後は呼び出し回数が増えない
- 読めない (null) ときは知らせない
- 閉じたら、このタブではもう出さない
- オフラインの間は見に行かない — 失敗した取得はブラウザがコンソールに積むので、オフライン起動の
  E2E (`offline.spec.ts`) が「コンソールエラー 0 件」で落ちた
- `enabled: false` (開発サーバ) なら 1 度も見に行かない
