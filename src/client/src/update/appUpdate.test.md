# appUpdate.test.ts — 配信の印を読むテスト仕様

## 何を

`fetchLatestBuildId` (配信の `version.json` から、いま配られている build の印を読む) と、
`CURRENT_BUILD_ID` (このタブの build の印) を検証する (#262)。

## なぜ

開いているタブが新しい版に気付く手段はこの印だけである (`sw.js` は build をまたいで変わらないので、
ブラウザは更新を知らない)。**読めないときに印を取り違えると、新しい版が無いのに知らせが出る** —
開発サーバ (印が無く、画面の HTML が返る)・配信の入れ替え中・オフラインのどれでも
「新しい版は無い」(null) と扱うことを固定する。知らせを誤って出すより、出し損ねる方がよい
(次に開けば新しい版になる)。

## どのように

- 印を読むときに `cache: 'no-store'` を付ける — HTTP のキャッシュに古い印が残っていると、
  新しい版を見落とす
- 404・JSON でない・`build` が無い / 空 / 文字列でない・`null`・fetch が投げる、をすべて null に
- テストでは build が印を埋めないので、`CURRENT_BUILD_ID` は `dev` (`typeof` で見るので投げない)
