# SearchPanel.test.tsx — 検索の画面のテスト仕様

## 何を

検索窓と結果一覧 (`SearchPanel`) の**振舞い**を検証する。見た目 (色・寸法・位置) は見ない。

## なぜ

この画面は**最小で作ると決めたもの**である (利用者判断 2026-09-20、UI/UX の見直しは step 3)。捨てるかもしれないものにテストを厚く積む理由は無いが、**捨てる判断をするために動かす**以上、動かないものを渡しては判断材料にならない。したがってテストは「作り込み」ではなく**「触れる状態であること」**に絞る。

固定するのは、**やり直しが効かない種類の誤り**に限る。具体的には入力と検索の対応 (打った語で引いているか)、トグルの反映、結果から要素への橋渡しの 3 つである。これらが壊れていると、利用者は「検索が役に立たない」と判断してしまい、それは UI の良し悪しではなく**結線の欠陥**なのに UX の評価に混ざる。

## どのように

### 打った語で引く

- 入力するたびに `onSearch` が**その時点の値**で呼ばれる。**Enter を待たない。**仕様は検索窓の要素として enter を挙げているが、打つたびに出る方が「どこがどうだめか」を掴みやすい。Enter でも引けるので仕様を狭めてはいない
- **日本語の変換中は引かない。**`compositionstart` から `compositionend` までは `onSearch` を呼ばず、確定した時点の値で 1 度だけ引く。ここを落とすと未確定の文字 (「ｋ」「か」…) で検索が走り、確定前に結果が入れ替わる。**日本語が公用語のリポジトリで、これは日常的に踏む**
- 変換の確定後に引き直す値は、**確定後の値**である。`composingRef` を下ろすだけで引き直しを忘れると、変換して確定した語では一度も検索されない

### トグルはその場で効く

大小文字のトグルを変えたら、**その場で引き直す**。押してから打ち直させると、トグルの意味が分からない (「押したのに何も起きない」)。検索語が空のままトグルを押しても呼ばれることまでは問わない — 中核が空を 0 件で返す。

### 結果から要素への橋渡し

- 1 件を押すと `onReveal` が**その 1 件**で呼ばれる。ここが要点で、渡す `SearchHit` が別の行のものだと、**関係ない要素にグラフが飛ぶ**
- 仕様は「ダブル・クリックにより」と書いているが、**1 回のクリックでも効く**ようにしてある。押して何も起きない UI は壊れて見える。ダブルクリックを殺してはいないので仕様は満たす

### 同じ要素の複数のヒットが混ざらない

同じノードの label と本文の両方が当たると 2 行出る。key は「要素 + 欄 + プロパティ名」で作る。テストは同じ id で欄の違う 2 件を渡し、**2 行出て、それぞれが自分の `SearchHit` で `onReveal` を呼ぶ**ことを見る。これは行の取り違えという実在の欠陥を捕まえており、「常に先頭のヒットを渡す」変異で死ぬ。

**ただし「key が id だけだと片方が消える」は誤りだった。**当初この項にそう書いていたが、key を id だけにする変異を当てても 13 件すべてが通る。React は重複した key に警告を出すものの描画は両方行い、**この行は内部状態を持たない**ので振舞いが変わらないからである。現状では**等価変異**である。

それでも key を分けておく理由は 2 つあり、どちらも**テストでは固定されていない**。(1) 警告を出させないため。(2) 行が内部状態を持った瞬間 (開閉の印、選択中の強調) に初めて実害が出るが、**そのときこのテストは何も言わない**。ここは意図として残す。

### 0 件と「まだ引いていない」を分ける

- 検索前 (`searched` が偽) は結果の領域ごと出さない。0 件と同じ見た目にすると、開いた瞬間に「見つからない」と出る
- 検索したうえでの 0 件は**そう言う**。黙って空にすると、壊れているのか無いのかが分からない

### property は名前と型を出す

仕様「property の場合は, 名前, 型も表示」。型は値から推論したものである (step 2 に「型が先に決まっている」状態は無い)。

### ヒットした部分だけ色が変わる

抜粋を `matchStart` / `matchLength` で 3 つに割り、真ん中だけ `mark` にする。**中核が返す位置をそのまま信じる**ので、位置そのものがずれていれば中核のテスト (`searchSheet.test.ts`) が落ちる。

**`mark` の中身だけを見てはならない。**最初はそう書いていたが、前の断片を捨てる変異 (`before` を空にする) が生き残った。`mark` の中身は `slice(matchStart, end)` のままなので、**前後が丸ごと消えても中身は変わらない**からである。しかもこの穴は、行の同一性を見るテストを通すために `hit` ヘルパーの既定を「抜粋全体がヒット」に変えた副作用で広がっていた — **既定を緩めると、既定に頼るテストがまとめて痩せる**。

したがってテストは `mark` の中身と、**行全体のテキストが抜粋と一致すること**の両方を見る。

## テストしていないこと

- **見た目**。位置・色・寸法は step 3 で見直す
- **移動できること**。仕様は「ダイアログは移動可能」と求めるが、既存のダイアログに移動できるものが 1 つも無く、覆いの構造から変えることになる。step 3 へ繰延 (この判断はコード側のコメントにも書いてある)
- **グラフ側のハイライトそのもの**。`onReveal` を受けた側 (`GraphEditor`) の仕事で、React Flow の選択と `setCenter` に委ねている
- **検索の中身**。どの欄を走査するか、抜粋をどう切るかは `searchSheet.test.ts` が見る
