# AcceptInvitationDialog のテスト仕様

## 何を

参加依頼の承認ダイアログが、**何に参加するのかを名前で見せてから**承認させることを
検証する。

## なぜ

参加コードを貼っただけで参加が成立すると、**渡し間違いや貼り間違いに気づけない**。
仕様が確認の一段を挟んでいる (`participation/accept.png`) のはそのためで、
出すのは 3 つ — 誰が、あなたを、どのファイルに。

**どれも DID や FileId ではなく名前で出す。**`did:plc:ag2ritx6qpujmphxjj2upd53` を
見せられても、それが誰かは分からない。自分のハンドル名を出すのは、**コードが自分宛で
あることを目で確かめられる**ようにするためである (宛先違いは畳み込みより手前で
弾いているが、弾かれた理由を読むより「誰宛か」が見えている方がよい)。

## どのように

- **3 つが出ることと、id が出ないことを対で見る。**「alice.test が出ている」だけでは、
  DID と併記されていても通ってしまう
- **名前が引けなかったときは fileId が出る。**`labelCache` の fallback がそうなっている。
  空欄にすると「読めなかった」のか「名前が無い」のかが区別できない。
  この部品は渡されたものを出すだけなので、**引けなかった状態を渡して**確かめる
- **閉じても承認しない。**確認の一段が意味を持つのは、ここで止められるからである
- `busy` の間は参加できない (二重の承認を書かない)

## 引かなかったもの

- 何が `preview` に入るか (依頼の実在確認、名前の解決) は `useParticipation` の仕事で、
  この部品は受け取ったものを描くだけである。文言の組み立てだけをここで固定する
