# アプリ内タブのテスト

## 何を

- `tabs.ts` — タブの並びを動かす純関数。開く・移る・閉じる・アクティブのアドレスの置き換え・
  条件で閉じる (step3 Phase 3 S3-3)。**タブは pane の並び + アクティブな pane** で、pane を足す・
  前に出す・外す (S3-5 の multiple モード)
- `tabStorage.ts` — 並びの保存と復元 (Q3: `localStorage`)
- `navigation.ts` — いまの画面から行き先のアドレスへ移る「次の 1 段」

## なぜ

タブは中身を持たず、アドレスだけを持つ。だから**並びの規則が崩れると、画面は静かに違う
グラフを出す** (例外は出ない)。とりわけ次の 3 つは、画面のテストでは引き当てにくい。

- 同じアドレスのタブが 2 つできる (Q2)。undo の履歴の置き場 (`addressKey`) が 2 つのタブで
  共有され、どちらで編集したのか分からなくなる
- アクティブが並びの外を指す。画面は何も出さないか、閉じたタブの中身を出し続ける
- 保存した並びが読み戻せない。再読み込みのたびにタブが消える (Q3 の決定に反する)

いずれも「**あらゆる**操作の列で成り立つ」主張なので性質として書く。

## どのように

### 生成器

- **アドレスは小さなプールから引く** (2 File × 2 シート × trunk/branch × head/vector の 16 通り)。
  広いと同じアドレスを 2 度引かず、「既存のタブへ移る」に当たらない
- 操作は「開く / 移る / 閉じる / pane を足す / pane を前に出す / pane を外す」の列。移る・閉じるの対象は**いまの並びの中の位置**で引く —
  存在しない id を渡すと何も起きないだけで、規則を試さないため
- `retargetActive` は列に入れない。画面の側でアドレスが動いたことを写すもので、同じアドレスの
  タブを作りうる (例: branch を閉じて trunk に戻ると、trunk のタブと並ぶ)。Q2 は「開く」操作の
  規則であって、並び全体の不変条件ではない

### 性質

| 性質 | 固定すること |
| --- | --- |
| アクティブは常に並びの中、並びが空のときだけ null。どのタブも pane を 1 つ以上持ち、アクティブな pane は並びの中 | 閉じたタブ・外した pane を指し続けない |
| 明示しない限り同じアドレスの single のタブは 2 つできない | Q2。pane を外すと multiple が single に戻って既にある single と並ぶことがあるので、pane の操作を含まない列で見る |
| 開いたアドレスがアクティブになる | 既存のタブへ移る場合も含めて |
| 閉じたタブだけが消え、残りの並びは変わらない | 閉じる操作が他のタブを動かさない |
| 保存して読み戻すと同じ並びになる | Q3 の往復 |
| 移る手順を最後まで踏むと 4 段以内に着く | 段が循環しない。画面の動き (File を開くと trunk、シートを選ぶと trunk) を模した上で |

### 例

性質では読みにくい具体の振舞いを固定する。

- 閉じたときの移り先 (右隣、右端なら左隣。ブラウザのタブと同じ)
- アクティブでないタブを閉じてもアクティブは動かない
- `forceNew` なら同じアドレスでも足す (修飾キーで別のタブに開く口)
- 既存のタブへ移るとき highlight は差し替える (検索の結果から開いた場合に強調が出る)
- シート・File の削除で、それを指すタブが閉じる。multiple のタブは該当する pane だけを失う
- pane を足してもアクティブな pane は動かない
- アクティブな pane を外すと右隣、右端なら左隣が前に出る。最後の 1 つを外すとタブが閉じる
- **アクティブより前の pane を外すと、アクティブは同じ pane を指し続ける** (位置を 1 つ詰める)
- multiple のタブは、サイドバーから開いたアドレスを吸い込まない (Q2 は single だけを見る)
- 復元: S3-3 の形 (アドレス 1 つ) で保存した並びも読める。アクティブな pane が並びの外なら先頭へ。
  無い・JSON でない・形が違う値は空。**壊れたタブだけを捨て、残りは復元する**。
  アクティブが捨てられたら先頭へ

## 変異で確かめたこと

- `openTab` の重複の判定を外す → Q2 の性質と highlight の例が落ちる
- 閉じたときの移り先を左隣優先にする → 移り先の例が落ちる
- アクティブより前の pane を外したときに位置を詰めない → その例が落ちる。**性質の不変条件
  (アクティブな pane は並びの中) では捕まらなかった** — 詰め忘れても並びの中を指していることが多く、
  指す pane が変わるだけである。だから例で固定した
