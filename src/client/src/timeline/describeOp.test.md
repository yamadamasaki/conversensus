# describeOp のテスト

## 何をテストするか

change inspector が op を 1 行で出すための `opKindLabel` (種類の名前) と `opDetail` (人が読める内容) (#73)。

- 種類は日本語の短い名前。知らない種類 (後の版が足した op、器の op) は `kind` をそのまま出す
- 内容は本文・種別名・property の名前。運ばない op は空
- 長い本文は上限 (`DETAIL_MAX_LENGTH`) で切って `…` を付ける

## なぜテストするか

知らない種類で落ちると、後の版の op が 1 つ混ざっただけで inspector が描けなくなる (知らない op は保存して
読み飛ばす方針, step3 FPR §5.3)。長い本文をそのまま出すと、狭い右サイドバーが 1 つの op で埋まる。

## どのようにテストするか

op を手で組んで、返る文字列を比べる。
