# theme.test.ts

見た目の体系 ([visual language](../../../deepse/architecture/step3/visual-language.md)) の値が、
文書の決まりを守っていることを確かめる。

## 何を

1. **`theme.ts` が参照する CSS 変数が、すべて `index.css` に定義されている**
   - `var(--cs-typo)` はブラウザでは黙って無視され、色が抜けるだけで誤りに気付けない。型検査も届かない
2. **コントラストが WCAG AA の下限に届く** (visual language §0 の下限、#273)
   - 文字の組 (前景・背景) は 4.5:1、意味を持つ図形 (線・枠・アイコン) は 3:1
   - 組は visual language が「この上に置く」と決めたものを列挙した。値を直すとき、どの組が崩れるかがここで分かる
3. **部品のソースに色の値を直書きしていない** (#267)
   - `.ts` / `.tsx` (テストを除く) の **文字列リテラルの中** に `#rgb`・`#rrggbb`・`rgb()`・`rgba()` が無いこと
   - コメントの issue 番号 (`#202` など) を拾わないよう、文字列の中だけを見る
   - 例外は `theme.ts` (変数の名前の置き場) と `graph/exportPng.ts` (PNG の背景。CSS 変数を読めない描画先に渡す値)

## なぜ

色を役割の変数にまとめても、次に部品を書く人が値を直書きすれば元に戻る。3 はそれを止める柵である。
2 は「AA に届かない色」を値の側で一度だけ検査する — 部品ごとに測らなくてよくなる。

## どのように

- `index.css` を文字列として読み、`--cs-*: 値;` を正規表現で拾う (CSS を解釈する部品は使わない。
  `:root` に平らに並べる書き方を前提にしている)
- コントラストは WCAG 2.x の相対輝度の式をそのまま書いた
