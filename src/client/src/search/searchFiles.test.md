# searchFiles.test.ts — File をまたいだ中身の検索のテスト仕様

## 何を

`searchFiles` (全 File の trunk の Sheet に Sheet 内検索を当て、当たりに File と Sheet を付ける) を
検証する (#248)。

## なぜ

同じ検索語が、Sheet 内検索 (`SearchPanel`) とここで違う結果を出すと、どちらかを信用できなくなる。
当て方を 2 つ書かず、`searchSheet` をそのまま当てているのはそのためで、**その一致を性質として固定する**。
当たった場所 (File と Sheet) が無ければ、結果を押しても開けない。

1 文字の検索語は全 File の要素の大半に当たる。Worker から運ぶのも描くのも重いので上限で打ち切り、
打ち切ったことを呼び出し側に伝える (黙って切ると、無いものと誤解される)。

## どのように

- 例: 当たりに File と Sheet の id と名前が付き、File の順に並ぶ
- 例: 上限を超えたら打ち切って `truncated`。ちょうど上限なら打ち切りではない
- 例: 大文字・小文字の区別が `searchSheet` へ渡る
- 性質: **あらゆる File の並び・検索語・区別の有無で**、当たり (File と Sheet を除いた部分) は
  各 Sheet の `searchSheet` を順に並べたものと等しい
  - 生成器は `a` `b` `A` の 3 文字から 3 文字までの本文を引く。小さなプールで当たりを頻繁に起こし、
    `A` で大文字・小文字の区別の有無を引き当てる
