# PropertyEditor.test.tsx — property editor の画面のテスト仕様

## 何を

行の描き分け (編集できる / できない)、値の確定、追加と削除の口を検証する。
**何を出すかは見ない** — 選別・型・編集可否の判断は Q1 (`propertyRows`) の仕事で、
ここは受け取った行を描くだけである。

## なぜ

**間違えると op-log に残る。**この画面が出す操作は `node.setProperty` /
`edge.setProperty` になり、全参加者の projection に届く。表示の誤りなら見れば分かるが、
**編集させてはいけないものを編集させたら、記録は追記のみなので取り消せない**。

同時に、**編集できない理由を言わない画面は壊れて見える**。Phase 5 が label で同じ問題に
当たり、「編集できるかで要素そのものを変える」(`div` か `button` か) ことで解いた。
ここはそれを 2 種類の理由に広げる。

## どのように

### 編集できるかで要素そのものを変える

- 編集できる行は **入力欄**を出す
- 編集できない行は **ただの文字**にする。入力欄を `disabled` で出すと、打てそうで
  打てない欄になる
- **理由を文言で出す**。`templateKind` なら「種別は作成時に決まり、変更できません」、
  `structuredValue` なら「構造を持つ値はこの画面では編集できません」。理由ごとに
  文言が違うことを固定する — 同じ文言にするなら理由を持つ意味が無い

### 値の確定

- **Enter と blur で確定する。**どちらか片方だと、打ってから別の行へ移った編集が消える
- **変わっていなければ何も起きない。**同じ値で確定しても `onSet` を呼ばない。
  変わらないものを op-log に積むと、偽の LWW 上書きが T8 の報告に出る (Phase 5 の判断)
- **Escape で元に戻す。**確定前なら捨てられること
- **IME 変換中の Enter を無視する。**日本語の確定 Enter で値まで確定すると、
  変換を確定しただけで op が飛ぶ。日本語が公用語のリポジトリでは日常的に踏む

### 値は文字列のまま返す

**型を指定するのは実装コードか template のような拡張であって、入力された値では
ない** (利用者判断 2026-09-20)。したがって入力から型を推論して値を寄せない。

当初は `優先度: 3` を `4` に直したとき数値で返していたが、**撤回した**。カスタムの
プロパティは node のインスタンスごとに値が違いうるので、その場の値から型を決めても
**その型を使う場面が無い**。害もあり、`3` と打っただけで数値になると**文字列の
`"3"` を入れる手段が無くなる** (step2 に型を指定する口は無い)。

固定するのは「数値に見えても・真偽値に見えても文字列で返る」ことである。

### 変更は「キー 1 つ」で返す

`onSet(name, value)` / `onRemove(name)` を呼ぶだけで、**全体は組まない**。
`NODE_PROPERTIES_CHANGED` の `from`/`to` に全体を載せる契約は呼び出し側 (Q2 の結線) に
置いた。**契約を 1 か所に置く**ためで、ここが全体を組むと `ImageNode` と 2 か所に
同じ約束が散る。

### 追加の口

- **名前と値を入れて追加できる** (custom は自由、仕様の表)
- **既にある名前は追加できない。**追加のつもりで既存の値を上書きするのを防ぐ
- **空の名前は追加できない**
- **template が宣言した候補は `datalist` で出す。**`select` にしないのは、
  **宣言に無い名前も足せる**からである (custom は自由であり、選択肢に閉じてはいけない)

### 読み取り専用のとき

再参加した後、同期が済むまでは編集させない (Phase 2 S6)。**すべての行が文字になり、
追加の口ごと消える。****見るのは止めない** — 「読むための操作は残す」という S6 の
判断に揃える。

### 他者の編集が届いたら追従する

同じプロパティを相手が直したら、開いたままの欄も新しい値になる。**編集中の打鍵を
奪わない**ため、追従するのは値が変わったときだけである。

## テストしていないこと

- **行の選別・型・編集可否の判断**。`propertyRows.test.ts` が持つ
- **op の発行**。`NODE_PROPERTIES_CHANGED` / `EDGE_PROPERTIES_CHANGED` の組み立ては
  結線の側で、reducer は Q0 で塞いだ
- **どの要素を対象にするか**。選択の観測は結線の仕事
- **見た目** (位置・色・寸法)。UI/UX の見直しは step 3
