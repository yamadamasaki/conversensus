# depsDelta のテスト

## 何をテストするか

deps を差分で送り、受け手で全体に戻す仕組み (D1, 計画 `deepse/plans/refine-d1-deps-delta.md`)。

- `deltaDeps`: 全体のうち基より大きい項目だけを残す。基に無い項目は 0 と比べる
- `DepsDeltaEncoder`: 送れた実績が無ければ全体、あればその seq を基にした差分。**送れずに飛ばした batch は基にしない**。
  File ごとに別に覚える
- `restoreDeps`: 差分を基の全体に足して戻す。基が取得の中に無いものは戻さずに `unresolved` へ

## なぜテストするか

差分が全体に戻らないと、受け手の手元の正典に「知っていることを少なく見積もった」deps が残る。因果の判定はそれを
信じるので、並行でない編集が並行に見え、競合が出続ける。例外は出ず、画面では気付きにくい。

- 送り手は、画像の実体が無い batch を飛ばして後を送ることがある (`pushRemote`)。飛ばした batch を基にすると受け手が
  戻せないので、「送れた batch だけを基にする」を固定する
- 受け手には順不同で届く (rkey の順・取得の順は seq の順と限らない)

## どのようにテストするか

- 例: 上の振舞いを 1 つずつ
- **性質**: 2 人の actor が、seq が進むにつれて増えるだけの deps の列を持ち、各 batch を送れたか送れなかったかを
  任意に決める。送り手は seq の順に試して送れたものだけを覚え、受け手には順不同に並べ替えて渡す。このとき
  **届いたものはすべて元の全体の deps に戻り、戻せないものは無い**
- **性質**: 差分の項目数は全体を超えない
- 生成器: deps の項目の actor は小さなプール (3 人) から引き、1 歩の増分は 0〜3。広いと同じ actor の項目が続かず、
  「基と同じなので差分に載らない」場合に当たらない。増分 0 は「その actor について何も新しく知らなかった」を表す
