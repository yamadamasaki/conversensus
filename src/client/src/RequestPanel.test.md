# RequestPanel.test.tsx — 右の欄の「依頼」の区画のテスト仕様

## 何を

`RequestPanel` (応答を求める node を選んだときに、状態・宛先と、今できる操作を出す区画、agent 段 4 R4、
計画 Q2 案 A) を、操作の受け口を偽にして描いて検証する。

## なぜ

**できない操作のボタンを出さない**ことがこの区画の約束である — 押せるのに効かない形を作らない
(閉じた依頼に「答える」、下書きに「送り直す」など)。宛先は DID で持つが、人にはハンドル名で見せる。

## どのように

- 状態ごとのボタン: 下書き → 送る / 送った・回答あり → 送り直す・閉じる・答える (何回目かも出す) /
  閉じた → 開き直す
- ボタンは操作を渡す (閉じる → `{ kind: 'close' }`)
- 宛先が空なら「指定なし (参加者全員)」。候補から足すと宛先の列を渡す
- 宛先はハンドル名で出し、× で外す。候補には宛先に入っていない人だけが出る (全員入っていれば候補の欄を出さない)
- 答えは書いてから押す。空では押せず、押すと書いた本文を渡して欄を空にする
- 読み取り専用では、状態と宛先だけを出す (ボタンも答えの欄も出さない)
