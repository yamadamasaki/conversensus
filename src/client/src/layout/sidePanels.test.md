# サイドバーの幅と開閉のテスト

## 何を

`layout/sidePanels.ts` — 左右のサイドバーの幅を許す範囲に収める規則 (`clampWidth`)、ドラッグの
移動量から幅を出す規則 (`resizedWidth`)、`localStorage` への保存と読み戻し (step3 Phase 3 S3-4b)。

## なぜ

- **幅が範囲を外れると、ボディか サイドバーの中身が読めなくなる。**狭すぎるとファイル名もボタンも
  潰れ (#51 と同じ壊れ方)、広すぎるとボディが無くなる。ドラッグはどこまででも引けるので、
  収める規則が唯一の守りである
- **左右で引く向きが逆である。**左は右端を右へ、右は左端を左へ引くと広がる。取り違えると、
  右サイドバーを広げようとして狭まる
- **読み戻しが壊れると、再読み込みのたびに既定に戻る**か、壊れた幅で描かれる

いずれも「あらゆる幅・移動量で成り立つ」主張なので性質として書く。

## どのように

### 生成器

- 幅は**範囲の内外と境界** (最小・最大そのもの) を引く。範囲の中だけを引くと、収める規則を試さない
- 移動量は小数も引く (ポインタの座標は小数になる。幅は整数にする)

### 性質

| 性質 | 固定すること |
| --- | --- |
| どれだけ引いても、幅は許す範囲の整数に収まる | 範囲の守り |
| 範囲の中では、左は右へ・右は左へ引いた分だけ広がる | 向きの取り違え |
| 保存して読み戻すと、幅を範囲に収めた同じ状態になる | 往復。範囲の外の値を保存しても、読み戻すと範囲に収まる |

### 例

- 無い・JSON でない値は既定。**既定の右サイドバーは畳んである** (仕様: 使う機会が限られる)
- 片側が壊れていても、もう片側は残す
- 数でない幅は最小に収める
