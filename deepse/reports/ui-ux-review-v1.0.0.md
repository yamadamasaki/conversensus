# UI/UX review — v1.0.0 (2026-10-05)

> 対象: v1.0.0 (FPR) の画面。物差しは [design language](../architecture/step3/design-language.md) と、一般的な
> 使いやすさ・見やすさの原則。Claude が Chrome (macOS, 1091×1120) で開発ビルドを見て書いた。
> 未ログイン・1 端末。merger と通知は画面を出さず、Phase 5・6 の実機確認の記憶とコードで見た。

## 0. 要約

**骨格 (どこに何を置くか) は design language のとおりに組めている。**左サイドバー・ヘッダ・ボディ・右サイドバー、
multiple モード、タブ、Folder は仕様の形をしている。

足りないのは **見た目の体系** である。design language は「どこに何を置くか」を定めているが、色・文字・余白・
アイコン・状態・言葉遣いを定めていない。そのため部品ごとに作った人が決め、**色のリテラルが 46 種類、角丸が
5 種類、フォントが 4 系統**に散っている。個々の不揃いを直すより先に、決まりを足す方が効く (§3)。

## 2. 所見

**重さ**: 🔴 使い方を誤らせる・届かない / 🟠 分かりにくい / 🟡 不揃い

### 2.1 左サイドバー

- 🟠 **操作が記号だけ**: 上段の「+」「↑」「📁」、File 行の「📁」「⚙」は文字が無く、title (hover) にしか説明が無い。
  iOS では hover が無いので、何のボタンか分からない
- 🟠 **metagraph の印が `⌘`**: Mac の利用者は Command キーと読む。index (metagraph) の意味が伝わらない
- 🟡 branch の行だけ monospace・10px・赤みのある背景・✕ (削除) が常に出ている。merged の branch に ✕ が並ぶ
- 🟡 File 行 (太字) と Sheet 行・選択の背景色の段が 3 種類あり、どれが「開いている」かが一目で分からない
- 🟡 **仕様の「保存」→「OK」が未実装** (design language の左サイドバー「個々の File」)。設定のポップアップは「保存」のまま。
  また「ファイルを削除」(破壊的) が「保存」(主) の隣にある
- 🟡 ログインの入口が左下の小さな青い文字だけ (未ログインの帯 (v1.0.0 の L-3) を足したので、帯の方が目立つ)

### 2.2 ヘッダ (グラフの操作)

- 🟠 **ボタンの形がそろっていない**: 🔍 と 🏷 (絵文字)・「Undo」「Redo」(灰の文字)・「グループ化」「グループ解除」
  (青の塗り)・「PNG」(灰の文字)・⧉ (記号)
- 🟠 **「グループ化」「グループ解除」が常に青い**: 選んでいなくても押せる見た目。主の色 (青) を、主でない・使えない操作に使っている
- 🟡 開いているグラフの名前がヘッダに無い (タブにしか無い)。design language の「ヘッダ = 個々のグラフを管理する」なら、名前と状態 (trunk / branch / 未コミット) がここに要る
- 🟡 仕様の「map 表示の on/off」が未実装 (FPR 後の候補)

### 2.3 タブ

- 🟡 タブが溢れると横スクロールバーが出る。名前が省略される (「S3-4 実機確認 | S3-4 実機確…」)
- 🟡 アクティブなタブの見分けが弱い

### 2.4 ボディ (キャンバス)

- 🟠 **File を開いても全体が見えない**: 開いた直後、node が右端で切れている (右サイドバーを開いた後に表示を合わせ直していない。metagraph に node を足したときにも寄る — FPR の確認 §4)
- 🟡 **node の 4 つの接続点が常に出ている**: 選んでいない node にも黒い点が 4 つあり、図がうるさい
- 🟡 **選ぶと node の中身が動く**: 選択すると点線の「ラベル」の口が node の中に現れ、本文が下へずれる
- 🟡 Toulmin の template graph で、上段の edge の label が node の外を回って重なる (FPR の確認 §3)
- 🟡 空のキャンバスの「ダブルクリックで編集」はあるが、空のシートで「何をすればよいか」の案内が無い (右クリック・ダブルクリックで何が出るか)

### 2.5 右サイドバー

- 🟡 「詳細」の見出しと「要素を選ぶと、そのプロパティが出ます」だけ。仕様の timeline / operation inspector / change inspector は FPR 後
- 🟡 property editor の入力欄 (名前・値) と「追加」が小さく、型を指定する口が無い (仕様どおり、型は template が決める)

### 2.6 通知・ダイアログ (Phase 5・6 の実機確認とコードから)

- 🟠 **ダイアログの形が 4 種類**: 確認 (`ConfirmDialog`)・入力 (`InputDialog`)・知らせ (`AlertDialog`)・設定のポップアップ
  (`SettingsPopup`)・参加者のダイアログで、余白・ボタンの並び・閉じ方が少しずつ違う
- 🟡 通知 (競合・上書き・fork) は右下に積む。重要度 (競合は判断が要る / 上書きは事実の報告) の見分けが色と大きさだけ
- 🟡 **言葉がそろっていない**: 「クラウド同期済み」(design language が「曖昧」と書いている用語がそのまま)、File / ファイル、Sheet / シート、
  merge / マージ、「merge ↑」の矢印

### 2.7 小さい画面

- 🟡 iOS で使えることは利用者が確かめた (FPR 基準 1)。ただし両サイドバーとタブを開いたままだと狭く、hover に頼る説明
  (title) が読めない。小さい画面での並べ方は design language に無い

## 3. design language に足すとよいもの (提案)

今の design language は **情報の配置** (どこに何を置くか) の文書である。次の 8 つを足すと、部品を作る人が
迷わず、今回のような不揃いが増えなくなる。上ほど効く。

1. **色の役割 (design token)**: 色を値でなく役割で決める — 主の操作・選択・差分 (追加 / 変更 / 削除)・競合・
   警告・破壊的操作・無効・地・線。今は青が「主の操作」「選択」「リンク」「グループ化」を兼ねている。
   **差分と競合の色はグラフの言語の一部** (merger と branch の表示) なので、ここで固定する価値が大きい。
   実装は CSS の変数にまとめ、ダークモードもそこで受ける
2. **文字の段 (type scale)**: 例えば 11 / 13 / 15 / 18px の 4 段と、それぞれの用途 (補足・本文・見出し・タイトル)。
   最小を 11px、本文を 13〜14px にする。monospace を使う場面 (id・ハッシュだけ等) を決める
3. **余白と角丸の段**: 4px 刻みの余白、角丸 2 種類 (小部品 4px・面 8px) 程度
4. **アイコンの決まり**: 絵文字・記号・アイコンを混ぜない。1 つのアイコン集 (例: Lucide) にそろえ、
   **文字のラベルを付けるか、付けないなら必ず tooltip とアクセシブルな名前を持つ**。iOS では hover が無い
5. **操作の状態**: 普通・hover・押下・選択・無効・実行中 の見え方。**使えない操作は灰にする** (いまの「グループ化」)
6. **ダイアログと通知の型**: 確認 / 入力 / 知らせ / ポップオーバー / 通知 (toast・帯) の 5 種類に決め、ボタンの並び
   (主は右、破壊的は離す・赤)・閉じ方 (Esc・外側のクリック)・主の言葉 (「OK」「保存」「削除」のどれを使うか) を決める。
   通知は重要度 (判断が要る / 知らせ / 進捗) ごとの見え方を決める
7. **言葉の表 (glossary)**: 画面に出す言葉を 1 つの表に — File / シート / branch / merge / commit / fork / 競合 /
   参加者 / 同期 / 「クラウド」の代わりの言葉 (例: 「PDS」か「アカウントの保存先」)。英語のまま使う語と日本語にする語を決める。
   i18n (FPR 後の候補) の下ごしらえにもなる
8. **グラフの描き方**: node と edge の見た目の決まり — 接続点は hover / 選択のときだけ出す、選んでも中身は動かさない、
   label (種類) の chip、group の枠、差分 (追加 / 変更 / 削除のゴースト) と競合 (赤の点線) の描き方、
   template が決める種類ごとの色。**ここが conversensus 固有のデザイン言語の中心**で、他のアプリから借りられない部分

あわせて、決めておくとよい振る舞い:

- **空の状態** (File が無い・シートが空・検索の結果が無い) で、何をすればよいかを出す
- **小さい画面** (iPhone / iPad) での並べ方: サイドバーを重ねて出す・タブを畳む 等
- **アクセシビリティの下限**: コントラスト AA、キーボードで全操作 (いまも多くはできる)、フォーカスの見え方

## 4. issue にする候補 (この review から)

- 🟠 ボタン・アイコンを 1 つの集にそろえ、ラベルか tooltip を必ず持たせる (サイドバーとヘッダ)
- 🟠 ヘッダの「グループ化 / 解除」を選択に応じて無効にする。ボタンの見た目を主 / 副 / 記号の 3 種にそろえる
- 🟠 File を開いたとき・右サイドバーを開閉したときに、表示をグラフ全体に合わせる
- 🟠 metagraph の印を `⌘` から変える
- 🟡 設定のポップアップの「保存」→「OK」(仕様の未実装) と、破壊的な「削除」を主の操作から離す
- 🟡 node の接続点を hover / 選択のときだけ出す。選んでも「ラベル」の口で中身を動かさない
- 🟡 コントラストが AA に届かないアイコンと文字を直す (⚙・✕・📁・「グループ化」・リンクの青)
- 🟡 ダイアログの型をそろえる
- 🟡 「クラウド」の言葉を変える (design language が既に指摘)
- 🟡 ヘッダに開いているグラフの名前と状態を出す
- 🟡 タブの溢れ方 (スクロールバー) とアクティブなタブの見分け
- 設計の作業として: **design language に §3 の 8 つを足す** (色の役割と、グラフの描き方を最優先)

> ⚠️ この review は Claude が 1 つの画面の大きさ・1 つのブラウザで見たものである。利用者の使い方 (よく使う操作の順・
> 頻度) は見ていない。重さの判定は仮のもので、issue にするときに利用者が決める。
