# UI/UX review — v1.3.0 以降 (v1.4.0 候補, 2026-11-11)

> 対象: v1.3.0 (2026-11-05) から main (`e93deea`) までに画面へ入った変更。前回は
> [v1.0.0 の review](./ui-ux-review-v1.0.0.md)。Claude が Chrome (macOS, 1568×769) で開発ビルドを
> 見て書いた。alice (:5173, 日本語) と bob (:5174, 英語) の 2 アカウント、File は `template-test`。
> 色のコントラストは DOM から文字だけ計算した (アイコンは測っていない)。

## 0. 要約

**新しい機能は、既存の骨格 (左サイドバー・ヘッダ・右サイドバー) の中に収まっている。** avatar・依頼 node・
template の後付け・読み取り専用のトグルは、どれも新しい場所を作らずに入った。

気になるのは次の 3 つ。

1. **タブが増えると名前が読めなくなる** (35 枚で 1 枚 73px)。前回の「タブが溢れる」(§2.3) が、
   File を使い込むほど悪化している
2. **依頼 node は、種別名と状態の chip が場所を取り、本文が切れて何の依頼か読めない**。答えた agent の node も
   同じ。agent の印 (ロボットの avatar) は良くできている
3. **英語の UI で種別名が日本語のまま** に見える。#356 の意図に反するか、データが古いだけかを要確認 (§2.5)

## 1. 計測した事実

| | 値 |
| --- | --- |
| 文字の大きさ | 10px 1 件・11px 12 件・13px 63 件・15px 1 件 (前回の 10〜16px より狭まった) |
| 開いているタブ | 35 枚。幅は 73px (名前が読めないものが多い) |
| コントラスト (文字 4.5:1) | avatar の文字 3.62 (10px、白地でなく黄土の円)、`React Flow` の表記 2.85 |
| ヘッダの操作 | すべて `aria-label` と `title` を持つ (読み上げは可。見た目は記号だけ) |

## 2. 所見

**重さ**: 🟠 分かりにくい / 🟡 不揃い

### 2.1 タブ

- 🟠 **35 枚のタブが 73px に詰まり、名前が読めない。** 「foo / Sheet 1」と「foo / Sheet 1 (⎇ )」の区別も付かない。
  hover の title には全名が出る。閉じる ✕ だけが並んで見える

### 2.2 ヘッダ

- 🟠 **操作が記号だけ** (前回 §2.2 の続き)。新しい avatar の on/off (人型) は map (地図) の隣で見分けにくい。
  on/off は色 (青) だけで示す
- 🟡 `Arrange (dev)` は開発ビルドだけの口 (`devPanesEnabled`)。本番には出ないので所見にしない

### 2.3 node と avatar (#354)

- 🟠 **本文が 2 行で切れ、短い文にも灰色のスクロールバーが常に出る。** Toulmin の「主張の根拠となる事実」は
  最後の字が欠ける
- 🟡 **2 人が書いた node は avatar (A・B) が重なり、node の右下の角にはみ出す。** 3 人以上は未確認
- 🟡 avatar の文字は 10px・コントラスト 3.62

### 2.4 依頼 (agent 段 4・node の操作)

- 🟠 **依頼の本文が、種別名と状態の chip の下で切れて読めない。** module-test の Sheet 2 では、依頼 node の本文が
  1 行の半分 (「set property…」) しか見えず、何を頼んだ node か分からない。chip (「回答あり · 3 回目」) が
  node の上半分を占めている。**答えた agent の node も同じ** (「依頼の node (b5b893bb-…) に property を 2 つ設」で切れる)
- 🟡 状態の chip は枠付きで入力欄に見える。狭い node では 2 行に折れる (template-test の「送った・未回答・1 回目」)
- 🟡 **同じ 3 操作 (送り直す・答える・閉じる) が、選ぶと node の上に、右クリックにも出る。** 発見しやすさは
  良いが、2 か所で同じ並びを保ち続ける必要がある
- 🟡 参加者一覧は「依頼者」の列が `—` ばかり。列が空のときは出さない方が静かになる

### 2.4.1 agent の印 (agent の宣言、module-test の Sheet 2)

良い点: **agent の avatar は頭文字でなく、緑の円にロボットのアイコン**で、人と一目で区別できる。hover で
「agent.test (agent・裏付けあり)」と出る。参加者一覧には「agent (裏付けあり)」の印と「operator: alice.test」が出る。

- 🟡 **「認めるのをやめる」が「参加取りやめ」と同じ重さのボタンで、agent の行だけ 2 段になる。** 今認めている状態
  なのか、押すと何が起きるのかが文面から読みにくい。「裏付けあり」も初めて見る人には用語として唐突
- 🟡 **avatar が 3 つ (B・ロボット・A) 並ぶと互いに重なる。** ロボットのアイコンが小さく、人の円と並ぶと潰れる
- 🟡 agent が書いた node の本文は、長いコードが縦横のスクロールバーを同時に出す (読めるが、node の中で
  スクロールが 2 方向になる)

### 2.5 template (#355・#356)

- 🟠 **「template を当てる」の一覧に「依頼・相談」しか出ない** (同じ File に Toulmin model もある)。
  仕様 (すでに当てた種を除くなど) か漏れかを、計画の §5.11 と突き合わせて確かめる
- 🟠 **英語の UI (bob) で、node の種別名が日本語 (「論拠」「依頼」) のまま。** #356 は「見る人の言語」。
  この File の template は #356 の前に作ったもので ja しか持たない可能性が高い。**新しく作った File で
  確かめる**。ja しか持たないとき、英語の利用者に日本語が出ること自体は仕様だが、そのことを示す印は無い
- 🟡 Sheet の「…」のポップアップは、その行でなく下の Sheet 行 (Sheet 2・3) を覆って出る
- 🟡 template の dialog は、チェックボックスの文字が小さい (11px)

### 2.6 読み取り専用 property (#357)

- 🟡 トグル「読み取り専用も表示」は見出しの右隣に小さく置かれ、見つけにくい。off でも template graph の node は
  property が全部出る (どれも書き換えられる property だから正しい)。**system・種別の property がある node では
  on/off の差を確かめていない**

## 3. 見ていないもの

- 「認めるのをやめる」を押した後 (状態を変えるので見なかった)
- 依頼を送る dialog・「送り直す」の後 (状態を変えるので見なかった)
- 3 人以上の avatar、Safari、モバイルの幅
- アイコンのコントラスト
