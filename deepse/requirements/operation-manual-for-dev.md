# Conversensus Operation Manual in development

このドキュメントは, プロダクト・オーナが開発中の Conversensus の動作確認を行うための操作マニュアルである.

このドキュメントは, 将来的にはユーザーズ・マニュアルや, PRD のベースになることを想定している.

テストデータの投入・リセットや読取フラグの切替など, テスト環境そのものの用意については [`user-test-environment.md`](./user-test-environment.md) を参照すること.

## 起動

より詳細, より最新の情報については, [user-test-environment.md](./user-test-environment.md) を参照すること.

### ATProto 向け開発時環境

#### PDS の起動

- `bash infra/pds/setup.sh` # 環境変数を `infra/pds/.env` に設定する. 既に設定済みならば不要
- Docker Desktop などで docker daemon を起動しておく
- `cd infra/pds && docker compose up -d` # container で PDS を起動する
- `curl http://localhost:2583/xrpc/com.atproto.server.describeServer` # 起動を確認する

#### アカウントの作成

あらかじめ, テスト用のアカウントを作成する.

まずは招待コードを作成する.

```shell
curl -X POST http://localhost:2583/xrpc/com.atproto.server.createInviteCode \
    -H "Content-Type: application/json" \
    -H "Authorization: Basic $(echo -n 'admin:7147f1f843bbf2a2f97b69a30d797543' | base64)" \
    -d '{"useCount": 1}'
```

招待コードが返ってくる.

```json
{"code":"localhost-lvkjj-wiq6n"}
```

それを使って, アカウントを作成する.

```shell
curl -X POST http://localhost:2583/xrpc/com.atproto.server.createAccount \
    -H "Content-Type: application/json" \
    -d '{
      "email": "masaki@metabolics.co.jp",
      "handle": "alice.test",
      "password": "devpassword123",
      "inviteCode": "localhost-lvkjj-wiq6n"
    }'
```

アカウントを作成したら, サイドバー下部の「ATProto ログイン」からハンドルとパスワードを入力してログインする. セッションは `localStorage` の `atproto_session` に保存されるので, 次回以降は自動的に復元される. ログアウトはサイドバー下部の「ログアウト」から行う.

> **注意**: `src/client/.env.local` に `VITE_ATPROTO_{HANDLE,PASSWORD}` を置いても**自動ログインはしない** — これらの env はコード中のどこからも参照されていない (2026-07-20 時点). 参照されるのは `VITE_ATPROTO_PDS_URL` のみ.

#### server/client の起動

- `bun run dev:server`
- `bun run dev:client`

vite (7) は node 20.19+ or 22.12+ を要求する. v24 を入れた.

http://localhost:5173/ で client が走っているはず.

### macOS アプリ (Tauri) として動かす

step1 Phase 8 (2026-08-14) から, **単体で動く macOS アプリ**として起動できる.

- `bun run app:dev` # 開発中に動かす
- `bun run app:build` # `.app` と `.dmg` を作る (`src-tauri/target/release/bundle/` の下)

**このアプリはサーバを同梱している**ので, `bun run dev:server` を別に立てる必要は無い.
bun もリポジトリも持っていない人に `.dmg` を渡せる.

上の dev 環境とは以下が違う. **同じマシンで両方を同時に動かしてよい.**

| | dev (ブラウザ) | アプリ |
|---|---|---|
| サーバ | `bun run dev:server` を手で起動 | 同梱 (アプリの起動・終了と一緒) |
| ポート | 3000 | 39847 |
| データ | リポジトリ内の `data/` | `~/Library/Application Support/site.conversensus.app/` |
| ログ | 端末 | `~/Library/Logs/site.conversensus.app/` |

**アプリのデータは dev 環境とは別物である.** アプリは空の状態から始まるので, dev 環境で
作ったファイルを持ち込みたければ export / import で運ぶ.

以下のくだりは, 今は多分必要ない.

> 配布した `.dmg` から入れた場合, **署名していないので初回は Gatekeeper に止められる**.
> 右クリック → 開く で一度許可すれば, 以後は普通に起動できる (詳細は
> [user-test-environment.md](./user-test-environment.md) §8).

## グラフ管理

グラフ管理の対象は, File, Sheet である. Branch については後述する.

### 新規ファイル作成

左サイドバーの一番上の input フィールドにファイル名を入れ, 右隣の '+' ボタンをクリックすることによって, 新しいファイル (このファイルは OS のファイル・システム上のファイルではなく, このシステム内で定義されたもの. 後述するシートを束ねたもの) が作られる.

既存のファイルと同名のファイルを作ることもできる. それらは内部 ID で区別されている.

'+' ボタンのさらに右隣の '↑' ボタンをクリックすることによって, export した .conversensus ファイル (後述) を import できる.

### ファイル管理

その下には, 既に作られたファイルの一覧がある.

行の左端のアイコンをクリックすると, そのファイルに含まれるシート (後述) の一覧が展開して, 表示される.

行の右端の「設定」アイコンをクリックすると, ダイアログが表示され, その中で以下の操作ができる.

- ファイル名の変更
- ファイルの概要の入力
- ファイルの export (.conversensus という拡張子を持つ JSON ファイル)
  - **そのファイルが使っている画像の実体 (base64 でエンコード済み) も一緒に書き出される**ので, 別の端末で import しても画像は表示される
  - ただし**この端末に実体が無い画像は含められない** (他の端末が作って一度も表示していない画像など). その場合は件数を知らせるダイアログが出る
- ファイルの削除
  - 削除するとファイル一覧から消える. 削除は操作ログに残る操作なので, ATProto にログインしていれば他の端末にも伝わり, その端末の一覧からも消える
  - 逆に, 他の端末で削除されたファイルは, この端末に降りてこない
    - 起動時の同期で無視されるか, 「今すぐ同期」（後述) で削除される
  - 削除は取り消せない (undo の対象外). ただし操作ログ自体は残るので, 将来「ごみ箱」のような復元手段を足すことは妨げられない
- 名前や概要の変更の保存
  - ESC キーを押したり, ダイアログ外をクリックすると保存せずにダイアログを閉じる

### シート管理

シートは, 一枚の (大きな) グラフである. 一つのファイルには, 複数のシートが収められる.

ファイルの内容一覧の一番下の '+ シートを追加' をクリックすると, 新しいシートが追加される. その時点でのシートの名前は "Sheet"+数字 というようなものであるが, 後で変更することもできる.

シート一覧の各行の右端の「設定」アイコンをクリックすると, ダイアログが表示され, その中で以下の操作ができる.

- シート名の変更
- シートの概要の入力
- シートの削除
- 名前や概要の変更の保存
  - ESC キーを押したり, ダイアログ外をクリックすると保存せずにダイアログを閉じる

## グラフ・エディタ

グラフ・エディタの対象は, Node, Edge (Node の一種として, Group や画像もある) である.

### ノード

- ノード作成
  - グラフ画面の何もないところをダブルクリックすると, ノードの種類のメニュー (Markdown / グループ / 画像) が現れる. 選んだ種類のノードが, ダブルクリックした位置に作成される
    - メニューの外をクリックするか ESC キーを押すと, 何も作らずに閉じる
- ノード内容の編集
  - ノードの内部をダブルクリックすると, そのノードの内容を編集できるようになる. 内容はテキストであるが, markdown 形式のマークアップをサポートする. サポートされるマークアップは [react-markup](https://remarkjs.github.io/react-markdown/) が提供するものである (ただし, 画像の埋め込みはサポートされない)
  - 編集を確定するには, 編集エリアの外をクリックする
  - ESC キーを押すと編集はキャンセルされる
  - 編集中はテキスト入力に対する undo/redo が可能である
- ノード移動
  - ノードの内部をドラッグすると, そのノードを移動できる
- ノードの大きさ変更
  - ノードの上下左右辺あるいは四隅のハンドルをドラッグすると, そのノードの大きさを変更できる
- ノード削除
  - ノードを選択して delete キーを押すと, そのノードが削除される. ノードが削除されると, そのノードに接続しているエッジも削除される
  - グループを削除すると, その中身 (子孫のノードとエッジ) もまとめて削除される. 中身を残したい場合には, 先にグループを解除してから削除する
  - 一度の delete で消えたものは, 一度の undo でまとめて元に戻る
- ノードの選択
  - ノードをクリックすると, そのノードが選択される. 選択されたノードは, 青い境界線で表示される
  - 続いて別のノードをクリックすると, そのノードが選択され, 先に選択されていたノードの選択は解除される
  - command + クリック (Mac) / control + クリック (Windows) すると, 選択されたノードに追加される
- ノードの copy/paste
  - ノードを選択して command + c (Mac) / control + c (Windows) を押すと, そのノードがコピーされる
  - command + v (Mac) / control + v (Windows) を押すと, コピーされたノードがペーストされる. ペーストされたノードは, コピーされたノードと同じ内容を持ち, かつ, コピーされたノードの右下に配置される

- [未実装] プロパティ

### エッジ

- エッジ作成
  - ノードの上下左右にあるハンドル (黒丸) をドラッグして, もう一方のノードのハンドルにドロップすると, その二つのノードを接続するエッジが作成される
- エッジの選択
  - エッジが選択されると, 色が濃く (灰 → 黒) なる
- エッジのラベル編集
  - エッジをダブルクリックすると, そのエッジのラベルを編集できるようになる
  - 編集を確定するには, ENTER キーを押すか, 編集エリアの外をクリックする
  - ESC キーを押すと編集はキャンセルされる
  - 編集中はテキスト入力に対する undo/redo が可能である
- エッジの種類の変更
  - エッジを右クリックすると現れるコンテキストメニューから, そのエッジの外見の種類を変更できる. 現在は以下の種類がある
    - Bezier
    - Straight
    - Step
    - Smooth Step
- エッジ削除
  - エッジを選択して delete キーを押すと, そのエッジが削除される

### グループ化

- グループ作成
  - 一つ以上のノードを選択して, command + g (Mac) / control + g (Windows) を押す, あるいは右上の「グループ化」ボタンをクリックすると, それらのノードをグループ化できる
    - 選択されたノードは, 青色の境界線で表示される
  - 作成されたグループは, それらのノードを囲むような青い背景と青い太めの境界を持つ矩形で表示される
  - グループの上部にはラベル (デフォルトで "グループ") が表示される. ラベルをダブルクリックすると, グループのラベルを編集できるようになる
- グループ内部でのノード作成
  - グループ内でダブル・クリックすると, pane と同じノードの種類のメニューが現れる. 選んだ種類のノードが, 最初からグループに属した状態で, ダブル・クリックした位置に作成される
- グループへのノードの出し入れ
  - 一つ, あるいは選択された複数のノードをグループに drag & drop して入れることによって, グループに参加することができる
  - グループ内にあるノード, あるいは選択された複数のノードをグループから drag & drop して出すことによって, グループから抜けることができる
- グループ移動
  - グループの内部をドラッグすると, そのグループを移動できる. グループを移動すると, そのグループに含まれるノード (と, それらに接続されたエッジ) も一緒に移動する
- グループの大きさ変更

      - グループを動かしてみて, そのノードが付いてくる可動かによって, グループへの所属を判別できる

    - [未完成] 現状では, いったんグループの大きさを変更すると, この機能はオフになる
- グループ解除
  - グループを選択して command + shift + g (Mac) / control + shift + g (Windows) を押す, あるいは右上の「グループ解除」ボタンをクリックすると, そのグループが解除される
    - グループ・ノードだけが消え, 中身のノードとエッジは残る. 中身は一段上のレベル (解除したグループがさらに別のグループの中にあったなら, その外側のグループ. そうでなければトップレベル) へ移る

- グループの copy/paste
  - グループを選択して command + c (Mac) / control + c (Windows) を押すと, そのグループがコピーされる
  - command + v (Mac) / control + v (Windows) を押すと, コピーされたグループがペーストされる. ペーストされたグループは, コピーされたグループと同じ内容 (のコピー) を持ち, かつ, コピーされたグループの右下に配置される

### 画像

画像ノードでは, 上部にラベル (キャプションと考えても良い), 下部に画像を表示する.
その他は markdown ノードと同様に扱うことができる.

- 画像ノードの作り方は 3 通りある
  - ノードの種類のメニューから「画像」を選ぶ. この場合は空のノードができるので, ダブルクリックして URL を入力する
  - **画像ファイルをグラフ画面に drag & drop する.** 落とした位置に画像ノードが作られる
  - **画像をコピーして command + v (Mac) / control + v (Windows) で貼り付ける.** 画面の中央に画像ノードが作られる
- 画像の差し替え
  - **既にある画像ノードの上に drag & drop する**と, そのノードの画像が差し替わる (新しいノードは作られない)
  - **画像ノードを 1 つだけ選択した状態で貼り付ける**と, そのノードの画像が差し替わる
    - 複数選択しているときは, どれが変わるか予測できないので新規ノードを作る側に倒している
  - ノードをダブルクリックして URL を入れ直すこともできる
- 画像の実体はこの端末に保存され, 操作ログには**参照だけ**が載る. ATProto にログインしていれば, 送信時に実体も PDS へ上がり, 他の端末でも表示できるようになる
- **1 枚 5 MiB まで.** 超えるものは受け付けず, 理由をダイアログで知らせる
- 実体がこの端末にも PDS にも無い画像は「画像を読み込めません」と表示される (他の端末が作った画像で, まだ同期されていない場合など)

## 同期

ATProto にログインしていると, 編集は操作ログとして PDS へ送られ, 他の端末に伝わる.
ログインしていない場合はこの端末の中だけで完結する (同期の表示も出ない).

左サイドバーの一番下に, ログイン中の handle と同期の状態が表示される.

- **「クラウド同期済み」** — 送信すべきものが残っていない
- **「クラウド未同期: N 件」** — 送れていない編集がある (オフライン・PDS 障害など).
  編集は失われておらず, この端末には保存されている
- **「今すぐ同期」ボタン** — ログイン中は常に押せる. 押すと**送信と受信の両方**を行う

### 他の端末の変更が入ってくる契機

**現状, 他の端末 (や他のウィンドウ) の変更は自動では入ってこない.** 受信が走るのは
次の 3 つのときだけである.

1. ファイルを開いたとき
2. ネットワークが復帰したとき
3. **「今すぐ同期」を押したとき**

したがって, 同じファイルを 2 つの画面で開いたまま編集し合っても, 互いの変更は見えない.
**「今すぐ同期」を押すか, ファイルを開き直す**と反映される.

> [未実装] 自動的に反映されるようにする (GitHub #202). 定期的に取りに行くと常時コストを
> 払うことになるため, PDS からの通知 (Jetstream 購読) に載せる予定である.

編集中に受信した内容は, **編集が終わるまで画面に反映されない** (入力中のテキストを
巻き込まないため). 次の受信の契機で反映される.

## バージョニング

シート毎に, ブランチを作成して複数のバージョンを管理する.

ブランチは, それぞれそのバージョンのシートの内容と変更履歴を保存し, trunk (main) に統合 (merge) される.

> [未実装] 「承認されてから merge する」という承認の仕組みは, 共同編集 (後述) 側の概念であり
> まだ無い. 現状は merge を実行した本人の判断だけで統合される.

### ブランチの作成と利用

- ブランチ作成
  - 左サイドバーのシート名の下の "+ branch" をクリックすると, その時点のシートの内容を基点として, 新しいブランチが作成される
  - この基点を **分岐点** と呼ぶ. 分岐点は「ブランチを作成した時点の trunk の内容」であり, その後 trunk が進んでも変わらない
- ブランチ内での編集
  - あるブランチに切り替えた状態でシートを編集すると, その編集はそのブランチの変更履歴に保存される
  - **差分の起点はブランチの状態によって 1 つに決まる.** 同時に 2 つの差分が表示されることはない

    | ブランチの状態 | 起点 | 差分の意味 |
    |---|---|---|
    | 無変更 (分岐した直後 / merge した直後) | — | 差分を表示しない |
    | 変更中 (前回の commit 以降に編集がある) | 前回の commit (一度も commit していなければ分岐点) | 次の commit の対象 |
    | commit 済み (編集が無く commit が 1 件以上ある) | 分岐点 | 次の merge の対象 |

    - trunk では差分を表示しない
    - シート上のハイライトと commit ダイアログの内容は, **常に同じ差分を指す**
  - 差分は以下のように表示される
    - 追加: グリーン (#16a34a) のハイライト
    - 変更: オレンジ (#f97316) のハイライト
    - 削除: 破線 (ゴースト表示). ゴーストは選択・移動・接続のいずれもできない
  - ノードの移動やリサイズなど, **layout だけの変更も「変更」として表示する** (意味の変更と区別しない)
    - 連続したドラッグは 1 回の操作として記録されるので, 移動量のしきい値は設けない
    - 同じノードを何度動かしても, 起点との差分としては 1 個に集約される
  - 編集した結果が起点と同じ値に戻った場合 (undo した場合を含む) は, **差分に出ない**
- ブランチの commit
  - ブランチを切り替えた状態でシートを編集しているときに, シート右下の "コミット" ボタンをクリックすると, そのブランチに対する変更が commit として保存される
    - そのときに変更理由も記述する (必須)
  - commit が完了すると, 差分の起点が分岐点に切り替わり, 分岐点の内容との差分が同じように表示される
    - この差分が次の merge の対象であることを表している
- ブランチ切り替え
  - 左サイドバーのシート名の下にあるブランチの一覧から, ブランチをクリックすると, そのブランチに切り替わる
  - あるいはシート名自体をクリックすると, trunk (main) に切り替わる
  - いずれの場合も切り替え前のブランチの編集内容は保存される
- ブランチの merge
  - ブランチを commit すると, そのブランチの今の状態を trunk に merge することができるようになる
  - "merge" ボタンをクリックすると, そのブランチの内容が trunk に merge される
    - そのときに merge 理由も記述する (commit と同様に必須)
    - merge は, 単なるブランチによる trunk の上書きではなく, ブランチを切った後に trunk に加えられた変更も, ブランチの変更とともに trunk に統合されるようになる
    - merge それ自体が trunk の履歴に残り, 「いつ・誰が・何のために merge したか」を後から辿れる
- ブランチの close
  - merge されていないコミットが存在していない状態では, そのブランチを close して, それ以上の変更ができないようにできる
- ブランチ削除
  - ブランチ自体の存在を忘れるためには, 未 commit であっても 未 merge であっても, ブランチを削除することができる
  - 削除されたブランチには, 今後アクセスすることはできない
