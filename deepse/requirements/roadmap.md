# conversensus roadmap

## step 0 (origin)

- 標準的な web アプリケーションとして動作する
  - サーバ／クライアント・アーキテクチャで動作する
  - サーバ上のデータベースをストレージとして利用する
- ファイルベースのストレージを利用する
- 単一ユーザで利用する (認証なし)
- 基本的なグラフ構造 (Node, Edge) を編集できる
- 基本的なグラフ構造 (Node, Edge) を表示できる
- Group はない
- File は複数作れる
- Sheet は各 File に一つのみ
- Property は Edge の label のみ
- View は graph のみ
- Template はない

これ以降は, 機能上の進行と基盤上の進行に分けて考える. 全体としては, この二つが interleave する形で進行する.

## platform progression

### platform step 1 (ATProto/PDS)

- 複数ユーザで利用する (認証あり)

### platform step2

- 共同作業する
  - 権限を考える
    - 対象
    - 種類
    - 権限が発現する場所
    - op-log にアカウントを入れる前提 (lexicon の verb には authorDid が入っている)
  - 衝突に対応する
    - 検知
    - 通知
    - 議論
    - 合意
    - 保留, 分離?
- 複数の ATProto/PSD に接続する
- branch のグローバル化

## function progression

### function step 1

個人がスタンドアロンで利用する場合の, 一画面上の操作を一通り実装し, これだけでツールとして利用できるようにする.

- グループ化できる
- バージョンを管理できる
- 画像ノードがある

### function step 2

実際に実用的なグラフ (今まで Canva などで書いたグラフの模写, あるいは conversensus 自体に関するグラフ - ドキュメントなど) を書くのに必要な機能を揃える.

- ユーザがプロパティを設定, 表示できる
- 他のノード, エッジ, シート, ファイルへのハイパーリンクが可能である
  - markdown テキスト中から, あるいは
  - リンク・ノードを追加する
- 検索する

## and beyond

- ATproto 以外 (e.g. P2P) に接続する
- より粒度の小さいリアルタイム同期をファイル単位で選択できる
- バージョン・グラフを可視化する
- 既存の, あるいは自前のオントロジとの統合を可能にする
- properties と視覚属性を対応付けられるようにする (template)
- ノードの接続に型や制約を付けられるようにする (template)
- グラフの「実行」を可能にする
- プラグインとは異なる拡張の仕組みを作る
- グラフ以外のビューを提供する
