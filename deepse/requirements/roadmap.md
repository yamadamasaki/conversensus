# conversensus roadmap

## step 0 (origin)

- 標準的な web アプリケーションとして動作する
  - サーバ／クライアント・アーキテクチャで動作する
  - サーバ上のデータベースをストレージとして利用する
- ファイルベースのストレージを利用する
- 単一ユーザで利用する (認証なし)
- 基本的なグラフ構造 (Node, Edge) を編集できる
- 基本的なグラフ構造 (Node, Edge) を表示できる
- Group はない → ある
- File は複数作れる
- Sheet は各 File に一つのみ → 複数可
- ~~Property は Edge の label のみ~~
- View は graph のみ
- Template はない
- 画像ノードがある

これ以降は, 機能上の進行と基盤上の進行に分けて考える. 全体としては, この二つが interleave する形で進行する.

## step 1

### platform (ATProto/PDS)

- アーキテクチャを洗練する
- 複数ユーザで利用する (認証あり)
- tauri でパッケージングする

### function

- 個人がスタンドアロンで利用する場合の, 一画面上の操作を一通り実装し, これだけでツールとして利用できるようにする
- バージョンを管理できる

## step 2

step 2 の目標は, 共同作業できるようにすることである. そのためには, 多くのプラットフォームの拡張, ユーザ機能の追加が必要になる. また, step 1 でやり残した個人作業のための機能もいくつか追加したい.

step 2 ではやらないが, step 3 (あるいはそれ以降) で実現したいことの一部も記述しておく. これはアーキテクチャを立案する際にあらかじめ勘案し, もし必要ならばロードマップの変更も考える.

- アカウントを作成する
- File に招待する
- 衝突回避/合意形成/概念創発/ネガティブ・ケイパビリティ (保留, 分化, ...)
- template
- hyperlink
- properties
- 検索する

仕様の詳細は [spec-step2](spec-step2.md) を参照のこと.

## and beyond

- branch のグローバル化
- File の private 設定
- ATproto 以外 (e.g. P2P) に接続する
- より粒度の小さいリアルタイム同期を File 単位で選択できる
- バージョン・グラフを可視化する
- ハイパーリンクによる参照関係を可視化する
- 既存の, あるいは自前のオントロジとの統合を可能にする
  - REA ontology (ebXML)
  - 各種 upper ontology
  - ...
- グラフの「実行」を可能にする
- プラグインとは異なる拡張の仕組みを作る
- グラフ以外のビューを提供する
  - list
  - table
- 検索する (GQL)
- i18n
- edge に曲がるポイントを追加する
- node の間隔を揃える
- 自動レイアウト
