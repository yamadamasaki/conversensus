# notification

> [step3](../step3.md) の子文書。出所: Notion「notification」(2026-09-30)。
> 未決: PDS に置くと公開される点、op-log から導出できる通知との切り分け (O4)。

通知には、以下の二種類が考えられる。

1. システム (local で動いている web app (パッケージング/配布の方法はここでは不問として)) から、
   そのシステムのユーザへの通知
2. 他のユーザからの通知

(2) に関しては、ATProto では他人の repo には書き込めないので、基本的にはメンバ (誰?) の
repo から pull して来るか、別のサービス (chat など) を使うしかない。

ここでは (1) についてのみ、考える。

1. 自分の repo にキューを作る
2. システムからユーザへの通知が必要になった時点 (例えば implicit merge で衝突が発生した) で、
   ユーザが active ならば、通知を表示させる
3. ユーザが active でなければ、キューに通知を置く
4. システムは、ユーザがログインしたタイミングで repo のキューを見に行き、まだ閉じていない
   通知があれば、それをユーザに知らせる
5. いずれの場合も、ユーザがその通知を閉じたら、システムはキューから取り除く

もっとも単純化された形で実装する。

今までとは別の collection になるので、lexicon 定義が必要だろう。例えば、

- 発信者 (とりあえず「ローカルのシステム」)
- 時刻
- 種類 (とりあえず「短い通知」)
- メッセージ内容 (文字列)

通知を送り合いたい actor があらかじめ分かって、登録されていれば、その repo を定期的に
巡回することで、同じ仕組みで通知を受け取れる。

もう少し頑張れば、グループ・チャットに発展させられるかもしれない。
