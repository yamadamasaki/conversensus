## 1. 結論

**土台の疑問はもう無い。Phase 8 は「配る形にまとめる」作業である。**
spike で Tauri シェルと WKWebView の適合は実証済で, ANA-125 で WebKit 固有の壊れ方も
潰した。残るのは**アプリ 1 つの中にデーモンとデータを収める**という, 未着手の配線だけである。

**未着手であることの確認**: リポジトリに `src-tauri` は無い (spike は使い捨てだった)。
ゼロから作る。

一番の勘所は **「利用者は bun もリポジトリも持っていない」** という点である。今の構成は
`bun run dev:server` が `DATA_DIR` 既定でリポジトリ内の `data/` を開く前提で組まれている。
配布物ではその 2 つが両方とも成り立たない。§2 の測定はそこを突いている。

## 2. 診断 (実測, 2026-08-14)

### 2.1 デーモンは単一バイナリにできる — 2.8 秒 / 57MB

```
bun build --compile src/server/src/index.ts --outfile conversensusd
  → [40ms] bundle 52 modules / [2.8s] compile
  → Mach-O 64-bit executable arm64, 57MB
```

`bun:sqlite` を含めて問題なく通り, **起動して `GET /files` が 200 を返す**ことも確認した
(`DATA_DIR` と `PORT` を渡した場合)。sidecar 同梱の前提は成立する。

### 2.2 **`DATA_DIR` を渡さないとバイナリは即死する** (重要)

```
$ PORT=3201 ./conversensusd
EROFS: read-only file system, mkdir '/data'
  at getEventStore (/$bunfs/root/conversensusd:6941)
```

`eventStoreServer.ts` の既定は `join(import.meta.dir, '../../../data')` だが,
**コンパイル済みバイナリの中では `import.meta.dir` が `/$bunfs/root`** になるため,
既定のデータ置き場が **`/data`** (ルート直下) に化ける。

**黙って変な場所に書かず落ちるのは良い性質である。** ただし Tauri 側が
`DATA_DIR` を必ず明示的に渡さないと, アプリは起動直後に死ぬ。

### 2.3 ポートが埋まっていると即死する。しかも**ログが嘘をつく**

利用者の dev サーバ (:3000) が動いている状態で `PORT=3000` で起動すると:

```
server running on http://localhost:3000      ← 先にこれが出る
error: Failed to start server. Is port 3000 in use?  (EADDRINUSE)
```

`index.ts` の `console.log` が**モジュール評価の時点**で出るのに対し, 実際の bind は
その後の `Bun.serve` である。**「起動した」と言ってから落ちる。**
この開発機では dev サーバが動いていることが多いので, **アプリが既定の 3000 を掴みに
行く設計にすると日常的に衝突する**。

### 2.4 クライアントのビルドは VPS を向いている

`src/client/.env.production` が `VITE_API_BASE=https://api.conversensus.site` なので,
**素の `bun run build` はローカルデーモンを見ない**。spike で 40 分溶かした穴がこれである
(`step1-phase8a-r1-spike.md` §7 S3 障害 1)。Tauri 用のビルドは別に用意する必要がある。

### 2.5 Rust の toolchain は aarch64 のまま生きている

```
rustup default → stable-aarch64-apple-darwin
rustc host     → aarch64-apple-darwin (1.97.1)
```

spike の是正が残っている。**R1 の再発はしない。**

### 2.6 VPS は 3 役を持っており, api には認証が無い

| ホスト | 役割 |
|---|---|
| `app.conversensus.site` | クライアントの静的配信 |
| `api.conversensus.site` | **デーモン** (`DATA_DIR=/opt/conversensus/data`, systemd) |
| `pds.conversensus.site` | ATProto PDS (Docker) |

`src/server/` に認証は 1 行も無い (grep 済)。**`api.` は誰でも読み書きできる単一の
event store** である。今それが問題にならないのは URL を知っているのが実質 1 人だからである。

**これは Phase 8 の作業対象ではない** (§3) が, D6 の「VPS をアプリ配信から降ろす」が
本当に指していたのはここだと考えられるので, 診断として記録する。

## 3. 決まっていること (ユーザー判断, 2026-08-14)

| 問い | 決定 |
|---|---|
| 配布の到達点 | **署名しない。** 自分の Mac で動く `.app` / `.dmg` まで。Apple Developer 登録 (年 $99) と notarization は別課題 |
| 対象 OS | **macOS だけ。** Windows (WebView2) / Linux (WebKitGTK) は対象外 |
| 自動更新 (updater) | **入れない。** 署名が無いと更新後の起動でまた Gatekeeper に引っ掛かる |
| VPS (D6) | **手を触れない。** Phase 8 は Tauri に集中する。D6 は「共有 `api.` をどうするか」として別課題に立て直す |
| web 版の位置付け | **今は決めない。** Tauri を実際に使ってみてから判断する |

**D6 を外した理由**: Tauri 配布と VPS の移行は独立しており, 混ぜると失敗の原因が
分からなくなる。また「アプリ配信を降ろす」判断は**アプリが実際に配れると確かめてから**の
方が安全である (逆順だと戻れない)。自宅マシンへの移行案は
「IPv6 only の PDS に relay が到達できるか」という測れば分かる 1 点にほぼ集約されるので,
別の spike で先に潰せる。

## 4. 設計方針

### D1: デーモンは sidecar として同梱し, **寿命は Tauri が持つ**

利用者は bun を持っていないので, デーモンはバイナリで運ぶ (§2.1)。
**アプリを終了したらデーモンも終わる**ことを配線の責務とする —
孤児プロセスが残ると, 次の起動でポートを掴めず §2.3 の死に方をする。

### D2: **`DATA_DIR` は Tauri が明示的に渡す。既定に頼らない**

§2.2 のとおり既定は配布物では壊れている。OS 標準のアプリケーションサポート配下を
Tauri 側で解決して環境変数で渡す。**「既定を直す」のではなく「渡す」**のは,
リポジトリで開発するときの既定 (`data/`) を変えないためである。

### D3: **専用ポートを固定する。3000 は使わない**

§2.3 のとおり, 開発機では :3000 が埋まっていることが多い。
アプリは開発用と重ならない専用ポートを使う。

**動的ポート (空きを探して使う) は採らない。** クライアントは `VITE_API_BASE` を
**ビルド時に**焼き込む作りなので, 動的にすると「実行時に API の場所を教える」経路が要り,
製品コードに Tauri 依存の分岐が入る。固定なら製品コードは何も知らなくてよい。
**再開条件**: 固定ポートが実際に衝突して困ったとき。

### D4: web 版のビルドは触らない。Tauri 用を**別に**作る

`.env.production` は VPS を指したまま残す (§3 で web 版の位置付けを決めていないため)。
Tauri 用は別のモード / env ファイルでビルドする。**どちらのビルドが何を向くかを
名前で分かるようにする** — spike で 40 分溶かしたのはここの取り違えである。

### D5: 「起動して使えるか」は人間が見る。**ただし観測はログで残す**

Tauri アプリの中は Playwright から触れない。spike で確立した観測手段
(webview から localhost のプローブへ値を返す) は使えるが, **常設の検査には重い**。

代わりに **デーモン側のログを配布物でも読めるようにする**。§2.3 の「起動したと言ってから
落ちる」を直し, **bind に成功してから成功を名乗る**ようにすれば, 失敗はログに正しく出る。

### D6: 署名しないことの帰結を**手順として書く**

未署名の `.app` は Gatekeeper に止められる。**「動かない」と誤診しないため**に,
初回起動の手順 (右クリック → 開く) を `user-test-environment.md` に書く。

## 6. 受入基準

1. **`.dmg` から入れたアプリが単体で動く** — bun もリポジトリも無い状態で,
   デーモンが自前で起動し, ファイルの作成・編集ができる
2. **アプリを終了するとデーモンも終わる** — 孤児プロセスが残らない (`pgrep` で確認)
3. **データが OS 標準の場所に置かれ, 再起動しても残る**
4. **開発中の dev サーバ (:3000 / :5173) と同時に動かしても, どちらも壊れない**
5. **web 版を壊していない** — `bun test` / lint / typecheck / E2E (webkit + chromium) が緑
