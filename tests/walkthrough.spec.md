# walkthrough.spec.ts — 通しスモーク (ANA-125 S2)

## 何をテストするか

利用者が最初に通る導線を **1 本のテスト**として端から端まで動かす。

ファイル作成 → ノード作成 → ノード編集 → シート追加 → シート往復 → export →
import → 画像 drop。

## なぜテストするか

**ANA-125 の目的は「Safari で使い込みを始められる状態」の機械判定である。** #51 の
ような「導線を止める壊れ方」がこの通し道のどこかに残っていないかを, 実 Safari を
呼ぶ前に洗う (計画書 `deepse/plans/step1-refinement-ana125-safari.md` §3 / D2)。

**単体テストの代わりではない。** 個々の機能の網羅はテスト対象と同じ場所にある単体
テストが持っている。ここに置くのは**エンジンをまたいで壊れるもの**だけである
(CLAUDE.md「E2E (ブラウザ)」)。だから 1 ファイル 1 テストで, 分岐も網羅もしない。

なぜ 1 本に繋げるか: 個別に切ると, export したファイルを import する,
シートを往復しても編集が残る, といった**状態を跨ぐ壊れ方**が見えない。#51 と
同じく「操作は成功するのに次の操作ができない」形の不具合はここでしか出ない。

## どのようにテストするか

### 合格条件は 2 つある

1. **各操作の結果が状態に出ていること** — ノードが 1 つ増える, 入れた文字が残る,
   別シートは空である, 戻ると編集が残っている, import した先に同じノードが居る,
   落とした画像がデコードまで済んでいる
2. **未処理例外・コンソールエラー・読み込み失敗が 0 件であること** —
   `pageProblems.ts` を `page.goto` より**先に**仕掛け, 最後に 0 件を見る

2 が要るのは, **画面が正しく見えることを合格条件にしてはならない**からである
(計画書 D2)。step1 では PDS への送信が数週間にわたり全滅していたのに画面は
正常に見えた。1 だけだと同じ形の穴をそのまま空ける。

### 検査で意図的にそうしていること

- **`<img>` が居ることでは合格にしない。** 参照だけ書けて実体が取れていなくても
  要素は出る。`naturalWidth > 0` まで見て初めて「blob が往復した」と言える
- **シート追加の直後にノードが 0 件であることを見る。** ここが 0 でなければ,
  シート切替で React Flow を再 seed する経路が効いていない
- **import 後にファイル名のボタンが 2 つになることを見る。** 「元 + 取り込んだもの」
  という結果そのものであり, ダイアログや画面の見た目には依存しない
- **ファイル名にプロジェクト名と時刻を混ぜて一意にする。** `webServer` はテスト全体で
  1 つなので, 2 番目のエンジン (chromium) は 1 番目 (webkit) が作ったファイルが
  残っているデーモンを見る。名前で引く検査が隣のエンジンの残骸に当たらないようにする

### この検査で見られないもの

- **実 OS のドラッグ**。画像 drop は `DataTransfer` を組んで `drop` を投げる合成
  イベントである。ここで見ているのは「drop を受けてから画像が画面に出るまでの配線」で
  あって, トラックパッドから来る挙動 (ANA-115 症状 B) ではない。それは **S4 で実機**を見る
- **実際の権限ダイアログ・クリップボード・ファイル選択ダイアログ** (計画書 §3 の表)。
  import は `filechooser` イベントを掴んでパスを渡すので, Safari のダイアログ自体は通らない

## 反証で確かめたこと

「通ったから正しい」を避けるため, **drop の送出を外すと落ちる**ことを確認した
(ノードが 2 件にならず失敗する)。検査が実際に画像 drop の結果を見ていることの裏付けである。
