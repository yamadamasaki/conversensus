# paneDrag.spec.ts — 押していないポインタで続くドラッグ (ANA-125 S4 / ANA-115)

## 何をテストするか

**ボタンを押していない押下 (トラックパッドのタップ) でドラッグが始まっても,
カーソルを動かしたときにノードやキャンバスが付いてこないこと**。
併せて, **押し込んだ本物のドラッグは今までどおり動くこと**。

## なぜテストするか

実 Safari + トラックパッドの使い込み (ANA-125 S4) で観測した症状である。
#51 のコメントには「ノードがカーソルに付いてくる」とあったが, 実際は次のとおりだった。

- **掴んだ先による** — ノードのことも, 画面全体のこともある
- **トラックパッドのタップでのみ起きる。押し込んだドラッグでは起きない**
- もう一度クリックするまで止まらない

Web インスペクタで測った事実 (2026-08-13):

| | 押下 | 移動中 |
|---|---|---|
| 押し込んだドラッグ (正常) | `buttons=1` `pressure=0.5` | `buttons=1` |
| タップ (暴走する) | `buttons=0` `pressure=0` | `buttons=0` |

さらに WebKit は `mouseup`/`pointerup` を `mousedown`/`pointerdown` より**先に**配送する
ことがある。先に来た解放は誰も待っていないので捨てられ, **後から来た押下で始まった
ドラッグを終わらせる解放が残らない**。React Flow のドラッグは d3-drag で動き,
**d3-drag は移動中に `buttons` を見ない**ので, 押していないのに動き続ける。

対策は `src/client/src/stuckDragGuard.ts` — 移動の `buttons` が 0 なら合成 `mouseup` で
打ち切る。判定は**イベントの事実 (押されていない) だけ**で, エンジンでは分岐しない。

## どのようにテストするか

- **タップはページの中で `MouseEvent` を組み立てて投げる。**
  `page.mouse` は押下中に必ず `buttons=1` を立てるので, タップは合成でしか作れない。
  また **`view: window` を立てないと d3-drag は動かない** (d3-drag は `event.view` に
  リスナを張るため)。Playwright の `dispatchEvent` は view を立てないので,
  ここだけ `page.evaluate` を使う
- **ドラッグ対象は 2 つ見る** — ノード (`.react-flow__node` の transform) と
  キャンバス (`.react-flow__viewport` の transform)。症状が両方で出るためである
- **本物のドラッグが動くことを同じファイルで見る。** 打ち切りの guard は
  「動かなくする」方向の変更なので, 効きすぎていないことを併せて固定しないと危ない

## 反証で確かめたこと

guard を入れる前は **webkit / chromium とも 4 件全部赤**だった。d3-drag が `buttons` を
見ないという穴自体はエンジンに依らず, **WebKit だけがその病的なイベント列を配送する**
という構造である (#51 が「WebKit 固有」ではなく「両方に在る穴が WebKit で出る」形だったのと同じ)。
