# i18n.spec — 画面の言語

## 何を

ブラウザの言語が en のとき、

- 英語の画面で開く (左サイドバー・ヘッダ)。`<html lang>` が `en`
- File を作ってグラフを開いた画面に、**日本語の文字が残らない** (描いた文字・`aria-label`・`title`・`placeholder`)。
  言語の名前「日本語」は切り替えのために日本語で書くので除く
- 左サイドバーの切り替えで日本語を選ぶと日本語の画面になり、`<html lang>` が `ja` になる。**再読み込みしても日本語のまま**
  (端末に覚える)

## なぜ (E2E にする理由)

言語は、モジュールの読み込み時に `navigator.languages` から決まる。happy-dom の単体テストは言語を固定しているので、
本物のブラウザ (WebKit と Blink) の `navigator.languages` で英語が選ばれることは、ここでしか見られない。日本語が
残っていないかも、App 全体を描いた画面でしか通しでは見られない (単体の `enRendering.test.tsx` は部品ごと)。

## どのように

- このファイルだけ `locale: 'en-US'` で開く (他の E2E は ja に固定, `playwright.config.ts`)
- 日本語の検出は、ひらがな・カタカナ・漢字の範囲で行う。**利用者が付けた名前は除く** — `translate="no"` の要素
  (File・Sheet・Folder の名前) の中身と、その名前を含む属性の部分。WebKit では他のテストが作った File が一覧に
  見えていて、その名前 (日本語) を拾って落ちた (fixture が保存領域を空にするようにした後も、利用者の名前は除いて見る)
- fixture (`tests/fixtures.ts`) が persistent context に `locale` を渡していなかったので、以前は設定の locale が
  どのテストにも効いていなかった (エンジンの既定の言語で開いていた)。渡すように直した
- `pageProblems` で未処理例外・コンソールエラーが 0 件であることも見る
