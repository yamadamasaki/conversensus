# sidebarLayout のテスト仕様 (E2E)

## 何をテストするか

**サイドバーの行が溢れず, 中のボタンが押せること** (GitHub #51 / ANA-125 S1)。
対象は 2 箇所:

- **新規作成の行** (ファイル名入力 + 「+」 + import) — #51 が報告された場所
- **ファイル一覧の行** (ファイル名 + ギア) — **同じ形をしている**別の場所

## なぜテストするか

#51 の症状は「import ボタンが, はみ出して表示されているし, クリックしても実行されていない。
実際には, 左サイドバー内に残っているボタン部分をクリックすると, import が実行されたりはする」。

原因は **flex アイテムの `min-width` の既定が `auto`** で, `<input>` が `size` 属性由来の
固有幅より細くならないことである。**その固有幅がエンジンごとに違う**ため, WebKit では行が
溢れて import ボタンがサイドバーの外へ出る。**Chromium でも行は溢れており** (実測で 8px),
差は溢れる量だけである — WebKit では 18px 溢れてサイドバーの端を越え, その位置の最前面が
キャンバス側の要素になるので押せなくなる。

**目視では「ボタンの形が少し違う」程度にしか見えない**が, 数値なら一意に判定できる。
だから回帰テストとして固定する。

## どのようにテストするか

**実測値ではなく関係を検査する。** 仕様は「行が溢れないこと」「ボタンが押せること」であって
特定のピクセル値ではない。フォントやパディングを変えたときに無関係な赤が出ないようにする。

- **行が溢れない** — `scrollWidth <= clientWidth`。原因に最も近い形
- **import ボタンが行の内側に収まる** — `importBtn.right <= row.right`
- **import ボタンの中心が押せる** — 中心の `elementFromPoint` がボタン自身であること。
  **見えていても押せない**という #51 の分かりにくさを直接表す
- **import ボタンを押すとファイル選択が開く** — `filechooser` イベントで見る。
  レイアウトが直っても配線が切れていれば落ちる (症状の言葉どおりの検査)
- **長いファイル名でも行が溢れない** — ファイル行のギアボタンは `flexShrink: 0` で,
  隣のファイル名ボタンは `overflow: hidden` を持つので自動最小サイズが効かず縮む**はず**である。
  理屈で済ませず固定する。縮まなければギアが押せなくなり #51 と同じ壊れ方になる

**webkit と chromium の両方で回す。** 片方だけでは「エンジン差」も「直した側で壊した」も
言い切れない。

## ここでテストしないこと

- **見え方 (文字の鮮明さ・フォントの太さ)** — エンジン差であり不具合ではない
  (`../deepse/plans/step1-refinement-ana125-safari.md` D4)
- **import した中身が正しいか** — `.conversensus` の解釈は `src/shared` の
  `migrations.test.ts` と `src/client/src/files/fileTransfer.test.ts` の領分。
  ここは**ボタンが押せてファイル選択が開くところまで**を見る
- **サイドバー以外のはみ出し** — 検査対象は「壊れが確認された箇所と, 同じ形をしている箇所」に
  限る (計画書 D2)。当てずっぽうに広げない
