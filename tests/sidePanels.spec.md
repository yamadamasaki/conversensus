# sidePanels のテスト仕様 (E2E)

## 何をテストするか

左右のサイドバーの**幅変更と折り畳み** (step3 Phase 3 S3-4b, 仕様 design-language)。

## なぜテストするか

- 取っ手は**ポインタのキャプチャ** (`setPointerCapture`) で引く。ポインタの扱いはエンジンごとに
  違いが出やすい (paneDrag.spec の前例) ので、WebKit で実際に引く。happy-dom の App 結合では
  レイアウトもポインタのキャプチャも本物でない
- **幅を狭められるようにしたことで、#51 (新規作成の行が溢れて import ボタンが押せない) が
  狭い幅で再発しうる。**#51 は既定の 240 で直したもので、最小の 160 では確かめていなかった

## どのようにテストするか

- **取っ手を右へ引くと左サイドバーが広がり、再読み込みしても残る**: 80px 引いて 80px 広がること、
  再読み込みの後も同じ幅であること (`localStorage`)。未処理例外・コンソールエラーが 0 件
- **畳むと帯だけが残り、広げると元の幅に戻る**: 畳むと中身 (ファイル名の入力) が見えなくなる
- **最小の幅まで狭めても、新規作成の行は溢れない**: 取っ手にフォーカスして ← を押し続ける
  (キーボードでも変えられる約束を兼ねる)。最小で止まること、行の `scrollWidth <= clientWidth`
  (sidebarLayout.spec と同じ物差し)
- **右サイドバーは既定で畳まれていて、広げると詳細が出る**
