# headerFold.spec — ヘッダの操作を幅に合わせて畳む

## 何を

長い File の名前で、右サイドバーを広げてヘッダを狭めても、ヘッダの中身が溢れず (`scrollWidth ≤ clientWidth`)、
畳んだ操作 (PNG) が「その他の操作」のメニューから使えること。undo は残ること。

## なぜ (E2E にする理由)

畳むかどうかは、描いた中身の幅と箱の幅を比べて決める (`layout/useFoldLevel.ts`)。単体のテストは配置をしない
happy-dom で幅を差し替えているので、**本物の配置 (flex の縮み・省略) で溢れが消えるか**はブラウザでしか分からない。
WebKit と Blink で flex の最小の幅の扱いが違うと、片方だけ溢れたままになりうる。

## どのように

- 幅 1100 で File を作り (名前は長い)、何も畳んでいないことを見る
- 幅 1024 にして右サイドバーを広げる。**画面の幅の段は広いままで、ヘッダだけが狭くなる** — 段では畳まず、
  ヘッダ自身の幅で畳むことを見る
- 溢れが 0 になるのを待ち、「その他の操作」と「元に戻す」が見え、メニューに PNG があることを見る
- `pageProblems` で未処理例外・コンソールエラーが 0 件であることも見る
