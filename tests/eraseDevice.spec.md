# eraseDevice.spec.ts

## 何を

ログアウトで「この端末のデータも消す」を選んだ後の起動で、手元の正典 (OPFS の SQLite) が本当に消えること (#288)。

## なぜ E2E か

消す処理の規則 (印・別のタブ・待ち直し) は単体 (`eraseDevice.test.ts`) でフェイクの上で見ている。**OPFS の
ファイルが実際に消えるか**は、エンジンの OPFS の実装 (閉じたばかりの同期ハンドルがいつ解けるか、`removeEntry` の
recursive) 次第で、フェイクでは分からない。WebKit (本命) と Chromium (対照) の両方で見る。

## どのように

ログアウトの問いにはログインが要るので通らない (問いの流れは `logoutFlow.test.ts`)。問いの後に付く印
(`sessionStorage` の `conversensus_erase_requested`) を直接置いて再読み込みする。

- **消える**: File を作る → 印を置いて再読み込み → その File が無い。**消した後も新しい File を作れる**
  (保存領域が壊れずに空から開く)。コンソールのエラー・未処理例外が無いこと (`pageProblems`)
- **別のタブが開いていれば消さない**: 同じ context に 2 つ目のタブを開いてから、1 つ目で印を置いて再読み込み
  → File が残る。2 つ目のタブの Worker が同じ DB を開いているので、消してはならない
